# Changelog

Version numbers follow `MAJOR.MINOR.PATCH`; the 0.x series is under active development. Release tags and downloadable archives use the same version.

## 0.9.8 — Unreleased

- Fixed World tree scrolling away when hiding, showing or resetting object parts. Visibility changes retain the expanded rows, horizontal and vertical scroll position, and keyboard focus, including filtered results.
- Expand imported objects in the World tree to select and edit their supported child objects and geometry. Map clicks still select the whole object. Hidden healthy/destroyed branches are listed with their initialized eye states; their eyes can hide healthy and show destroyed without changing source files. Reset part visibility restores the defaults.
- Fixed single-object ClipTo edits failing with a 4,096-source-file error when shared-model validation searches many missing paths. Missing-file checks now have a separate allowance while existing-file verification and shared-mission crater-mode checks remain enforced. Acceptance checks the project boundaries once around the file checks, reducing UI stalls on these edits.

- GameZ Script has moved to its own standalone repository and release. The VS Code extension, language server and source_language MCP command are no longer included in zStudio.


- Camera animation paths are orange; object paths remain teal, with a color key in Paths. Gravity-driven objects in source previews land on standable map surfaces, including terrain and bridges. Procedural movement stops at world Y −500 or 500 without triggering an impact; keyframes and cameras remain unrestricted. Paths, playback and seeking share these rules.
- Playback controls have an opaque, theme-aware background, including their margins and wrapped rows, so the underlying map does not show through.
- **Animations in the map editor.** The World tree has one **Animations** section, containing objects placed by animations and the mission/common definitions. Selecting a definition opens Properties and a structural timeline without running the animation or evaluating paths. Object cards link to exact affected definitions and bindings.
- **Events and activation.** Edit existing event operands, clock thresholds, sequence activation, definition activation and prerequisites in a shared Apply/Revert draft. Edits preserve source comments and formatting, are checked against every map that includes the source file, and become one project undo step. Keyframe scripts and event order remain read-only.
- **One world viewport and timeline.** Playback runs directly in the map, sharing its LOD and Difficulty controls. Play pins the target; browsing another definition only inspects it, while Use selection explicitly retargets. Source shows authored clocks and read-only samples; Run shows observed occurrences and coverage. Children are collapsed and excluded until included per call path. Stop restores the initialized static map; Exit also releases the target. Timeline and Diagnostics share one compact transport with an opaque background.
- **Timing and paths.** Edit timing in Properties using the event's native clock, with numeric precision and a 60 Hz ruler; negative/off-grid source values are preserved. Timeline zoom, pan, fit and follow-playhead are independent of the playback range. Evaluate paths explicitly computes bounded guides in separate silent state; guide eyes only toggle compatible cached results. Camera/object colors, direction marks and discontinuity breaks are retained.
- **Drop windows in Properties.** Explicit Analyze drop windows uses a separate recognized-flight recipe without changing the main preview's child inclusion. Route, timeline and Properties moves share the validated window adapter, preserving STOP duration and neighboring windows. Ordinary CALL/STOP event editing remains available and can change window recognition. The floating panel and top **Show → VTOL route** button are removed from this workflow.
- MCP adds `zstudio_animation_timeline` for structural inspection, child inclusion, scenario configuration and timeline presentation, and `zstudio_source_animation` for the shared definition draft. `zstudio_animation_paths` replaces `zstudio_parachute` for definition paths, source preview and existing drop-window operations. `preview_state.animationPaths` reports the analyzed definitions and snapshots.
- Animation editing checks the visible map, selection and revision. Beginning a source draft detaches the run and marks previous observations stale; Apply/Revert does not restart it. Optional event flags can be disabled and re-enabled; clicking a retained drop-window marker reopens its animation card. Phase, Height, scoped conditions and child inclusion belong to the preview scenario; playback and analysis share its terrain and motion rules.

## 0.9.7 — 2026-10-23

- **One file.** zStudio is now a single, compressed `zStudio.exe` with .NET included, instead of `zStudio.exe` and a `dependencies` folder (459 files in all). The ZIP holds only `zStudio.exe`, `LICENSE`, `THIRD-PARTY-NOTICES.md` (now with every licence text) and the Blender extension `zStudio-Blender-extension-0.9.7.zip`, and shrinks from 79 MB to 72 MB. The first start of each version unpacks the WPF native libraries (about 8 MB) to `%TEMP%\.net\zStudio\`. Decompressing the program in memory makes a start about 0.2 s slower than 0.9.6 and uses about 70 MB more memory. Replace an earlier version's folder rather than extracting over it: its `dependencies` folder is no longer used.
- The guides are no longer in the download: **Help** opens each guide, and the release notes, on GitHub as they are for the installed version. **About zStudio** shows zStudio's licence and the third-party notices.
- The Blender extension is now `zStudio-Blender-extension-<version>.zip` (it was `zstudio_recoil-<version>.zip`), beside `zStudio.exe` instead of in `dependencies\blender`; install it from there. Blender still lists it as **zStudio RECOIL**. It now asks the selected `zStudio.exe` for its version and works with the one of its own version, so the ZIP no longer has to stay beside `zStudio.exe` after installing.
- MCP: `zstudio_help` returns the installed version, the links Help opens and the licence and notice files beside `zStudio.exe`.
- **Update check.** The status bar shows **Update available** (left of Preview notices, also without a map) when a newer release is on GitHub; click it for the release page. zStudio checks at most once a day (**Help → Check for updates automatically**, on by default); **Help → Check for updates** checks now. MCP: `zstudio_update_check`, and `zstudio_state` reports `update`. With it and `zstudio_help` the catalog has 103 tools.

## 0.9.6 — 2026-10-23

- **New 3D renderer.** The 3D views draw with zStudio's own Direct3D 11 renderer on Vortice.Windows instead of HelixToolkit and SharpDX (archived since 2019). The old packages they brought in are gone: NETStandard.Library 1.6.1, Microsoft.NETCore.Platforms, SharpDX, HelixToolkit, Microsoft.CodeAnalysis (Roslyn), Cyotek.Drawing.BitmapFont, CommunityToolkit.Common/Diagnostics and the Windows Forms runtime. The portable ZIP shrinks from 106 MB to 79 MB (577 to 459 files). Maps show their first frame sooner, and a whole map seen from above takes about half the processor time per frame. The preview needs a Direct3D 11 (feature level 11_0) graphics adapter, which every Windows 11 PC has.
- What changes on screen: polygon edges and bounds near the horizon are no longer cut by the sky; of two surfaces lying exactly on top of each other, the same one always shows (before, it depended on the renderer's internal sort); clicks and the navigation cube use the current camera exactly; the axis letters are Arial at the display's scale. VTOL drop-window and AI path selection markers no longer leave a marker at the world origin when there is nothing to mark.
- The 3D view loses the undocumented camera controls HelixToolkit added: with the view focused, the arrow keys, Page Up/Down, W/A/S/D/Z/Q (outside Flycam) and Backspace no longer move the camera, the mouse's Back and Forward buttons no longer jump to an earlier view, and a right, middle or side button press on the navigation cube no longer turns it (left click works as before). Touch acts as the mouse: a tap is a left click, press-and-hold a right click, and touch gestures no longer move the camera. The mouse wheel no longer zooms during an AI path move, rotate or scale, a drop-window move or a box selection, so the camera stays still while the change follows the pointer.
- When the graphics device is lost (a driver update or reset, a locked or remote session), the 3D view rebuilds it by itself; if that fails, it tries again when the display settings change or the session is unlocked or reconnected, and on the next resize or preview load, instead of staying blank. A failure is reported once in the status bar or the animation editor's diagnostics; in a source map it is listed in Problems until the view draws again. MCP `capture` of the 3D preview returns an error instead of an older frame when no frame can be drawn, and now captures while a narrow window's Properties pane covers the workspace.
- **Player tank states.** In a source map, the player tank's card (`bft_00` in the shipped maps) chooses how the view draws it: **Master type** (Tracked, Amphibious, Hover, Sub) and **Weapons** (primary RFPG or ERFPG; secondary any of the 16 others). The card shows them first, with its **Details** after them, collapsed. It is a preview only, never saved: the tank is posed by running the mission's own transition animations to their end, and only the chosen weapons are drawn. A type is offered when the map's data has its transition (m1 Tracked only, m2 adds Amphibious, m3 and m4 Hover, m5 onward Sub); in Sub the weapons the game forbids there are disabled. Opening a map starts as a new game of that mission does (Tracked, RFPG and HE Mortar in the shipped maps); compiled Whole world and animation previews draw that start too, so the tank no longer shows every weapon model stacked on its gun. MCP: `zstudio_scene_options` adds `bftType`, `bftPrimary` and `bftSecondary`, `zstudio_preview_state` adds `bft`, and `zstudio_scene_tree` marks the tank's row `playerTank`.
- The player's start position follows the missions' openings: in m1–m6 the opening holds the controls until it releases them from the tank's pose, and in m2–m6 it also moves the tank there, so the start is read-only and the card says why; m1's start, editable before, is now read-only too. In the multiplayer maps (m7–m13) of a reconstructed project it can now be moved (before, the card showed "missing or ambiguous tank template").
- m2 Easy opens in a source map; before, switching to Easy failed because `aiv_easy.zrd` places the player tank twice. Its card is read-only, and the AI Vehicles rows say "listed twice in aiv_easy.zrd".
- The selected object's card names why its placement can't be edited (a **Placement editing** row in Details), and a selected unit that was hidden becomes editable as soon as it shows again (its eye, the end of an isolation or Show all). Placed AI Vehicles and Pickups rows give their placement in the tooltip and in MCP `zstudio_scene_tree` `placement`. MCP `zstudio_scene_selection` `isolate` now refuses a map's units and pickups (`unsupported`), as the World tree does. `zstudio_scene_tree` `show`, an `isolate` that ends or moves an isolation and `select` of its row, `zstudio_scene_selection` `show_all` and `isolate`, and `zstudio_scene_card` `select` can now select such a unit in the view, which changes `zstudio_scene_inspect`'s `selected`.

- Edited positions of AI network nodes, AIV vehicles and pickups, and AIV headings, are saved with one decimal, as the shipped files write them (pickup rotations, in radians, with four); drags snap to that precision, so the view shows what is saved. Values an edit does not change keep their text.
- Reconstruction keeps a texture's authored shape: the copy chosen has the shape the pack with the most room holds (the larger shape when such packs have equal room). Before, 42 strips of the 1999 release (such as `sonic06`, 128 × 16) became the stretched squares of the smaller packs (64 × 64). Reconstruct affected projects to get the strips back.

## 0.9.4 — 2026-10-21

- Source maps can create pickups through Tools → Add pickup… or the Pickups section's context menu. Choose a catalog type, position, rotation, amount, respawn delay and one or all difficulties. The shared source workspace verifies that the template can spawn, supports undo/redo and saves the owning resource files without creating archives.
- MCP `source_pickup_add` provides the same operation. Exclusive difficulty edits preserve layouts that use fallback resources; adding to all difficulties writes each effective resource once.
- **Export fix:** `OBJECT_ACTIVE_LIST` activation prerequisites now compile with the expected active state the game tests. Before, exported `anim.zbd` files reversed these conditions (m6's deflector cell conditions, which the final boss's destruction waits on, and three m1 checks); re-export affected missions. Animation comparison now checks this value.
- The NAudio (3.3.0) and MCP SDK (ModelContextProtocol.Core 2.3.0) dependencies are updated.
- The World tree's **Pickups** always hold three groups, **Weapons**, **Ammo** and **Other**, each with its count, Frame and eye; **Group by type** (a toggle on the Pickups row) adds a row per type inside them. A weapon pickup shows the weapon itself (the game manual's render), ammo its weapon's HUD icon, health and technology their own icons. Pickups are named by the manual's names and a number per type (`ERFPG #1`, `Proximity Mine #2`) instead of `pu01700`, which stays in the tooltip; search finds them by name, kind, catalog type or game name. A unit or pickup every difficulty places reads **All** instead of `E/M/H`. MCP `scene_tree` adds the group and type rows, `pickupType`, `pickupKind`, `pickupNumber`, `pickupName` and related fields, and a `frame` action; `scene_options` adds `pickupsByType`. **MCP changes for 0.9.3 clients:** pickups are now children of the group (or type) rows rather than of the Pickups row; a pickup's `Label` (and `scene_properties` `Name`) is its tree name (`ERFPG #1`) instead of the game name, which `scene_tree` now gives as `instanceName` (a pickup only other difficulties place was labelled by its template, now `pickupTemplate`); `search` requires every word of the query for every row; a row's `animations` now also lists indirect associations, not only the animations bound to it by name (its initial roots); `animationUses` gives each one's origin (`initialRoot` is the earlier list; both stop at eight).
- Objects that receive mission animations indirectly (turret destruction and firing, vehicle startup, destruction and transitions, pickup collection, weapon flyout models, and other animations' calls and writes) are marked with the animation icon at half saturation; initial roots keep the original colour. Tooltips give each association's reason, and MCP `scene_tree` adds `animationUses` with their origins.
- New reconstructions place m6's `lasdesig` in `data/common/models` and m4's `train`, `rcar1`, `trnsplsh` and `tturret` in `data/m4/models`. Existing projects are unchanged.

## 0.9.3 — 2026-10-19

- The World tree's sections are renamed **World**, **AI Vehicles**, **Pickups** and **Animations (keyframed)** (MCP keeps the pass kinds `aiv`, `puppies` and `anim`), and three are added, in a fixed order: **Zones** after World, **AI Networks** after AI Vehicles and **Animations (definitions)** last. A section, folder or file row opens or closes with a click and is never the selection.
- **Zones** lists the map's zones with their colour, label and polygon count (as placed), and polygons without a zone. Each zone's colour is shown on its own with its eye, and all start hidden; while any shows, the zone overlay is on, in the kind the row's **Objects | Polygons** switch chooses (disabled while none shows; the zone overlays leave the command bar), and another overlay hides every zone. Selecting a shown zone draws it strong, the others faint, and selecting a zone opens its card in Properties: its label (one undo step; the zone picker no longer renames), what uses it and **Paint with this zone**. While Edit zones is on, selecting a zone makes it the zone to paint.
- **AI Networks** lists the mission's networks (`net_01`…) with node counts and their attack strategy's colour. Each network is shown on its own with its eye, and all start hidden; while any shows, the AI overlay is on (these replace the command bar's AI nodes, network picker and See-through). Networks are always drawn through geometry, at half strength where geometry hides them. Selecting a network shows it emphasised and opens its card, which edits its header settings with checks as they are typed, as one undo step that changes only those values in its `net_NN.zrd`. The card uses the names of the developers' own Net Edit dialog, found in the game's executable (Net Name, Net Type, Attack Strategy, Activation Radius, Attack Radius, Return Radius, Attack Dwell, Post Attack Dwell, Pursuit Radius Min and Max, Buddies Attack and Activate, Path Width, Hide Times), and the line under each field says what it does in play; the pursuit lines follow the chosen strategy, and the fields the game never uses are marked. Turning Buddies Attack on also stores Buddies Activate, without which the game ignores it. MCP: `source_ai_network`.
- **Animations (definitions)** lists the `.zad` files the mission's `anim.zad` names, by folder and file, with each definition; a file listed twice shows twice, missing files are listed and definitions that bind nothing in the world are dimmed. A definition's read-only card shows its source, binding, settings, sequences and keyframe scripts, and the objects it binds to are outlined in the view.
- World tree keyboard: Up/Down, Home/End and Page Up/Down move through every shown row without stopping on a row's buttons (section, folder and file rows take focus without becoming the selection), Left/Right reach the row's buttons (Space or Enter presses one, Escape returns to the row), and Space or Enter opens or closes a row with children.
- Empty nodes (an Object3D with no geometry and nothing below it) have their own type in the World tree: a dashed cube in slate, "Empty" in the legend and Properties ("Empty Object3D"), their zone shown and counted in Zones, and no Frame or eye (MCP category `empty`). Before, they showed as groups.
- MCP: `scene_tree` describes the section rows (`sectionRow`, and `master` on the four rows with a master eye) and hides, shows and selects them; `preview_state` reports `sections`; `drafts`/`resolve_drafts` take `target: "section"`.
- The Zones, AI Networks, AI Vehicles and Pickups rows have a master eye that shows or hides everything below them; it changes when pressed, or when everything below comes to be shown, or hidden, one by one. Units and pickups are shown and hidden one by one too; middle-click isolation is left to world objects. Section and pass rows are never drawn faint; hidden zones, networks, units and pickups are. Every row's eye and Frame button are always shown (not only on hover), and the Zones and AI Networks eyes keep their ordinary colour.
- Reconstruction's note on an animation definition rebuilt from `anim.zbd` now says that the game uses that version, compiled from a newer version of the definition than the archived text, with the date `anim.zbd` records for it and what the newer version changes (for example `RESET_TIME ( 0.5 ) → ( 0 )`), leaving out differences of spelling.
- Reconstruction also names a deleted group by the name its node in its part's cache left in a freed slot: five groups of m6's city part are now `street`, `ramps`, `bwall`, `phones` and `hydrants` instead of `groupN` (both releases). A new reconstruction numbers m6's other 75 deleted groups `group1`–`group75`, so all but `group1` change number. To get the names in a project reconstructed before, rename the five with the world tree's right-click **Rename…** (`group7` is `street`, `group3` `ramps`, `group2` `bwall`, `group8` `phones` and `group9` `hydrants`); the game never uses these names.
