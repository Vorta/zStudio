# Pickup placement editor

In a source map, **Tools → Add pickup…** and the **Pickups** section's context menu create a pickup from the engine's 40-type catalog. Enter an explicit XYZ position, Euler XYZ rotation in degrees, amount and respawn delay, then choose **All**, **Easy**, **Medium** or **Hard**. Amount defaults to the catalog value; zero uses the game default. Rotation and respawn default to zero. Coordinates are authored as entered, without terrain snapping.

The map must already load the selected type's template with a copyable `bvol` collision child. Creation evaluates actual placement before accepting one undoable source transaction. Existing records, comments and numeric values are retained. **All** writes each effective resource once; an exclusive difficulty edit creates missing variants when necessary to keep other layouts unchanged, including when Easy or Hard falls back to Medium's default list. Save writes the owning sources; only explicit game export creates archives. MCP: `zstudio_source_pickup_add`.

Editing compiled ZBD assets is being retired in favour of [source projects](source-project.md). A compiled root opens only through MCP `open_root` (the GUI opens only source projects); the workflow below applies there. In a source map, pickups are edited from the selected-object card, without a lock (see [Placements](source-project.md#placements)).

Open a mission's `gamez.zbd`, then **Whole world**. The **Unlock editing** toggle starts unchecked for each newly opened map; turn it on, then click the visible pickup to select it and show its bounds. Hover and tree inspection still work while editing is locked. This lock also governs AI-node and supported AIV tank coordinates.

With **Unlock editing** on, the selected pickup's card fields take input at once, its **Move** toggle shows the three translation arrows (red X, green Y, blue Z) and its **Rotate** toggle shows rotation handles. Drag an arrow to move along that world axis. The card's rotation is the stored Euler XYZ, shown in degrees. The handles use enlarged shafts and arrowheads and keep a consistent screen size as you zoom. Their click targets extend 12 logical pixels to either side of each arrow, including its tip, and take priority over the map beneath them. A hand cursor shows when a handle can be grabbed. Drags and typed values change the card's draft; **Apply** (or Enter in a field) accepts it as one undoable action and **Revert** discards it. Escape, losing mouse capture, locking, or leaving the view cancels an unfinished drag. Outside a pickup drag, middle drag orbits, Shift+middle pans, Ctrl+middle or the wheel zooms toward the pointer, and Ctrl+Shift+middle dollies. See [3D navigation](3d-navigation.md) for keyboard shortcuts.

The separate **Properties** window shows the type, record number, XYZ coordinates, affected difficulties, resource and save target. Enter a number and press Enter or leave the field to apply it. Escape restores the last accepted coordinate. There is no clear-field button. After selecting a pickup, press **Alt+Enter**. The window stays on that placement when you select something else, and its coordinate edits follow the original source identity. If another change removes that record from the map's placements (for example a member deleted or reordered in its archive), the window says the placement is no longer available and accepts no edit; select it again in Whole world. Enable **Unlock editing** in the owning Whole world view to enable edits. Translation does not rotate, resize, snap to terrain, or simulate pickup collection/respawn. An axis aimed directly at the camera may require a different view or numeric entry.

## Difficulty and identity

Moves and rotations apply to all uniquely matching difficulty records. Matching uses pickup type and the original position/rotation, not generated object names or record indices. Amounts and respawn values remain unchanged. If several difficulties use the same fallback resource, it is edited only once. The panel lists difficulties that are unmatched or ambiguous; their records remain unchanged. Switching difficulty or LOD retains authored changes and selection when a unique counterpart exists.

The `m1` lists for Easy, Medium and Hard contain the same 64 placements. A Nanite move therefore updates its three matching records. Pickups are loaded from `puppies_easy.zrd`, `puppies.zrd`, or `puppies_hard.zrd` inside the resolved archive. In `m1` that archive is **`zrdr.zbd`**; the surrounding `gamez.zbd` supplies models and world geometry.

## Save and working copies

- **Save / Ctrl+S** updates the owning working archive. Dragging itself never writes files.
- **Save As / Ctrl+Shift+S** writes a new archive and makes it the session's subsequent save target, even when nothing was edited yet: like an edited archive, it then keeps its own baseline instead of following other documents' changes to the original. While it has no unsaved changes or Undo history, a change saved to the original file is followed: the map reads the new original and later saves still go to the copy. It keeps the current map context; install the saved archive in your own working game-data folder to use it there. Reopening the untouched original dataset still shows its original placements.
- The `zbd_1998` and `zbd_1999` reference datasets remain protected. Save from those directories requests a copy elsewhere. For repeated direct saves, open a separate working copy of your game data.
- Undo/redo use the title bar's Undo and Redo icons or Ctrl+Z/Ctrl+Y. Unsaved changes are marked on the map's row in Files and participate in close/reload/workspace-change prompts.
- Backups have no GUI command: the stored preference (MCP `workspace_view` `backupOnSave`, off by default) applies to every pickup save, and `save_document` takes a `backup` flag for one save.

Saving patches position and rotation nodes in the existing archive layout. Member order, directory records, padding, unrelated resources, unknown bytes and untouched coordinates remain intact. An edited integer coordinate is written as a float node of the same length. All outputs are staged and reparsed before replacement; an external file change prevents overwrite. Each file replacement is atomic. If saving several archives stops partway through, the result identifies saved files and retains the remaining changes as unsaved.

This editor handles mission pickup lists. Pickups authored directly in GameZ, vehicles, turrets, scenery, pickup type/amount changes, and adding/deleting pickups are not editable here. Rendering remains a mission-start approximation. Binary preservation and reopened previews have been checked against the reference datasets; original-game validation is still outstanding.
