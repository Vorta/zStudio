# Architecture and format evidence

MechWarrior 3 base-game layouts extend the same C# format readers: version-27 GameZ, version-39 animations and structurally recognized motion/model-library members. Versioned immutable layout definitions, shared mesh serialization, member-local provenance and `ResourceEditSession` transactions preserve format boundaries and source identities. Motion sampling returns shared animation-frame poses to Rendering. Mission dependency selection excludes other readers from the chosen map; coordinate histories retain archive identity across mission changes. See [MW3 scope, workflows and limitations](mechwarrior3.md).

Responsive Files stays inside the shared Navigator. A single FileTree changes hosts between the first tab and a sibling column; FolderNode owns expansion/selection so WPF container recycling cannot reset them. Layout version 4 adds FilesWidth and ContentBrowserTab while keeping stable BrowserTab identities. Detachment requires FilesWidth + NavigatorWidth + 600 DIP + splitters + the requested animation Inspector width, with a 40-DIP entry buffer. Automatic transitions preserve preferred dimensions and run under the presentation-change guard; deferred scroll/focus restoration checks layout/interaction generations. GUI navigation and MCP section selection use the same adapter. The renderer and editing services do not participate in the transition.

Local MCP adds two projects without coupling binary models to automation: `zStudio.Application` defines commands, schemas, structured results and errors; `zStudio.Mcp` hosts the official SDK over a SID-restricted named pipe and supplies the stdio connector. Desktop supplies dispatcher-bound adapters around existing editor/preview/export/save services. GUI property definitions also supply automation fields/actions. The visible workspace owns documents and renderers; connections do not create parallel sessions. Read-only calls can observe asynchronous operations while mutations are serialized. Document revisions, preview lifetimes and draft tokens guard concurrent GUI activity. MCP shutdown is awaited while the WPF window remains alive. See [MCP architecture and contract](mcp.md) and the independent [capability inventory](mcp-capabilities.json).

The runtime is C# 14 on .NET 10. Core has no UI, rendering or Python dependency; its Windows save safeguards use system filesystem APIs to resolve path aliases. Binary models remain independent of UI and rendering. Rendering owns Helix Toolkit / Direct3D 11 resources. Desktop owns WPF bindings, document lifetimes, dialogs, audio playback, and settings. The portable publish contains `zStudio.exe` and `dependencies/`; the latter holds the application libraries, .NET runtime, documentation, and licenses.

`tools/publish.ps1` publishes into a fresh staging directory and enables the desktop project's `CreatePortableLauncher` target. The SDK's `CreateAppHost` task binds the native GUI launcher to `dependencies/Recoil.Zbd.Studio.dll` and copies its icon, manifest and version resources. The [.NET apphost resolves its application root from that relative DLL path](https://github.com/dotnet/runtime/blob/v10.0.0/src/native/corehost/corehost.cpp), so runtime/native-library discovery remains local to dependencies. No wrapper process or custom assembly resolver is needed. Normal Visual Studio/build output keeps the standard layout. The checked-in `Assets/studio.ico` is a byte-identical copy of the supplied Studio icon, embedded as both a Win32 application icon and a WPF resource.

`FormatRegistry` probes structure and version. Texture packs, ZAR archives, prepared scripts, animation packages, and GameZ are independent readers. A sound ZAR begins with a RIFF member; its trailing index must take precedence over standalone WAV detection. Unsupported versions remain available for raw inspection. Files are immutable snapshots with source identity, record index, offsets, metadata, and diagnostics. File size/write-time changes trigger reload banners.

RECOIL worlds are GameZ version 15 in both releases and the September 1998 demo, and version 13 in the demos built from 21 July to 12 August 1998. Version 13 is read-only and reads into the same world model. Its texture, material and model sections and the other node classes match version 15, with two differences, established from every node of the ten version-13 demo worlds:
- **Node slots are 268 bytes.** After the sphere, version 13 stores the node's cached box as its eight corners in the parent's space (the node's model-and-child box under its own matrix; the bottom face, then the top, each starting at minimum X and maximum Z), then the model and child boxes and the activation pointer. The reader rebuilds the cached box from the model and child boxes the node's flags name, which reproduces every stored corner in the demos, and otherwise maps the corners back through the matrix.
- **Object3D records are 156 bytes.** A translation follows the scale, and the matrix and the rest move 12 bytes. The matrix already carries the translation (it is set wherever the vector is zero), so the reader drops it into the version-15 record and keeps it visible as the `translate` field.

`GameZWriter` writes version 15, so a demo world read and written again is a version-15 file. RECOIL's version-28 animations bind to a version-15 or version-13 world (the August demo pairs them with version 13). Model replacement and other GameZ saves accept only versions 15 and 27.

`field-layouts.json` is the checked-in, embedded source of fixed-layout definitions and the initial event catalog. Its source hash preserves provenance from the former Python reference; that CLI and its one-time snapshot generator are archived outside this repository. Maintain these definitions directly, reviewing semantic changes against engine evidence. No generation step or Python installation is required to build. Variable-length readers validate their own ranges and count budgets. Nonfinite float bit patterns remain inspectable as hexadecimal strings. Pointer words remain metadata.

Evidence hierarchy: engine code/decompilation, corpus bytes, then historical documentation. Each conclusion names the operation it establishes. The retail executable shows how the game behaves at run time, not how the lost build tool wrote the shipped files, so build behaviour comes from the shipped files. For example, the runtime polygon routine removes colinear corners, but the shipped models keep them, so the source importer keeps them too. Maintainer-only references are the RecoilRebuild `src/GameZRecoil` reconstruction and `Recoil.bndb` Binary Ninja database. These are external, read-only research references; they are not distributed and are not required for normal builds or unit tests. Addresses and symbol names in the documentation record the inspected evidence.

Scene details confirmed against `zClass/Camera.c`, `zClass/Object3d.c`, and `zMath/zmth_main.c`:

- Matrices store three basis vectors followed by translation, not interleaved translation. Local transforms compose before parent transforms using System.Numerics row-vector convention.
- Node visibility uses the base node's `0x4` flag; Object3D data's `0x8` flag bypasses its local transform.
- World partition cells own terrain/static roots in addition to world children. Duplicate cell-root references are collapsed, while child instancing is preserved.
- LOD uses squared near/far distances. The explorer selects an authored detail rank independently within each parent's bands, defaulting to rank 0 and clamping higher ranks per object; it does not simulate camera-distance fades.
- The horizon and its descendants follow the active viewport camera. They are hidden by default in the world overview and optional in animation previews. A background material pass draws them before foreground without depth writes or near/far clipping. OBJ exports retain the assembled hierarchy, including the horizon.

Geometry triangulation handles concave polygons, validates indices, preserves per-corner UVs, and derives missing normals. OBJ bakes instance transforms, uses inverse-transpose normals, corrects mirrored winding, and converts texture V for OBJ consumers. Textured surfaces use unlit diffuse materials to preserve decoded texture colors without additive ambient light or directional light. Untextured surfaces use gentle view-dependent shading to retain shape readability. Static world browsing does not simulate game effects. The animation viewport adds per-instance transforms, inherited opacity, texture cycles, morph deltas and approximate facades, lighting and fog; see `animation-editor.md`.

Whole world surface highlights classify existing parsed records: material `soil` at byte 32 is non-default when nonzero; base-node `flags` bits `0x10000` and `0x20000` identify CanModify and ClipTo respectively. Retail setters at `0x447D20`/`0x447D70` change those individual node bits, with their names preserved by the reconstruction's copy-node error messages and interpreter's `NodeSetCanModify` command. The material reset at `0x480C40` zeroes byte 32; the soil-name table at `0x4E0FD0` starts with `default`, followed by water, seafloor, quicksand, lava and fire. Classification uses the node's own flags, without ancestor/name-based inference or changes to the binary schema. Unknown nonzero soil values remain highlighted.

World batches separate instances by these two flag bits while sharing geometry and normal materials. One mutually exclusive highlight mode swaps matching batches to cached unlit yellow/green/red materials without replacing meshes or moving the camera. White-RGB copies of decoded alpha textures are prepared off-thread and preserve source alpha/cutouts, including when normal textures are hidden. These maps are separate from the Textures toggle; ordinary material and transparent-pass depth behavior is retained. The GUI and MCP share the same mode setter, and asynchronous replacement applies the latest session choice when publishing. See [surface highlights](world-highlights.md).

The shared 3D viewport uses explicit Blender-style gestures before Helix hit testing: middle orbit, Shift+middle screen pan, Ctrl+middle centered zoom and Ctrl+Shift+middle dolly. Orbit/pan/zoom retain decaying inertia. The first unmodified middle press picks the nearest eligible rendered scene triangle, including transformed instances and runtime animation meshes; helpers and horizons are excluded. Orbit rotates the eye offset and viewing basis together about a separate world-space pivot without recentering. Centered perspective zoom samples the current pointer ray against eligible scene geometry and uses camera-to-hit distance for travel speed, retaining the last reference on a miss. It refreshes the query between substeps of at most one wheel step and throughout inertia. Shared surface queries use the current camera without mutating the orbit pivot or depending on cached clipping planes. Orbit picking does not reset zoom speed; forward travel continues past the old target. Named axis views are orthographic; exact top/bottom poses are preserved with a stable camera basis, while free orbit and authored/Fly cameras retain upright +Y and ±89° pitch. Axis views automatically return to perspective on orbit, while explicitly selected orthographic remains. Camera snapshots retain projection, orthographic width, axis/automatic-perspective state, orbit pivot and navigation reference distance. Projection changes preserve target-plane apparent scale using the actual renderer projection convention and aspect. Clipping uses perspective side planes or parallel orthographic planes; picking, framing, billboards, horizon and constant-pixel pickup handles support both. Shared navigation exits animation Follow camera without changing simulation time. Frame uses visible transformed geometry, with stable source-node/descendant selection and runtime instances, excluding horizon/grid/handles. See [3D navigation](3d-navigation.md). Static model/world Fly instead uses normalized held-key movement integrated by elapsed time before camera finalization. Desktop owns foreground raw mouse registration, cursor confinement and capture lifetime; a recentered pointer fallback supports absolute/remote/injected input without raw relative motion. WASD moves relative to the viewing direction, Space/C along world Y, and wheel changes a bounded speed without translating the camera. Rendering owns navigation math and exposes state, speed, movement and relative-look operations. Escape, deactivation, focus/capture loss, hidden/disabled/replaced previews and shutdown clear input and restore orbit controls. Fly activation is explicit and separate from scene-option refresh; it is not persisted or added to animation previews. Camera normalization also covers keyboard/native rotation inertia, view-cube transitions and authored-camera following. Authored positions and serialized camera records are unchanged; terrain collision is not simulated.

Near and far clipping planes use visible transformed mesh geometry. Cached local bounds provide broad-phase view rejection; intersecting bounds refine against triangles clipped to the four view side planes and navigation floor, with double-precision camera subtraction. A guard band and conservative near/far padding protect visible surfaces. Invisible meshes and the horizon do not affect clipping. This avoids collapsing the near plane to a tiny value merely because the camera enters the world's aggregate AABB. The scale-dependent navigation floor remains 0.001–0.05 scene units, independent of the projection near plane.

A `Viewport3DX` subclass reimplements `IViewport3DX.Update`: Helix first finishes camera inertia, then Studio normalizes the final pose, refreshes facade/fog/horizon appearance and computes clipping before the render host copies camera matrices. Camera notifications invalidate only; they cannot recursively reapply animation poses or overwrite the final stationary frame. Animated mesh identities, morphs, texture-cycle sampling and static-instance replacement change on animation updates, not camera motion. Rendering remains on demand. Regression capture reads the existing back buffer, while sized exports scale a current-size bitmap without resizing the live render target (avoiding Helix's physical/logical DPI restore mismatch).

Texture lookup prefers sibling hardware texture variants, then software variants, then the root image pack. An explicit variant can be selected. Cache entries are bounded and checked against file stamps. Ambiguous record names are reported. Missing mission textures stay untextured; another mission's similarly named resource is not silently substituted.

Exports use source record IDs in filenames, reject destination traversal/directory links, create unique output folders, and write individual files atomically. They do not change source files. A canceled batch may leave completed exports in its new folder. JSON exports are an inspection schema, not the CLI's repack schema. Animation version 28 has a separate editable package model, bounded undo snapshots and a verified Save As writer. Its byte-preserving records keep unknown fields and opaque sequence tails. Simulation uses cloned runtime state and deterministic fixed steps with bounded seek checkpoints.

Whole world pickup editing uses a separate `PickupPlacementEditSession`. Stable archive/member/record identities retain authored coordinates and original-pose links across difficulty resources. The viewport uses a proxy translation gizmo and per-instance overrides; shared meshes and cached mission baselines remain unchanged. Save patches only changed scalar coordinate nodes in the owning ZAR archives, including integer-to-float conversion when needed. Outputs are reparsed, checked for unrelated-byte changes and staged before atomic replacement. Saved baselines, external-content checks and per-archive results retain accurate dirty state after partial failure. Save As retargets subsequent saves; backups are optional and off by default. Reference dataset paths remain protected. See [pickup-editor.md](pickup-editor.md). General ZAR and typed ZRD editing use ResourceEditSession and the shared ZrdDecoder model. Archive and pickup editors claim shared source paths until their document closes; edited resource snapshots feed the existing resolver. See [resource-editing.md](resource-editing.md). Prepared script editing and other unsupported format operations remain read-only.

WPF Fluent runtime theme switching is still marked experimental by Microsoft; the `WPF0001` opt-in is scoped to the theme-switch method. See the [WPF Fluent guide](https://github.com/dotnet/wpf/blob/main/Documentation/docs/using-fluent.md). Tests use .NET 10's [Microsoft.Testing.Platform runner](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-test).


## Texture and script edit snapshots

`ContentEditSession` provides snapshot history, ownership callbacks, external baseline checks and staged verified per-file saves for `TextureEditSession` and `ScriptEditSession`. Texture batches prepare complete immutable outputs before acceptance; direct/indexed encoding extends `TexturePackWriter`, and PNG parsing reuses `ModelImport.ReadPng` with an explicit dimension bound. `ScriptReader` supplies the lossless instruction/package model to both inspection and editing, and `PreparedScriptWriter` retains untouched storage. Resolver publication supplies pending texture/script snapshots to existing preview consumers. Other open texture documents follow the batch owner read-only and re-read disk on owner close; explicit Reload establishes their next baseline. GUI and MCP share these services, revisions, generated fields and asynchronous drafts/actions. See [texture-script-editing.md](texture-script-editing.md).
