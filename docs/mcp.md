# MCP

zStudio lets local AI agents work in its visible workspace through the Model Context Protocol. An agent and you share the same documents, edits, undo history, drafts, previews and verified saves; there is no separate headless mode. The connection is a named pipe restricted to your Windows user, with no network port.

## Connect

1. Open **Tools → MCP integration…** (also on the welcome screen) and check **Enable local MCP access**. Access is off by default; the choice is remembered. An agent cannot turn it on.
2. Click **Copy configuration** and add it to your agent's MCP configuration. The generic JSON form is:

```json
{
  "mcpServers": {
    "zStudio": {
      "command": "D:\\Tools\\zStudio\\zStudio.exe",
      "args": ["--mcp"]
    }
  }
}
```

3. Ask the agent for the workspace state. The first workspace request opens zStudio, or attaches to the running instance of that installation. Starting the agent and discovering tools leaves zStudio closed.

Keep `zStudio.exe` at a stable path. If several instances of the same installation run, add `"--instance", "ID"` to `args`, with the ID shown in the integration window (valid for that running instance). **Disconnect clients** drops current connections; restart the agent's connection afterwards. Unchecking **Enable local MCP access** revokes access. A workspace call that answers `access_disabled` means access is off. After moving or updating zStudio, check the configured path and restart the connection. Any process running as your Windows user can connect while access is enabled.

### Codex

Add this to `%USERPROFILE%\.codex\config.toml` (or your `CODEX_HOME`'s), updating any `mcp_servers.zstudio` section already there rather than adding a second:

```toml
[mcp_servers.zstudio]
command = 'D:\Tools\zStudio\zStudio.exe'
args = ["--mcp"]
enabled = true
startup_timeout_sec = 60
tool_timeout_sec = 120
```

Single quotes keep the backslashes. Alternatively run `codex mcp add zstudio -- 'D:\Tools\zStudio\zStudio.exe' --mcp`, then `codex mcp get zstudio` to check it. Restart Codex after changing its configuration.

## Discovery

`tools/list` returns every tool with a typed input schema and a description; the descriptions are the reference for each tool's behaviour and results. `resources/list` offers `zstudio://state` and `zstudio://capabilities`. Initialization, discovery and schema reads never open a window. Start a session with `zstudio_state` and `zstudio_capabilities`.

Arguments are validated against their schemas before anything runs; a malformed request answers `invalid_argument`. File and folder arguments (`open_root`, `open_document`, export destinations) must be full paths. Project paths in source tools (`model`, `recipe`, `file`) are relative to the project.

## Workspace model

- **Source project**: a folder with `data` and `gamegen`, opened with `zstudio_open_root` and `project: true` (or **File → Open workspace…**), or created with `zstudio_source_reconstruct`. One map is open at a time: list maps with `zstudio_source_world_list` and open one with `zstudio_source_world_open`. A source project is where editing happens; game files are produced only by `zstudio_source_export`.
- **Compiled root**: a folder of shipped game files, opened only through `zstudio_open_root` without `project`. It is read-only: inspect, preview and export its assets (see [Compiled game files](compiled-files.md)).

## Identities and revisions

- Use the identities that tools return: document UUIDs, asset kind and index, sequence and event UUIDs, node indices, pickup source identities, row identities in `zstudio_scene_tree`. Names are labels and are not unique.
- Every accepted edit increments the document revision. Mutations take the expected `revision`; a stale one answers `revision_conflict`.
- Preview commands take the current `preview` UUID from `zstudio_state`; a replaced preview answers `stale_preview`. Tree and inspection reads return a `context` token that later actions check.
- The GUI can act between your calls. Re-read state after an edit or navigation; a request whose target changed answers `context_changed` rather than acting on something else.

## Changing a source project

- **Transactions.** An edit is prepared and evaluated in memory before it is accepted, as one undo step. A change that cannot be evaluated answers `build_failed`; a file changed by another program answers `external_change`. Neither changes anything. Each edit returns the document to use next.
- **Drafts.** Unfinished GUI input (a Properties field, a scene card, a zone, AI network or animation card) blocks writes with `pending_drafts`. Read it with `zstudio_drafts` and apply or discard it with `zstudio_resolve_drafts`; nothing is committed or discarded implicitly.
- **Placement precision.** Positions of pickups, AIV vehicles and AI network nodes, and AIV headings, are stored with one decimal; pickup rotations in radians with four. Only changed values are rewritten; a change below that precision changes nothing.
- **Busy.** While the map is being evaluated, saved, or a GUI dialog waits for the user, mutations answer `busy`; reads and `zstudio_operation` keep working.
- **Undo and save.** `zstudio_undo_redo` steps through the project's shared history. `zstudio_save_document` writes every changed source file as one recoverable publication, after checking for external changes. `zstudio_source_changes` lists unsaved files, the history and a line diff. `zstudio_close_document` needs `discard: true` to drop unsaved edits.
- **Recovery.** An interrupted save is listed in `zstudio_problems` when the project opens; decide it with `zstudio_source_recovery` and `zstudio_source_recovery_resolve` (roll back, complete or abandon). MCP shows no dialogs.
- **Export.** `zstudio_source_export` builds game files from the saved project (save or discard edits first). Without `destination` it only checks that everything builds. With a destination outside the project it stages and re-parses every output (or the `outputs` you list) and writes nothing if one fails; replacing game files already in the destination needs `overwrite`, and they are restored if writing fails. `zstudio_source_export_selection` shares the GUI checkbox choices across projects and restarts: `action: get` returns paged output paths, groups and selected states; `select` or `clear` updates specified `outputs`, or every current output if omitted. These actions never export. Pass the desired checked paths explicitly to `source_export`; its omitted `outputs` still means all files.

## Operations

Long tools (those whose description says they return an operation ID, including `zstudio_ai_path` and drop-window analysis) return an operation object (`id`, `Name`, `State`, `Cancellable`, `result`), possibly already completed. Poll `zstudio_operation` until `completed`, `failed` or `canceled`, then read `result`. Exports, validation, source project and map operations and world comparisons can be cancelled with `zstudio_operation` `cancel`; opening another root or closing zStudio cancels obsolete work. Operations continue after the client disconnects; the newest 128 are kept.

## Paging and limits

- Lists take `offset` and `limit` and return `nextOffset` (null at the end). A page can hold fewer rows than `limit` so that complete identities and paths fit; follow `nextOffset`. A single row too large to return answers `too_large`.
- Requests are limited to 2 MiB per message and 1 MiB of arguments; results to 4 MiB. Long values are shortened with an explicit `…Truncated` flag and the full count; identities and paths are never shortened. Use paging, `zstudio_source_bytes` (at most 4,096 original bytes) or `zstudio_export` for complete data.
- `zstudio_capture` returns a PNG of the current preview or of a zStudio window (never other applications); 3D captures fit within `width` and `height` (at most 4,096) without resizing the view.

## Errors

| Code | Meaning and what to do |
| --- | --- |
| `invalid_argument` | Bad or out-of-range input; correct it. |
| `revision_conflict` | The document changed; read `zstudio_state` and retry with the current revision. |
| `stale_document`, `stale_record`, `stale_preview`, `stale_context` | The target was replaced or closed; read it again. |
| `context_changed` | The GUI or a newer request changed the target meanwhile; read again and retry. |
| `pending_drafts`, `draft_conflict` | Unfinished input; resolve it with `zstudio_resolve_drafts`. |
| `busy` | Evaluation, a save or a dialog is in progress; retry later. |
| `not_ready` | The view or data the command needs is not shown yet (for example while a map reloads). |
| `unsaved_changes` | Save, or close with `discard: true`. |
| `build_failed` | The edit would not build or the game would reject it; the message says why. |
| `external_change` | A source file changed on disk; reopen or reload the map. |
| `read_only`, `unsupported` | The target cannot be changed this way (compiled files are read-only). |
| `source_map_required`, `no_project`, `not_project`, `no_workspace` | Open a source project (a folder with `data` and `gamegen`) or a map first. |
| `too_large` | A row or result exceeds the limits; narrow the request. |
| `io_failed` | A file could not be read or written. |
| `access_disabled` | MCP access is off in **Tools → MCP integration…**. |

## Viewport

The camera is moved semantically: `zstudio_camera` reads the pose and orbits, pans, zooms, dollies, frames or sets views and projections, as the mouse does in the GUI ([3D navigation](3d-navigation.md)); an optional `screenPoint` picks the surface under that point as orbit pivot or zoom target. MCP never captures your mouse or keyboard. Manual camera moves leave an animation's Follow camera. `zstudio_presentation` toggles Fullscreen (**F11**) and Hide UI (**F10**). `zstudio_scene_options` sets what the toolbar sets (LOD, difficulty, textures, wireframe, face orientation, bounds, horizon, surface highlights, AI overlays) and, in a map, how the view draws the [player tank](map-editor.md#player-tank): `bftType` (`tracked`, `amphibious`, `hover`, `sub`), `bftPrimary` (`RFPG`, `ERFPG`) and `bftSecondary` (the pickup catalog's names without `_WEAPON`, such as `HEMORTAR` or `NAPALM`), applied together; a type the map's tank has no transition for, a beam or fire weapon in sub, a compiled world or a difficulty without a player tank is refused (`unsupported`) with the reason, and a change while the map is still opening is `not_ready`. `zstudio_preview_state` reports the shown preview's options, camera, playback, the state of AI path editing and VTOL routes, and `bft`: the tank's row node, the choice, what the view draws (`shown`) and the mission's start (`defaults`, from its data), each type's availability and reason, the secondaries, the gun models drawn, `posing` while the view rebuilds with the choice, `rebuilding` while a change would be refused as busy, and the card's note (compiled worlds report their defaults with `adjustable: false`; a tank that could not be prepared reports only `adjustable: false`, its `vehicle` and the `failure`). `zstudio_scene_tree` marks the tank's row with `playerTank: true`. In a map, `zstudio_scene_tree` `show` (and an `isolate` that ends or moves an isolation) and `zstudio_scene_selection` `show_all` and `isolate` also select in the view an object that was selected in the tree while hidden: the view selection, the Properties pane and `zstudio_scene_inspect` `selected` change, and its placement can be edited. Selecting it again does the same once the view shows it (the GUI's "Click it in the view"): `zstudio_scene_card` `select` with its `node` or `target`, or `zstudio_scene_tree` `select` of its row. While a draft is open those selects and `zstudio_scene_selection` are refused with `pending_drafts`; `zstudio_scene_tree` `show` and an `isolate` that ends an isolation still change the view but leave the selection as it is (with a card draft open, starting or moving an isolation is refused too). Only an open `zstudio_ai_path` or `zstudio_animation_paths` draft is followed up: once the application is idle after its confirm or cancel returned, the object is selected, so read `zstudio_scene_inspect` or `zstudio_preview_state` afterwards. In a map, units and pickups are never isolated (`zstudio_scene_selection` `isolate` refuses them as `unsupported`).

## Updates

`zstudio_state` reports `update`: whether a newer zStudio release is published (`status` `available`, `current`, `unknown` with a `reason`, `disabled` or `checking`), the `current` and `latest` versions, the release page `url` and when a check last got the latest release from GitHub (`checkedUtc`). `zstudio_update_check` reads the same, asks GitHub now (`check`, as **Help → Check for updates**; this works with automatic checks off, because you or the agent asked) or turns automatic checks on or off (`automatic`, as **Help → Check for updates automatically**). MCP never opens the release page; the status bar's **Update available** does that when you click it.

World objects in `zstudio_scene_tree` expand into their authored child objects, geometry and LOD branches, including initialized hidden states. Selecting a child selects that exact node; map picks still select the whole placed object. Child `hide`/`show` changes a preview-only visibility gate and can replace the preview, so retain the returned `context` and `preview`. Each physical part row reports `visibility` (`DefaultVisible`, `Visible`, `Override`, `EffectiveVisible`, `Reason`); a visible gate can still be blocked by its parent, isolation or LOD. `zstudio_source_map_parts_visibility` with `action: "reset"` restores the object's initialized gates. **Show all** clears ordinary row hiding and isolation while retaining these part gates.

For exact child inspection and supported source edits, pass `scope: "node"` to `zstudio_source_world_object`, `zstudio_source_world_command` or `zstudio_source_world_object_edit`. The default `scope: "object"` retains whole-object targeting. Unsupported child copy, delete or reparent operations are refused instead of targeting the parent. Source edits to a shared model still affect every load of that model; visibility overrides apply only to the current preview occurrence.

## Example

Move an object in a map and check that the project still builds:

1. `zstudio_open_root` with the project folder and `project: true`; poll the operation.
2. `zstudio_source_world_list`, then `zstudio_source_world_open` with `mission: "m1"`; poll it and keep the returned document UUID and revision.
3. `zstudio_scene_tree` with the document and a `search`, to find the object's row and `node`.
4. `zstudio_source_world_object` with the node, to read its transform and where it comes from.
5. `zstudio_source_world_object_edit` with `document`, `revision`, `node`, `action: "transform"` and `position`; poll it and keep the new revision.
6. `zstudio_source_changes` to review, `zstudio_save_document` to save.
7. `zstudio_source_export` without `destination` to check the build, then with a destination folder to write game files.

Animation path metadata includes `Kind` (`object` or `camera`), shown as teal or orange guides. Source paths and playback query current active standable surfaces beneath moving node origins, excluding the bound assembly; runtime transforms and morphs update collision. Procedural object movement stops at world Y −500 or 500 without impact cues; keyframes and cameras are unrestricted. `preview_state.animation` reports `collisionMode` (`terrain`, `plane`, `none`), `proceduralYLimits`, and limit diagnostics in `status`; path diagnostics appear in `animationPaths`. `animation_options.collision` controls the isolated flat plane and is refused in source-map preview, where terrain collision is automatic.

In a source map, `animation_mode` is Animation mode: `state` reports whether it is `active`, the `opened` definition and binding, Back/Forward, the `keptScenario` summary and the `layout`. `open` takes `document`, `revision` and a `definition` (its binding: the first, or `entry`); it resolves no drafts (pending ones are refused), never plays, evaluates or moves the camera, keeps the scenario with the opened binding as its primary (opening another definition keeps the previous primary as an ordinary start at its time, refused at 32 starts; another binding of the primary's own definition, as `binding` and the binding picker choose, replaces the primary at its time; a binding of the definition whose primary an edit took away, also one made while the map was closed, stands in for it at its time until it matches again) and returns a new `preview` id. `exit` stops the run, keeps the scenario and selects the definition. `back` and `forward` walk the opened definitions; `binding` takes `entry`. `layout` sets `view` (`structure`, `timing`, `split`; split needs a 1,300 DIP panel), `panelHeight` (at least 240), `rightTab` (`inspector`, `scenario`), `tree`, `diagnostics` and `diagnosticsHeight` (the strip under the panel, 96–700, given at most the room the panel leaves and at least 96, the panel keeping its height; `state` reports the height shown; in the mode `workspace_view` `navigator`, `tools` and `toolsHeight` change the same, never the map layout's panes); the whole request is checked before any of it applies. Zone painting is refused in the mode (`source_zone_tool` engage, as the GUI's tools). `animation_transport` drives the opened binding's run with seconds: Play prepares lazily, Pause keeps a silent complete frame, Seek evaluates silently at 1/60 s ticks, `previous`/`next` step one tick, and Stop restores the initialized static world, including the chosen player tank.

`animation_graph` is the Structure view with the GUI's identities (`activation:<entry>`, `frame:<entry>`, `sequence:<entry>:<guid>`, `row:<entry>:<guid>`, `ref:<group>`, edge ids from `read`); it needs Animation mode on a bound definition. `read` pages `section` `nodes` (default), `edges` or `rows` (with `node`, a sequence: its rows and its condition and loop blocks) by at most 100 (`offset`, `limit`, `nextOffset`); nodes carry their kind, column, order, bounds in layout DIP, collapse state, sequence, reference, activation (triggers, prerequisite groups with each item's state, callers) or frame details and their `run` at the playhead (a sequence's `state` follows the rule Timing's lanes use: of an instance that ended, `complete` only if it completed and `stopped` if it existed but was running, waiting or never ran when the instance ended, so a stopped binding's completed sequences stay `complete`; `notReached` without any evidence); edges carry `relation` (`call`, `callWait`, `localChild`, `release`, `contactRelease`, `stopSequence`, `stopAnimation`, `resetAnimation`, `invalidateAnimation`, `prerequisite`), `backLink`, their call `paths`, `included` (`all`, `none`, `some`), `run` (reached, latest time, excluded, refused) and the routed `points`; rows carry their vocabulary label, threshold badge, block and branch, members, whether and where they are shown, their `switch` (`game`, `true`, `false`) on IF/ELSEIF and their `run` (disposition, occurrences) and `condition` (pass count, latest outcome, at most 40 passes, and `pips`: drawn on the outcome line, at most 3, or on the question's `passStrip`, at most 40, with `more` for the rest; a question in a loop, or one tested more often than its outcome line holds, has the strip). A blocked sequence's run names the call it waits for (`blockedCall`) and that call's edge (`blockedBy`): `select` with that `edge` is the GUI's Blocked link to its include toggle. An activation's prerequisite groups report their `outcome` at the binding's latest start attempt (`met`, `unmet · refused`, `unmet · ignored for this start`) and each item its check there (`met`, `status`, `atStart`); the binding's run adds that start's `prerequisites`. Every result adds `graph`: identity, counts, expanded groups, bounds, `selection`, the `viewport` (zoom, centre, visible rectangle, level, run overlay, realised nodes) and the `run` time, staleness and player. `expand` and `collapse` change presentation only: `node` a reference node (one frame for its group, showing one binding at a time: `member` chooses it, as the frame header's switcher does, the first by default; at most 64 expanded, `limit_exceeded` beyond; the frame's `group`, `members` and `memberIndex` and the reference's `member` report it, and the frame's run `members` sums up every member's state) or a sequence (with `showAll` every row), `row` a grouped row's members, `all` every sequence. `select` takes `node`, `row` or `edge` (its source row) as a click does and returns `rangeDrawing` (`center`, `radius`, `player`, `distance`, `inside`) for a PLAYER_RANGE question or a range-gated activation, and the Inspector's card as `inspector`; an empty selection clears it (even with a draft pending, as Esc in the view). `inspector` reads that card without selecting (see below). `viewport` takes `zoom` (0.25–2), `center` ([x, y] layout DIP), `fit`, `reveal` (a node or row) and `runOverlay`, all checked before any applies; it needs the Structure view shown. `callers` pages every call or by-name event of the map that reaches `entry` (the opened binding by default). A condition switch is `animation_scenario conditions` with the frame's call path (`""` for the opened binding) and a call port `animation_scenario include` with the edge's paths, exactly as the GUI's switches and ports do.

`animation_scenario` reads and changes the map's one scenario, the object the Scenario tab shows (a change shows there at once). `read` returns the starts (in the map layout too), the call paths the starts reach, condition overrides, inputs, rules and whether it is customized; the groups of call paths are paged by `offset` and `limit` (`nextOffset`), each with its first 16 paths, and `read` with a `group` (its `group` key) pages that group's paths (`groupPage`). `starts` replaces the schedule with up to 32 `{id, entry, seconds}` records (primary id `00000000-0000-0000-0000-000000000000`, the opened binding; 0–3,600 seconds). `include` takes canonical call `paths` and `included`: including adds the calls leading to a path, excluding removes the paths below it. `includeAll` includes every reachable call except back-links and returns what it did (`scope` `opened`: only the paths below the opened binding's start, the other starts' calls excluded, as Include ▾ → This animation only); `excludeAll` clears them. `conditions` takes `{instancePath, entry, event, value}` records, `value` `game` (remove the override), `true` or `false`, on an IF or ELSEIF event, all applied as one change. `inputs` takes `player` (`{kind: atStart}`, `{kind: custom, x, y, z}` or `{kind: none}`), `seed`, `effectsDetail` (`High`, `Medium`, `Low`), `phase`, `height` and `beamOrigin` (`[x, y, z]`, or empty for the root). `pick` places `target` (`player`, `beamOrigin`) at the surface under `screenPoint` (DIP from the 3D view's top left), as Pick in view does. `rules` takes `prerequisites` (`check`, `ignoreStarts`, `ignore`), `rangeGates` (`game`, `ignore`) and `zoneGates` (`ignore`, `view`). What a source edit leaves unmatched (a start, an included call path, an override) stays in the scenario, marked: it never runs, is saved with it and comes back when an undo, a redo or a later edit makes it match. What changes while a binding stands in for the primary an edit took away carries over to that primary when it matches again (the stand-in's time, call paths and switches, a call that names its target by pattern reaching the primary's own sibling), without marks, and what cannot apply is dropped. `read` reports what is marked as `unmatched` (`starts`, `paths`, `conditions`, the `kept` kinds and up to 64 `items` with `kind` and `text`; null when everything matches, also while the scenario keeps only the hidden primary a stand-in hands back to after `remove` of the starts or `reset`), and `unmatched` with `resolve` (`remove`: drop them for good; `keep`: keep them marked and stop asking) and `kind` (`starts`, `paths`, `conditions`, `all`) is the Scenario tab's **Remove** and **Keep** (`not_found` when nothing of that kind is marked); like the tab it also applies with a draft open, and the kept kinds are saved with the scenario. Each item's `text` names its start or the call it sits in and the sequence, numbered when two would read the same; excluding a call path (`include` with `included` false), `excludeAll` or `includeAll` with `scope` `opened` (the other starts' paths) also drops the marked call paths below it, under a stand-in the marked primary's same ones too, and for a call into the stand-in's binding from another start the marked same call into the primary's binding; a `keep` restored with a scenario whose files mark more of that kind asks again. `reset` restores the defaults with the opened binding (after Exit, the kept one) as primary and clears what is marked (a primary standing in keeps, hidden, the place it hands back to when an undo takes its own binding away); `fitRange` sets the playback range to the latest start plus 30 seconds. Every change stops playback and re-evaluates up to the playhead before the call returns (a change made while another re-evaluates goes to the same playhead; a call waits only for its own re-evaluation); it never edits source files and makes shown VTOL drop analysis stale.

The Inspector's card is one object, the same for the GUI and MCP (`animation_graph inspector` or `select`, `source_animation card`): `kind` (`definition`, `activation`, `sequence`, `event`, `condition`, `call`, `reference`; `map` for the map layout's card), `title` and `subtitle` (the header above the Inspector | Scenario tabs), `selection`, `definition`, `entry`, the source `record`, the frame's call `path`, its `notices`, and `sections`, each with `id`, `title`, `summary`, `live` (it follows the run) and `items`. An item's `type` says how to act on it: `field` is a source field of the card's definition (`field` is its ID: `source_animation set` with `changes`; `layout` `check` is a check box such as Waits for release, `list` one name or path per line with `marks`, the ✓/○ satisfaction of each line at the playhead); `threshold` is the Start threshold (`field`, `present`, `clock`, `seconds`, `editable`, the `sentence` and, only with evidence, `observed`: `source_animation set` with `startClock`/`startSeconds` changes it and Add threshold, the field's change with no values clears it); `switch` is a condition's Game/True/False in one call path (`instancePath`, `entry`, `event`, `value`, `outcome`: `animation_scenario conditions`); `include` is Included in preview for call paths (`paths`, `included`, `below`: `animation_scenario include`); `text` is a line (`style` `info` carries a Condition card's game rule in words with the current inputs, `caution` a notice); `pair` a label and value with an optional `link`; `table` the outcomes or occurrences (each row's `seek` is `animation_transport seek`); `bindings` the definition's bindings (`plays`: `animation_mode binding` chooses another); `actions` and `link` name their operation (`select`: `animation_graph select`; `open`: `animation_mode open`; `expand`: `animation_graph expand`; `tab`: `animation_mode layout`; `object`: `scene_tree select`; `frame`: framing); `source` the file, line, excerpt and affected maps (`source_animation context`); `host` the Drop windows panel of a VTOL flight's Definition card (`animation_paths` without a definition); `noticeGroup` the definition's generic preview approximations, folded into one line (`label`, `notices`). `source_animation select` and `set` edit only in Animation mode; in the map layout the card is a summary and `set` is refused (`not_ready`).

`animation_runtime` `notices` pages every notice of the opened animation, as the view bar's chip lists them: `kind` (`approximation`, `support`, `ignoredPrerequisites`, `refused`, `unavailable`, `preview`, `limit`), `severity`, `text`, `count`, `time`, `generic` (a preview approximation about a kind of event, not an item: the cards fold them into one line, and badges and the chip's count leave them out), and where its ⚠ badge counts: `node` (a graph node), `row` (a graph row) and `lane` (a Timing lane); the item's Inspector card lists the notices naming it first. `animation_runtime` `player` reads the player reference at the playhead: `position`, `source` (`aiv start`, `opening handover`, `custom`, `none`, or `callback 10`/`callback 17` with `since`, when it moved it), `frozen` (callback 11 suspended the player), `evaluated` (false before a run: the scenario's setting), a `label` (`callback 10 at 24.967 s`) and every change of the run (`changes`, paged). `help` with `topic` `animation-mode` lists every Animation mode key (with where it works), the pointer actions and the legend's edges, Timing marks, states and families.

`scene_tree` rows list the first eight animations affecting an object (`animationUses`, with `animationUseCount` and `animationUsesTruncated`); `scene_tree` `animationUses` with the row (or `node`) pages every one of them, as the object card (**Show n more**) and the glyph flyout list them (one per definition and binding, so `animationUseCount` and `total` are the card's count), each with its `definition` for `animation_mode open`. `scene_inspect` adds `animations` for the inspected object: the card's first eight (`affecting`, with `total`) and, in Animation mode, `eventsNaming` (the opened definition's rows that name it).

`animation_timing` is the Timing view, in seconds, with the GUI's identities (`starts`, `group:<key>`, `lane:<group>:<sequence index>`, mark ids from `marks`); it needs Animation mode on a bound definition. `read` reports the presentation (`view` `lanes` or `log`, `visibleRange`, `labelWidth`, `thresholds`), the `selection` (lane, mark, event), the time and range, whether the run is evaluated or stale (`message` is the empty state's text), and counts (lanes, marks, Log rows, `retained` and `discarded` occurrences, `phasesDropped`: older sequence state changes a very long run discarded, so bands before the oldest kept one may be missing; `runExtent`). `lanes` pages the shown rows by at most 100: the Starts lane (`starts`: id, entry, seconds, label, `primary`, `prerequisitesIgnored` where the scenario's rule let an unmet start run, `refused` with its reason), instance groups (a start's binding, then the instances its calls reached nested under their caller and grouped by definition as the graph groups them: `members`, `instances`, `started`, `ended`, the binding `state`, `expanded`, `laneCount`) and sequence lanes (`sequences` per member, `run` at the playhead: `running`, `complete`, `waitingRelease`, `waitingThreshold`, `blocked`, `paused`, `stopped`, `notStarted`, `unavailable`). `marks` pages one `lane`'s marks and bands by time (100 at most): marks have `kind` `executed`, `interval`, `running`, `condition` (`value`, `forced`), `skipped` (`count`), `excluded`, `duplicate`, `blocked`, `release` (`targetLane`), `loop`, `refused` or `unresolved`, the event, instance, occurrence, family, the Log's `result`, and, for an event with a start threshold whose anchor occurred, its `bracket` (`clock` animation, sequence or previous; `threshold`, `anchor`, `end`, `label`, `gap`, `editable`); bands (`band: true`, with `open` true while the state still lasts at the playhead, the GUI's `→ now`, and false once it ended, `– end`, as the last band of an instance that ended always does) are `waitingRelease` (released by … or no releaser left), `waitingThreshold` (anim ≥ 23 s → 43.000 s), `paused`, `blocked`, `stopped`, `complete`, `unavailable` and a group's `binding` state. `log` pages the Log (newest last; each row's lane and mark). `options` takes `changes`: `thresholds`, `visibleRange` ([start, end], independent of the playback range), `fit` (`range`, `run`, `selection`), `labelWidth` (160–420 DIP) and `view`. `select` with a `lane` selects it as a click does (a sequence lane: the Inspector, the graph's node and the 3D outlines; a group: its binding; the Starts lane: the Scenario tab); without one it clears the selection. `occurrence` with `lane` and `mark` selects the mark's event (the Inspector's event card, that occurrence highlighted) and seeks to the tick that shows it (`result.playhead`). `expand` with a group `lane` and `expanded` opens or closes it (presentation only). `threshold` with an `event` and `seconds` proposes that event's start threshold in its own clock (a clock the open draft already changed is kept) through the card's source draft, exactly as the bracket drag does (`result.draft`; apply or cancel with `source_animation`). Starts move with `animation_scenario starts` (the Starts lane's drag and Remove start); the playhead moves with `animation_transport`.

`animation_transport` steps one 1/60 s tick (`previous`, `next`) and reads back seconds (`time` in its state, `animationTime` in `state`); `seek` shows the tick at or before `seconds`; `start` goes to the playback range's start; `duration` estimates how long the scenario runs without moving the playhead, on the map as stored and also with a source draft open (Open-ended when a sequence waits forever; a deterministic work limit bounds it, the same on any machine; `TimedOut` marks a result the 15 s wall-clock backstop stopped on a machine too busy for it, kept as it is and never measured again by itself: its explanation says it depends on the machine). `animation_options` takes the transport's `speed` (0.25, 0.5, 1, 2, as the Speed list), `volume`, `mute`, `replay`, `followCamera`, `effects` and the playback range `playbackRange` [start, end] (as the range flyout); `speed`, `volume`, `mute`, `followCamera` and `replay` also apply while a source draft is open (they never change the run), the others refuse with the draft open; every key and value is checked before any applies; in a source map `range` and `autoRange` are refused (`moved`) with a pointer to `playbackRange`, the Timing view's keys to `animation_timing options` and the scenario's to `animation_scenario`, before any key applies; the playback range starts at 0–30 seconds and runtime navigation is bounded to 0–3,600 seconds. `animation_runtime` also exposes `instances`, scoped `conditions` and `prerequisites` (each start attempt's activation prerequisites: `met`, `refused`, or `ignored` by the scenario's rule, with every check; evidence only) for source runs.

Call paths are canonical: a path identifies a particular callsite lineage, including repeated or cyclic references (`animation_scenario read` lists them). `animation_scenario include` enables a path; children start excluded, so opening an animation such as `start_north` does not run its child chain. An excluded waited call blocks its calling sequence; an included unresolved call reports unavailable and advances; an included duplicate retains the runtime's no-new-instance behavior.

`animation_paths` is the Paths chip. `analyze` with a definition explicitly evaluates guides in independent silent state for the opened binding (or `entry`) using the current scenario and inclusion policy. It does not pin, seek or stop the main run, change the camera, or switch the panel. `show` only displays compatible cached guides; `hide` retains the cache, `clear` releases it and `frame` frames the shown guides; `state` returns the chip (`state`: `not evaluated`, `evaluating`, `shown`, `hidden`, `out of date`, `partial`; `status`; the `rangeTests` and `contacts` toggles); `markers` pages the evaluated contacts (`kind` `contact`, where a moving node touched the ground) and impact sounds (`impact`, with its `sound`), `events` the analysis's dispatch traces. Without a definition, `overlay` sets Show range tests (`rangeTests`) and Contacts and impacts (`contacts`), and `ranges` lists every range condition and range gate of the opened animation and its expanded calls: `kind` (`condition`, `gate`), `where`, `attach` and its `center`, `radius`, the `player` at the playhead, `distance`, `inside`, `outcome` and whether the view draws it (`drawn`; on the m4 bridge the flare test reads distance 2,010, outside 64, false). Drop windows (without a definition, with their `snapshot`): `show` analyzes the opened flight in a source map (Animation mode on a definition with recognised flight-to-callback-911 calls), `analyze` an exact `entry`, `select`, `begin`, `set`, `confirm` (one undo step) and `cancel` are the Inspector's list, Move along path, start box and Apply / Revert, and `frame` frames the flight path; `preview_state.parachute` adds the admitted `callsites`, the `policy` (the analysis follows the scenario's condition switches) and `moving` (Move along path in progress). Selecting or expanding an animation never evaluates paths. Keyframes are inspected as read-only compiled samples; their shapes are not edited in this version.

Every animation time is in seconds; no MCP tool takes or reports frame numbers. Start thresholds are edited with `source_animation`: `set` with `startClock` (`animation`, `sequence`, `previous`) and `startSeconds` for `record` (else the selected event), or with the START_TIME field's values, writes the same shared draft as the Inspector's Start threshold and Timing's bracket drag (`animation_timing threshold`). `source_animation context` takes a source `record` and optional `scriptTime`, returning read-only excerpts with filenames, line numbers and truncation indicators. Viewing never snaps authored times; negative and off-grid thresholds are preserved, and runtime seek limits do not constrain authored time. Starting a draft detaches playback and makes prior drop analysis stale. Apply accepts one project-overlay history step; `save_document` writes sources, and export remains explicit. The separate VTOL analysis (`animation_paths` without a definition) has its own purpose and snapshot and admits only the recognized release calls. Moving a certified drop window uses its checked `set`/`confirm` pipeline and changes only the CALL start offset, preserving the STOP duration. Generic CALL/STOP timing editing remains available, but can change or remove the window relationship; analyze again before a verified window move.

Additional starts have canonical path prefix `/@<guid:N>`. Included call paths and condition `instancePath` use the full canonical paths, keeping repeated bindings distinct. Removing a start removes its policy paths. Timing's marks keep the run's actual shared-clock times. Calls remain excluded by default and only launch when their authored sequence reaches them. All scheduled animations share world state, collision, audio and analysis.

A compiled animation (an `anim.zbd` record selected in a compiled root) is read only and uses the same tools on its isolated preview, with the same identities: `animation_mode state` reports `compiled` and `readOnly`, the `opened` entry and the `layout` (`layout` sets `view`, `rightTab` `inspector` or `scenario`, `panelHeight`, `diagnostics` and `diagnosticsHeight`; `tree` and the other actions are refused, `unsupported`, since selecting another record in Assets opens it). `animation_graph` reads the graph with compiled numbering (`sequence 6 · move_piece3`; the frame label ends in `· read only`), and `select`, `expand` (with `member`) and `inspector` work as in a map; its `inspector` card has value items (`type` `value`: a read-only field with `label`, `value`, `mono`) and adds `stored`, `bytes`, `references` and `related` sections; there are no `field` items and no footer. `animation_timing` reads lanes, marks and the Log; `threshold` is refused (`read_only`). `animation_scenario` is the compiled Scenario tab: one start (the animation at 0 s) and every call included (`include` with `included: false` leaves a path and what lies below it out; `excludeAll` and `includeAll`), `conditions`, `rules`, `reset`, `pick`, and `inputs` with `player`, `seed`, `effectsDetail`, `phase`, `height`, `beamOrigin`, `world` (a `gamez.zbd` path; `""` goes back to the automatic world), `root` (a world node index; `null` clears the override, as **Clear override**) and `range` ([0, end] in seconds, or `[]` for Auto); `read` adds `inputs.world` (`shown`, `chosen`), `inputs.root` (`bound`, `overridden`, `node`) and `inputs.rangeDescription`. `starts` and `fitRange` are refused (`unsupported`): the preview plays its one animation from 0 s. The whole request is checked before any of it applies (`layout` with `tree`, `inputs` with a node the scene does not have, refuse everything). The scenario is never saved: its inputs, rules and world are kept for the file's other animations, while call exclusions, condition switches, a `root` override and a custom `range` belong to the animation shown (another starts with every call, no override and Auto); `reset` returns all of them, the world included, to the defaults, and `read`'s `customized` counts them all. `workspace_view` `tools` shows or hides its Diagnostics strip (`compiledAnimation.diagnostics` reads it; `toolsHeight` sizes it), which lists the preview's own problems (the run's issues, a failed preparation, audio), errors and warnings first and at most 500, then a row saying how many more `animation_runtime problems` lists, beside the file's; a note says how many distinct notes the run left out after 2,000. `animation_options` keeps only the view's options (`lod`, `difficulty`, `faceOrientation`, `map`, `grid`, `height`, `collision`, `horizon`, `effects`, `followCamera`) and the transport's (`speed`, `replay`, `mute`, `volume`), every key and value checked before any applies, as in a map; `seed`, `condition`, `activationOrigin`, `activationTarget`, `range`, `autoRange`, `playbackRange` (its range is `animation_scenario inputs range`), `worldPath`, `root` and `phase` moved to `animation_scenario`, and `traceRange`, `fitTrace`, `followLog` and `problemFilter` to `animation_timing` and `animation_runtime notices`; they are refused (`moved`) with that pointer. `animation_records` `bytes` returns up to 4,096 of the record's original source bytes (`entry`, optional `sequence` or `event`, `offset`, `length`; `label` is `original source bytes`, `recordLength` and `nextOffset` page the rest). `animation_select` selects the sequence's node or the event's row in the graph, as `animation_graph select`. `properties_open` refuses an animation (`unsupported`): its Inspector is the card. `preview_state.animation.camera` names the animation's camera at the playhead (`name`, `node`, `fieldOfView`; null without one), as **Follow camera**'s tooltip does. A compiled Whole world's Drop windows chip is `animation_paths` without a definition (`show` and `analyze` show every window's markers; `select`, `begin`, `set` and `confirm` are refused, `read_only`), and the player its analysis measures from is `animation_scenario inputs {player}`; there `animation_options` refuses `activationTarget` (`moved`) and any other key (`unsupported`): a Whole world has no animation preview.
