# Animation editing and preview

zStudio edits existing entries in version-28 animation packs. It preserves original data and writes a separate, verified ZBD through **Save As**. It does not create or duplicate whole animation entries or edit other ZBD families.

## Using the editor

Open the dataset root, then a mission's `anim.zbd`. Select an animation in Assets. Its matching GameZ scene, mission textures, effect templates from `effects.zrd`, and sample aliases from `sounds.zrd` resolve automatically. **GameZ…** chooses a scene when opening an exported copy elsewhere. **Bind…** changes the preview's root node when a name has multiple matches. These choices affect preview only.

For the opening cinematic, select `m1/anim.zbd` → `start_single_player`, enable **Map** and **Follow camera**, then play. Its child `m1_start_animation` animates `camera1`: the view descends toward the docks while turning. Follow camera also applies immediately to a paused pose; turning it off leaves the viewport available for free navigation. **Status** identifies the current camera by name and source index and shows horizontal FOV in degrees. Serialized camera FOV fields remain in radians in the Event editor.

The preview starts isolated. Beside the **LOD** dropdown, **Map** adds the map around it, **Horizon** shows the camera-following backdrop, **Follow camera** follows the animated camera position and orientation, including child animation tracks, and **Effects** enables approximate light/fog tint and screen overlays. Undo, Redo and Save As are accessible icon buttons on this same row, with tooltips and their existing shortcuts. The row scrolls horizontally when the workspace is narrow. Right drag rotates; middle drag pans; the wheel approaches the surface under the pointer. **Frame view** frames the current animated geometry. Texture colors are otherwise neutral.

**Grid** starts checked and shows a line grid on the world XZ plane at **Y=0**. It also enables flat-ground collision for procedural debris; unchecking disables both. Contact uses the lowest transformed mesh vertex, including spin, scale and morphing, with an envelope across authored LOD variants so the picker never changes physics. Landed debris remains above the plane through subsequent shrink/sink stages. The retail impact damping, waiting-sequence releases and impact samples are simulated; impact samples preload with other audio. `vtol_destruction1` now releases its five trail-stop sequences on contact and has a finite range of about 25.9 seconds in both supplied datasets. This is a preview approximation: it does not sample mission terrain or provide object/camera collision. Authored positioning and saved data remain unchanged.

**Height**, immediately beside Grid, defaults to **0** and adds an upward world-Y offset to the selected animation, in game units (0–100000). For `vtol_destruction1`, try **40** to start above the floor and let the debris fall onto it. Valid numbers apply as you type, without Enter or leaving the field. The field has no clear/X button. Empty, incomplete or invalid text keeps the last valid preview height while you edit; Enter, Escape or leaving the field restores its numeric display without an error. Rapid valid changes cancel superseded reconstruction work so the newest value wins. Changing height reconstructs the current playhead, retains custom range/playback and recalculates the finite duration. The offset includes nested animations, effects, lights, camera poses and sound positions; the map and grid remain in place. It is preview-only and is never written by Save As. Free camera position is retained; **Frame view** brings raised geometry back into view when needed.

The grid remains visible in top-down views and fades only in the distance, with antialiased lines. Its visibility is independent of the tightly fitted scene near/far planes. It neither writes depth nor participates in framing/picking; opaque geometry still covers it.

Toggling Grid silently reconstructs the current playhead with the same seed and settings, recalculates automatic duration, and restores playback when appropriate. Custom ranges are retained. If the new automatic range is shorter than the playhead, the displayed view extends to retain that position; **Auto** restores the calculated range. Scene/horizon refreshes preserve the checkbox.

The resizable **Details** panel on the right contains collapsible **Preview options**, **Sequences**, **Events**, **Status**, and **Event trace** sections. Sequences and Events initially open; the other sections initially close. Drag the bottom grip of any open section to resize it vertically. When the grip has keyboard focus, Up/Down adjusts its height in small steps; Shift uses larger steps. Lists and text scroll independently within their section; reaching a boundary passes the wheel to the outer panel. Preferred width, section heights and expansion choices are retained across asset selections and app sessions. **View → Reset layout** restores the defaults. **Preview options** contains **GameZ…**, **Bind…**, seed, condition override, and custom preview range/Auto.

Events show their name above the start clock and threshold. The header reads **Events**; the first line of its body identifies the selected sequence, its ordinal and event count, including the separate Reset / stop phase. Authored order remains authoritative. Select an event to use the existing **Properties → Event** inspector. **Status** holds current sequence states and preview notes. **Event trace** contains only recent dispatch text. The **Dispatched events** graphic sits below the viewport and transport, with its **Fit trace** action alongside the title. Collapsing Event trace or hiding Details leaves the graphic visible.

When neighbouring panes leave too little width for both columns, Details closes automatically. Open **Details** to use the preview area temporarily for the panel, then **Back to preview** to return. Transport and the dispatch graphic remain accessible below it, and the same animation, camera and selection are retained. Short windows use a compact graphic; its seek/zoom instructions remain in the tooltip. Widening the workspace restores the side-by-side layout. The toolbar scrolls horizontally when needed, including keyboard focus reveal.

The toolbar defaults to **LOD 0 · Highest detail**. Lower-detail ranks select each object's own authored distance band and clamp when an object has fewer variants. Switching LOD preserves the simulation time and inactive variants' state. It also changes the optional mission level. Automatic camera-distance transitions and LOD fading remain outside the preview.

Sprite material cycles resolve from saved GameZ data, the mission's `support/tex_fx*.gw` setup in `interp.zbd`, and shared materials initialized by `effects.zrd`. `fire_bft` uses the shared `fire1` cycle: 12 images at 10 fps, looping. Texture setup interprets bounded `source` includes, node/subnode selection and `CycleTextureSet*` commands; it does not execute arbitrary gameplay scripts or substitute game-state variables. Cycle and effect frames preload before playback. Seek and variant events select frames deterministically, including loops, stopped cycles and reverse speeds. Alpha maps, transparent zero-color keys and material opacity are preserved in the preview; transparent geometry blends without writing depth.

Select an animation in Assets and press **Space** to play or pause without moving focus to the viewport. A press during loading queues playback for that selection; a second press cancels it. Changing the selection cancels queued playback. Text boxes, dropdowns, buttons, checkboxes and sliders retain their normal Space behavior; modifiers and key repeat do not toggle playback.

The **Play/Pause**, **Stop**, **Previous frame (−1f)** and **Next frame (+1f)** icons share one row with the seek bar. The readout shows the current and ending 60 Hz frame boundaries: frame 0 is the initial pose, and frame 60 is one elapsed second. At narrow widths, the readout moves below the bar while all four icons remain beside it. Frame steps pause playback and clamp to the displayed range. Stop returns to frame 0 of the selected phase; Play at the endpoint restarts. Speed, **Replay preview**, Mute and volume sit below the transport. Replay preview repeats the displayed range independently of authored loop events.

Finite preview ranges are calculated automatically using an independent simulation with the current phase, seed, conditions, ground collision, height and activation points. Concurrent sequences, nested animations, thresholds, timed motion, finite loops, cleanup, effects and one-shot sound tails contribute to the range. A one-second timed animation fills a 60-frame bar. Edits, undo/redo and preview changes recalculate the range. Duration analysis uses a snapshot of editable data and does not advance the visible player or emit sound.

Some programs loop, wait for release, or depend on collision/gameplay. Their range is explicitly labeled **Looping**, **Open-ended**, or **Partial**, rather than presented as a known total duration. The suggested window is at least five seconds and includes observed finite tails; bounded analysis is limited to one hour of simulation and two seconds of work. Reaching a preview limit pauses and reports that the range can be extended. **Preview options → Preview range (s)** overrides the range, rounded up to a 60 Hz frame; **Auto** restores the calculated/suggested range. Custom ranges remain in effect while editing the selected preview.

The time slider and blue event trace scrub silently and pause playback. **Ctrl+wheel** over the trace changes only its displayed scale; **Fit trace** beside the graph restores the full range. Ordinary wheel movement over the right-side sections scrolls their content or the details panel. **Seed** fixes randomized events. **Engine conditions / Force true / Force false** lets you inspect conditional paths. Preview-only origin and target coordinates are in **Properties → Preview**; absent gameplay inputs default to the root and a target ten units along Z.

**Mute** starts unchecked; volume starts at 50%. Sounds prepare automatically while the animation opens, including procedural impact samples and sounds in child animations, conditional branches and cleanup. The loading message shows **Preparing audio…** during preparation; Space pressed while loading still queues playback. Edits and undo/redo refresh sound dependencies before playback resumes.

Press Play to hear resolved WAV samples and looped sound nodes. Pause, stop, seek, document switching, and closing release preview voices. Unmuting and resuming continue sounds that are still active at the current animation time. Scrubbing stays silent; Play after seeking resumes active sounds without replaying finished sounds. A sound that finishes during slow playback does not restart repeatedly. Audio-device failures show a diagnostic and check Mute; uncheck it to retry asynchronously. An unavailable sample is reported in Status without disabling other sounds. This is a nonspatial audio approximation and does not reproduce the original sound engine's attenuation, pitch or mixing.

The preview decodes only the selected animation's reachable sounds into shared PCM buffers on a background worker. One shared-mode WASAPI output mixes up to 32 independent voices, with a requested 50 ms buffer. It stays ready through pause/mute/stop, so sound events neither parse WAVs nor initialize or dispose devices on the UI thread. Looping wraps inside the sample buffer. Closing the preview cancels preparation and releases its output asynchronously; obsolete commands cannot start sound in the next preview.

The **Runtime / Reset / stop** selector separates the normal runtime sequences from the primary cleanup sequence. The sequence list shows both so either can be edited. Runtime sequences run concurrently. The event timeline shows actual dispatches accumulated by the simulation, rather than interpreting every threshold as an absolute timestamp. Select events in the table and edit their typed fields in **Properties → Event**. Press Enter or leave a field to apply it; invalid numbers, out-of-range references and invalid keyframe intervals are rejected.

- Add, duplicate, delete and reorder events using the toolbar above the event list.
- Add, duplicate or delete runtime sequences using the sequence-list buttons. Rename, change the initial/reset state, reorder sequences and edit cleanup delay under **Properties → Sequence**.
- Expand a transform-keyframe segment to edit its interval, position/rotation/scale channels, bases and rates. Segments can be added, copied, deleted or reordered.
- Target menus retain reference indices and display their names. **References** can retarget names in verified existing tables; reserved slots and unverified fields are read-only.
- **Undo / Redo** or Ctrl+Z / Ctrl+Y restores document edits, with up to 128 entry snapshots. Text fields retain normal text undo while focused.
- **Save As… / Ctrl+S** writes a new animation pack outside the selected source tree. It reparses and verifies the serialized bytes and the written file before an atomic move. Existing files are not overwritten. The working tab keeps its original mission context; subsequent saves also use Save As. Reload reads the original source again.
- A `*` on the tab indicates unsaved changes. Closing, reloading, changing roots or exiting with edits offers Save As, Discard and Cancel.

Unknown event types and malformed event streams remain available as preserved bytes and diagnostics. Unknown fields, pointer-shaped values and runtime caches are not interpreted as process pointers. Structural sequence operations are blocked if unknown records might hide references. JSON exports use the edited event model, but remain inspection exports rather than an import schema.

## Engine evidence and corrected meanings

Primary evidence is the external `Recoil.bndb` database and RecoilRebuild `src/GameZRecoil/` reconstruction, particularly `zEffect/zeff_anim_run.c`, `zeff_anim_init.c`, `zeff_anim_save.c`, `zeff.h`, `zClass/Camera.c`, `zClass/Object3d.c`, `zModel/gmod_const.c`, and `zSound/zsnd_init.cpp`. These private research references are not distributed or needed to build. No external source or database was modified.

Camera pose evidence: retail `CZNode::gwNodeBuildNodeToAncestorMatrix` (`0x449480`, camera branch `0x4496AE`) uses +0x20 as Euler angles and +0x14 as translation; flag 2 uses the cached matrix. `CZCamera::BuildWorldTransform` (`0x44ABF0`) takes the eye from the composed world translation and forward from negative Z. The historically named `gwCameraSetPosition` (`0x449EA0`) and `gwCameraSetTarget` (`0x44A0F0`) are therefore misleading for animation channels. Keyframes (`0x45AE90`) write position and quaternion-derived rotation through those setters. Preview uses the complete world pose and converts stored/event FOV radians to degrees; no authored camera bytes are rewritten.

| Behavior | Verified evidence and editor interpretation |
| --- | --- |
| Event scheduling | `RunSequenceEvents` at `0x45CC00`: start mode 1 uses entry elapsed time; 2 uses sequence elapsed time; 3 uses elapsed time since the preceding event. Timed handlers pass their unused frame slice to following events. |
| Primary sequence | Used by cleanup/stop callbacks; it does not start alongside runtime sequences. State 3 waits for release and resets to waiting on completion. |
| Sequence control | `0x16` releases a waiting sequence; `0x17` stops a sequence. Historical handler names were reversed. Reordering/renaming also repairs the verified procedural collision-release reference at bytes 208/240. |
| Named animation control | `0x19` requests stop, `0x1A` invokes reset/cleanup, `0x1B` requests finish so loops can exit. |
| Transform samples | Type `0x0C` stores a 12-byte interval header and 28 bytes per enabled channel. XYZ channels use a base and rate. Rotation stores WXYZ plus a rotation-vector rate; retail `0x475B80` uses `cos(length)` / `sin(length)`, so the vector length is a half-angle. |
| Procedural launch and gravity | Direct Binary Ninja inspection of `0x459E70` corrects the reconstruction's swapped temporaries: random ranges at 32/40/48/56 are yaw/pitch/speed/radial acceleration, in that draw order. `0x474580` rotates the **−Z** forward direction. Motion flag `1` adds the signed gravity value at byte 24; flag `0x2000` applies the transposed world basis. The inspector labels and preview implement those meanings. Terrain collision and inherited launch velocity remain unavailable. |
| Opacity | Types `0x0D` / `0x0E` control opacity and its override state. Despite its name, `gwObject3DSetLitFlag` toggles bit 2, which `RenderTraverse` at `0x44B300` uses to push an alpha override for the subtree. Stored opacity without that flag is ignored. The nearest active ancestor override is inherited. |
| Texture frame | Type `0x11` calls `SetCurrentVariant` at `0x4842B0`, selecting a texture-cycle frame, not a linked material variant. |
| Morph | Engine geometry uses base vertex plus morph delta times blend scale. |
| Effect templates | Name, model, MAPS, SPEED and LOOPING come from `effects.zrd`. The preview implements the observed one-second effect lifecycle and texture sequence with a camera-facing approximation. |
| Audio | `sounds.zrd` maps sample names to WAV resources; `LOOPED` controls looping. The highest available decoded sample quality is selected. |

The engine's deterministic random table uses the MSVC linear-congruential sequence. Playback state, child instances, sound state, trace and random cursor are captured in bounded seek checkpoints. Parsed event bytes never double as runtime scratch storage.

## Preview coverage and limits

The event catalog covers all 39 event IDs present in the supplied packs. Supported preview paths include position/rotation/scale, transform keyframes, opacity inheritance, activation, parenting, texture cycles, morph deltas, nested animations, effect templates, samples and sound nodes, loops and sequence control. Lights, fog, camera parameters, beam geometry, procedural physics and screen effects have explicit approximation labels. Game callbacks and localized messages are trace-only.

The preview is not the original game runtime. Mission-terrain and object-to-object collision, gameplay activation prerequisites, inherited launch velocity, original facade projection, exact lighting and depth sorting of translucent particles are not reproduced. Camera preview applies pose and horizontal FOV; the other serialized camera parameters remain editable but are not mapped to the viewport. Fog is an approximate tint on animated geometry; it is not the retail altitude-fog implementation. Screen waves are shown as a ring instead of distorting the render target. Sound is nonspatial. Manual activation bypasses prerequisites and does not run mission scripts.

No-op round-trip equality and successful previews establish preservation and editor behavior; edited files have not been loaded in the original executable. Long-running gameplay interactions and physical input/file-dialog workflows still benefit from hands-on testing.

See [testing commands](testing.md) and [actual verification results](status.md).

## Mission starting layout and horizon

Both Whole world and animation previews recover a single-player starting layout from mission resources. The **Easy / Medium / Hard** dropdown immediately after **Map** selects the animation's mission layout; Whole world has the same selector beside Horizon. The selection is shared across documents and remembered across launches, defaulting to Medium. It stays enabled when Map is hidden because animation bindings still use that mission context.

Easy selects `aiv_easy.zrd` and `vehicle_easy.zrd`, Medium selects `aiv.zrd` and `vehicle.zrd`, and Hard selects `aiv_hard.zrd` and `vehicle_hard.zrd`. Each absent variant falls back independently to its default filename. Empty valid variants remain empty; malformed selected resources produce an error and retain the last valid preview. Status and world inspection identify the actual resources used. Layouts are never merged. In both supplied datasets, m1 has 80/84/87 AIV placements for Easy/Medium/Hard, plus three startup-animation actors. m7–m13 have only the default AIV list.

Turrets are initialized from `ai.zrd` for each matching scene instance. The engine's numeric wildcard rules and explicit/named/default destruction-animation precedence select the primary cleanup sequence. This restores the healthy starting state without preventing the selected destruction animation from displaying destroyed parts later. Firing effects and fire-point helpers are hidden at initialization.

Pickups load from `puppies_easy.zrd`, `puppies.zrd` or `puppies_hard.zrd`, with the same missing-only fallback rule. Their logical types use the retail 40-type catalog to find `puNNN` templates. Each placement keeps its authored position, rotation and template scale; collision-only `bvol` geometry is hidden. All authored pickups are shown, including weapons that an in-game player might already own. m1 has 64 pickups on every difficulty; m2 has 56/53/56 for Easy/Medium/Hard. Amount and respawn delay are retained as metadata, with no collection, respawning or idle-movement simulation.

Pickup bindings use archive/resource/record identity and template provenance. Switching to a different pickup resource clears a binding rather than reusing a generated name or clone index. A fallback to the same resource retains a valid binding. Invalid individual placements have resource/record diagnostics and do not discard valid siblings.

Changing difficulty preserves the camera, playhead, playback intent, custom range, LOD, grid/height and event selection. A followed camera is reapplied at the reconstructed playhead. Audio dependencies and the warm output are reused. Clone node indices can change between layouts, so manual root bindings and world selections are remapped by source provenance and unambiguous actor identity; absent or ambiguous instances clear the binding. No edit or undo entry is created.

Surrounding actors stay stationary while the selected animation and its children play. Vehicle positions and headings come from AIV records; initial scripted poses and visibility come from load/startup animation setup. The baseline applies animation load initialization, turret resets, vehicles, pickups and then the immediate NEW_GAME_START events, in that order. Initialization does not play audio or advance the visible player. Bind lists recovered actor instances and positions. Edits and undo/redo rebuild the frozen baseline.

Evidence boundary: retail `zVehicle::SelectZrdByDifficulty` at 0x41FE50 selects the vehicle variants and falls back to `vehicle.zrd`, while the inspected `Player::GetAivZrdPath` at 0x41FE40 returns `aiv.zrd`. Selecting the supplied alternate AIV layouts is an explicit Studio preview capability. Retail turret initialization (0x437AC0 / 0x4367A0 / 0x45D6B0), pickup difficulty selection (0x41DDF0), spawn transforms (0x41DA20) and the type catalog (0x4DB6E8) were inspected in Binary Ninja and the reconstruction. The preview does not establish full game-runtime parity: AI, combat, inventory filtering, terrain-dependent pickup runtime behavior and collection/respawning remain outside the starting layout.

Some actors are only positioned by a later script. The world preview hides those unplaced actors with a diagnostic until activated; it does not scatter them at the origin. Explicit individual inspection of an effect/destruction may use a labeled stored pose. No generic offset is applied to static terrain or ordinary zero transforms. Source bytes and asset properties remain unchanged.

Horizon beside LOD controls the camera-following background, including world-bound animation poses. It follows the camera while paused and while Follow camera is active, and does not affect Frame view or depth precision. Whole world retains its own Horizon checkbox.

For m1/call_flufvtol the authored delay is 100 seconds. Seeking past that point launches flufvtol_flying on vtol2's authored path. World and child animations share the actor, so a second copy is not left at the origin. Other actors retain their recovered mission-start poses. AI, terrain settling/tilt, saved-game state and mission progression are not simulated.


## Flat-ground collision evidence (0.2.11)

Retail `zEffect::HandleNodeAnimEvent` at `0x459E70`, especially `0x45A4DB–0x45A6C0`, gates both waiting-sequence release (flag `0x800`, name/index at bytes 208/240) and impact audio (flag `0x1000`, positive sample index at byte 242) on contact. Velocity is damped by `0.199999988f` unless its squared magnitude is below squared acceleration, which completes motion. Gain uses post-damping speed and the threshold at byte 244, falling back to gravity at byte 24 times 10 for a negative threshold. The reconstruction incorrectly leaves the sound branch outside the contact gate. These semantics were verified read-only against retail assembly; source ZBD, reconstruction and BNDB were not modified.

The desktop substitutes mesh-based support at Y=0 for the engine's origin-based terrain ray pick and keeps landed mesh geometry above the plane during shrink/sink. Initial overlap correction alone emits no impact. Missing geometry uses an explicitly diagnosed origin fallback. Contact and support state live only in the runtime player and its seek checkpoints. The original 0.2.11 grid used the [Helix 3.1.2 plane-grid pass](https://github.com/helix-toolkit/helix-toolkit/blob/v3.1.2/Source/HelixToolkit.SharpDX/ShaderManager/DefaultEffectsManager.cs), which blends and tests depth without depth writes; the grid is excluded from scene bounds and picking.

In 0.2.12 the plane model uses a custom embedded shader/pass. The [stock pixel shader](https://github.com/helix-toolkit/helix-toolkit/blob/v3.1.2/Source/HelixToolkit.Native.ShaderBuilder/PS/psPlaneGrid.hlsl) couples opacity to the scene far plane, making the reference floor vanish around small isolated previews. The replacement uses world-space extent/fading and pixel derivatives for antialiased lines. Its pass alone disables depth clipping, clamps fragment depth and tests less-or-equal without writing depth. Scene camera clipping stays unchanged. Height keeps authored simulation coordinates intact and applies one world-Y presentation offset, including the ground-support measurement; this avoids doubled child offsets and authored keyframes erasing the selected height.
