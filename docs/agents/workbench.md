# Workbench GUI contract

Rules for the WPF workbench. User-facing descriptions: [map editor](../map-editor.md), [compiled files](../compiled-files.md), [3D navigation](../3d-navigation.md).

## Welcome screen

- Before a root opens show the welcome screen; hide workspace panes, actions and search without changing saved layout preferences.
- One card, Work with source project. Initialize: dialog with retail ZBD folder and project folder fields, Browse buttons, Initialize and open enabled only when both are given, progress and refusals shown in the dialog, Cancel stops the work. Open: only a folder holding `data` and `gamegen`.
- File → Open workspace… (Ctrl+O), Recent folders, a dropped folder and a command-line folder open only a source project and refuse any other folder with what is wrong with it; files are refused.
- Recent-folder paths render literally: underscores are never menu access keys.

## Workbench layout

- Fluent workbench, always compact; no density setting (owner decision).
- Compiled explorer (MCP-opened compiled roots; in a source project the Navigator and Inspector are collapsed, Reset layout is hidden and the [source map editor](#source-map-editor) applies): one Navigator (Files, Assets, Search, Document scene), the central preview, the [compiled animation preview](#compiled-animation-preview)'s panel and Inspector | Scenario pane for an animation, bottom tools (Problems, Related, Bytes), and a separate [Properties window](#properties-window) for other records.
- Keep both side panes visible when the viewport has room. Hide the whole right pane for non-animation viewers.
- Preferred pane dimensions, groups and tabs persist; automatic narrow collapse never overwrites them.
- Resizing, fullscreen and theme changes never replace or dispose the editor or commit drafts.
- Grouped native ToolBar overflow.
- Problems keeps the emitter's severity and source context and separates file/operation issues from preview, resource and support notices.
- Bytes shows original-source bytes, bounded to 4096, labelled as distinct from properties and runtime memory.
- No bottom Cancel button and no manual indexing cancellation (owner decision). Automatic cancellation on workspace or document replacement and on shutdown stays.

## Update check

- Owner request 2026-10-23: the status bar shows **Update available** (with the version) directly left of Preview notices when GitHub's latest published release (`releases/latest`: no drafts or prereleases) is newer than the build: SemVer of the tag against the informational version before `+`, so a prerelease build sees its release as newer. The item is docked right beside the source map's status group, so it also shows without a source map (welcome screen, compiled explorer). A click opens the release page, only one under `https://github.com/Vorta/zStudio/releases/` (anything else opens `…/releases/latest`).
- Help → **Check for updates automatically** (saved, default on): one check after the window shows (application startup, never tests), at most once a day: every check that asks GitHub saves its time (`UpdateAttemptedUtc`), so a failed, refused or rate-limited one waits a day too; the last successful check and its release are saved and shown until the next. The request runs on the thread pool (the first one can block in proxy discovery, which its timeout cannot interrupt). Silent: checking, an up-to-date build and any failure (offline, proxy, TLS, 4xx/5xx, rate limit, bad JSON, 10 s timeout) show nothing. Turned off, nothing shows until an explicit check, whose result (including a failure: `unknown` with its reason) then shows. Running 0.9.6 or older on the same profile drops the setting (older versions drop unknown keys), so automatic checks turn back on.
- Help → **Check for updates** is an explicit request, also with automatic checks off: the item shows "Checking for updates…", then Update available, or for 8 s "zStudio is up to date" or "Couldn't check for updates" (the reason in its tooltip; a click dismisses it). Closing cancels a running check.
- A private test profile never contacts GitHub; tests give the window a checker over a fake handler. MCP: `update_check` (state, check, automatic) and `state`'s `update`; MCP returns the release page URL and opens nothing.

## Navigator

- Files owns open-document navigation: marks open, active and dirty files; row close buttons keep the save/discard guards. Opening a file from Files switches to Assets. No document tabs.
- The search input belongs to Search.
- Hide Assets when no file is open; hide Document scene unless the active document has scene roots. Before hiding the selected tab move to Assets if a document remains, otherwise to Files. Document changes keep an existing Files or Search selection.
- Source selection uses stable entry, sequence and event identities. Runtime markers and asset export selection stay separate from it.
- Document scene (compiled explorer): the active 3D preview's hierarchy (an animation's stable bound scene; else the selected file's stored nodes). Shared references appear under each parent with a shared label; **Unlinked nodes** keeps disconnected roots and cyclic components; invalid references, cycles and the 256-level display limit are explicit leaves. Selecting a row inspects it and sets the Frame-selected target; it never moves the camera or opens or retargets Properties. Expansion and selection persist through presentation changes and compatible refreshes for the document's lifetime, matching mission objects by provenance, never by clone index. Presentation-only expansion, collapse and reveal never commit pending input.

## Properties window

- One reusable, owned, modeless window for every viewer, opened through a row context menu or Alt+Enter (in a source map Alt+Enter focuses the docked card — a source object's first control, or a placement's first editable coordinate while it is shown, else the player tank's chosen master type (see below) or the keyboard stays — also for a pickup, vehicle or animation-placed object chosen in the World tree; this window opens instead for a terrain piece (its recipe), for a pickup, for a vehicle or animation-placed object (read-only), and for an AI node or AI path selected in the view, and with nothing selected for the selected asset, else the archive). Closed at startup; size and position saved; closes when its document is disposed; the window X closes it. Never a docked pane and never takes workspace space; no bottom button row.
- Its document and record identity stay pinned across selection and preview replacement; ordinary selection never retargets it. Never bind editable fields to the active row; never keep a hidden renderer alive for it.
- Fields are editable for source documents (source objects, source pickups); compiled assets show a read-only view. A compiled animation opens its Inspector instead ([compiled animation preview](#compiled-animation-preview)); `properties_open` refuses it.
- Its commands target its owning document; native text undo stays. Icon-only Undo/Redo at the top right of the breadcrumb row; trimmed single-line heading with a full-context tooltip; document-scoped Ctrl+S.

## Drafts

- Scalar and compound drafts commit on Enter or an intentional field boundary, with inline validation; Escape restores. Exception: the source object card (`SourceObjectCardEditor`, `ManualDraftMode`) keeps its draft through Enter and focus loss; only Apply accepts it. Resolve drafts explicitly before navigation, retarget, save or close, including clean documents with pending input; popup drafts first. MCP draft rules: [architecture](architecture.md#mcp).
- Numbers display in ordinary decimal notation with the exact stored float precision; scientific notation is accepted as input; viewing a value creates no edit.
- Preserve unknown bits, inactive stored fields, authored rates and record order.
- Realizing a retained tree selection when its tab opens is presentation work, not navigation or a draft commit.

## Source map editor

- An open source map uses the source map editor: Save, Undo and Redo sit in its grouped command bar; the title shows the map name and an Edited pill; the World tree is the left pane; the selected-object card is always docked as the right Properties pane and never floats. These session panes never overwrite the compiled explorer's pane preferences; the [Properties window](#properties-window) rules still apply.
- World editing applies to objects throughout the hierarchy; how views update after an edit: [sources](sources.md#workspace-save-and-recovery).
- In source maps placement and object editing is always available. Compiled worlds allow read-only selection, cards and bounds, without handles or drags.
- Panes: World tree (`SourceOutlinerPane`), view, docked Properties pane; the gaps resize them for the session. Hiding a pane gives its width to the view; hiding Properties hides the selected object's form (it never floats over the view). Properties pane sections fill its width and an overflow scroll bar takes its own column.
- Diagnostics is the bottom pane: file and preview problems only, without the compiled explorer's tabs (no Related or Bytes) or its maximize and hide buttons; shown by default, the status bar toggle shows and hides it, and the project remembers that and its height. The status bar shows no messages: a failure in the map (a brush stroke, a stale conversion, Properties refused during a drag or Fly, the 3D view failing to render until it renders again) goes to Problems and opens Diagnostics; in [Animation mode](#animation-mode) it goes to Problems and the transport's status line and opens nothing.
- Status bar: the selection ("name · node #N" or "No selection"), mission start and difficulty, the player tank (below), "Animation mode · name" in Animation mode or, after Exit, "Animation scenario kept · n starts" (a click re-enters), instance and mesh batch counts; on the right the [update item](#update-check) when shown, Preview notices (with count) and the World tree, Properties and Diagnostics toggles.
- No Scene or Selection menu in a source map: the World tree's eyes (middle-click isolates) and the header's Show all eye replace Selection.
- The player tank's card puts Master type and Weapons before Details, which starts collapsed there and remembers its own expansion for the session (other objects' Details keep theirs; owner request 2026-10-23); with the tank chosen in the World tree, Alt+Enter focuses the chosen master type unless the open Details has an editable placement field (selected in the view, Alt+Enter opens the read-only Properties window, as for any vehicle). Master type and Weapons are each tagged Preview: radio groups that are one tab stop each, entered at the checked radio, arrows (Left/Right in a row, Up/Down in a column, Home/End) moving and selecting past disabled radios, tooltips on keyboard focus; disabled radios give their reason. A choice rebuilds the view like a difficulty change (pending drafts are resolved first) with "Posing…" in the changed section's header, keeps the radios' keyboard focus through the rebuild, and creates no draft, edit or undo step. With nothing selected the pane's Player tank row shows the choice and selects the tank; the status bar names a choice that differs from the defaults. Rules: [preview](preview.md#player-tank).

## Inspection card

- Selecting an object expands its details below the permanent hover readout; the panel stays at the top right as the camera or object moves, labelled offscreen or inactive when appropriate. Width and details height are bounded by the viewport, keeping the navigation cube clear (beside the panel in short viewports, a compact slot at constrained widths, its usual corner when space permits).
- Floating it is translucent (blurred scene under an 80 % tint of the theme background); docked in a source map it is opaque. The probe strip shows, on one line, the name under the cursor and the surface point with X/Y/Z coloured like the handles; outside source worlds a second row gives the object's origin.
- Header: icon, name and type (a source object's class and node number, the model in its tooltip), Isolate (not in source maps) and Close; trimmed title with a full-name tooltip. Collapsible sections: a source object's Object, Transform (Move/Rotate toggles in its header), Zone, Flags (check boxes), Surface; a placement's Details (toggles in its header). Footer: draft status with Revert and Apply, enabled once something changes. Showing a placement's handles starts its draft; hiding them ends it while it changes nothing. The card keeps its size and field positions when a draft starts or ends.
- Readouts are subdued selectable fields with stacked X/Y/Z for vectors; copy buttons keep round-trip precision and coordinate-space labels; the body has its own scrollbar gutter clear of the copy buttons. The wheel scrolls the card over its contents, never zooming the scene at a scroll limit; camera gestures start outside the card.
- Animation cards distinguish runtime instance IDs from source nodes; expired instances never silently bind to another copy. Inspection never changes events or playback.
- Height: the bottom grip resizes it (Up/Down 10 DIP, Home/End to the limits); minimum 216 DIP, default 432 DIP, maximum 80 % of the 3D viewer's height (the maximum wins in short viewers). The probe strip and action header stay fixed while the rest scrolls. One preferred height is shared by the three 3D viewers and saved; automatic shrinking and closing keep it; Reset layout restores 432. Resizing never moves the camera or commits drafts. MCP: `workspace_view` `changes.inspectionPanelHeight`.
- Closing the card clears its tree selection and Frame-selected target and collapses only the details. Compatible refreshes restore a retained source row's framing and inspection without choosing an arbitrary runtime copy. Isolating a pickup child keeps the whole placed pickup. Geometry shared by several mission actors has no uniquely editable placement and stays read-only.

## World tree

- Under World, imported objects expose their complete authored child hierarchy, including hidden healthy/destroyed states, nested references, geometry and LOD nodes. Viewport hits keep whole-object ownership; tree rows select exact nodes for framing, inspection and supported edits. Selection never changes visibility or camera; presentation-only expansion never accepts drafts. Resource-placed actors retain their placement selection rules.
- Child eyes share source-map part overrides: initialized flags supply the default, explicit gates can reveal initially hidden geometry, ancestors and LOD still apply. The eye shows the own gate, dimming also reflects effective visibility; tooltips explain a blocked visible gate. Overrides are session-only, independent for siblings and occurrences, and retained through compatible refreshes. Reset part visibility restores the owning object's initialized gates. The shared static refresh stops animation preview and keeps camera/selection; animation playback retains its own visibility behavior.
- Fixed row order: World, Zones, AI Vehicles, AI Networks, Pickups, Animations. Animations holds Objects placed by animations, then the mission and Common definition folders. Section, folder, file, pass and note rows show counts, open or close on click and are never the selection. A definition row shows its binding count ("1 binding", "8 bindings", "Not bound"), Open (▷) and Frame, no eye; only a definition with several bindings has binding rows ("root · #N", each with Open); calls belong to Animation mode. Enter or a double-click on a definition or binding row opens it in Animation mode; its context menu adds Open in Animation mode, Frame bound objects, Copy animation name, Show source (a flyout with the definition's excerpt) and Properties (Alt+Enter: selects it and focuses its card). Search matches a definition's animation name, root name and file. Selecting a zone, network or definition ends the object selection and opens its card in the Properties pane; Escape, Clear selection or a click on empty view space clears it.
- Keyboard: Up/Down, Home/End and Page Up/Down visit every shown row without stopping on buttons; a selectable row becomes the selection, other rows only take focus (outline) while the selection keeps its highlight and card. Left/Right step through the row's buttons (Zones switch, Pickups Group by type, Frame, eye; Left from the first returns to the row) and show their tooltips; Space or Enter opens or closes a row or presses the button; Escape returns from a button to its row.
- After a rebuild the tree that had the keyboard gives it to the selected row. After Group by type: the Pickups row or group row that had the keyboard keeps it (a type row gives it to its group when the types go; pressing the toggle from the keyboard keeps it on Pickups); otherwise the selected row takes it, or Pickups when nothing is selected or the selection is inside a closed row.

## Title row

- One title/menu row with full-height caption controls and a Windows maximize/Snap hit region; menu and caption hit regions reserved equally on both sides.
- Outside the source map editor the current document name is centered, trimmed, with a full-path tooltip; hidden without a document. Undo, Redo and Save exist only for source documents; compiled documents are read-only and never dirty.
- No separate folder/document command row and no duplicate Export or Validate buttons; exports live in the Export menu.
- Help: **Controls and formats**, then the user guides and the release notes, which open in the browser on GitHub at the installed version's tag (`v<version>`, never `main`: guides change between versions), then **Check for updates** and **Check for updates automatically** ([update check](#update-check)), then **About zStudio**: version, licence and third-party notices from the executable, so it works without the files beside it. MCP: `help` (the update items: `update_check`).

## Escape

- Order: exit captured Fly; else leave the polygon zone tool; else cancel the VTOL drop-window draft (or its loading analysis); else cancel the AI path box, draft or Edit mode; else cancel the active pickup/placement drag or terrain stroke (only that gesture); else stop an active export, validation, reconstruction or terrain-conversion planning. Escape never cancels loaded preview lifetimes.
- In a source map, an Escape nothing else uses (no field, drag, Fly or operation) clears the selection. Pick in view ends before the rest of the order. In Animation mode, after everything in progress (a drag, Pick in view, a drop-window move, a flyout), Esc clears the mode's selection (graph, Timing, a picked object) and the Inspector shows the opened definition again, as the pane's ✕ does; with a card draft open the drafted record's card stays (only the selection goes); with nothing selected it does nothing. A refusal while a card draft is open names the card ("the animation card's changes" for an animation draft). Shift+Esc exits Animation mode; plain Esc never does.

## Presentation modes

- In every 3D preview F10 toggles Hide UI and F11 fullscreen, independently (owner decision).
- Hide UI leaves the view alone: no menus, command bar, panes, status bar, banners, Properties window or editor guides; clicks select and edit nothing while navigation and Fly go on. It is refused during a zone or terrain stroke; it leaves the polygon zone tool (which cannot be engaged until the UI shows again) and turns off the terrain brush, keeps layout preferences and drafts, ends when 3D content is left and is never saved. F10's release is consumed so Windows does not enter menu mode (Alt opens menus); the title strip stops moving the window while hidden; keyboard commands such as Ctrl+Z still work. MCP: `presentation` `uiHidden`.

## Fly camera

- Captures input only on explicit activation in model and Whole world previews, never through a scene-option refresh; never in animation previews.
- WASD moves along the camera basis, Space/C along world Y, mouse movement looks around, the wheel changes speed without translating. Combined movement is normalized and integrated over elapsed time without inertia; speed never depends on surface hit distance.
- Desktop owns foreground raw mouse and cursor capture with a recentered fallback for absolute or remote input; Rendering owns the motion math.
- Release all held input, cursor confinement and capture on Escape, deactivation, focus or capture loss, an unavailable or replaced preview, and shutdown. Keep the final pose; keep the icon and speed hint in sync with the actual state; support overflow activation; never persist active capture.

## Animation mode

Design: `design/animation-redesign.md` §6–§7, §12, §13 (owner decisions in `.agent/ANIMATION-REDESIGN-PLAN.md`). A layout of the source map editor for one opened definition; the [compiled animation preview](#compiled-animation-preview) reuses its components read only.

- Entering: a definition row's Open (▷), Enter or double-click, its context menu, the definition card's accent **Open in Animation mode** (map layout only), an object card's or a row glyph flyout's animation link Open, the definition picker, Animation → Open in Animation mode / Return to …, the status bar's kept item, MCP `animation_mode open`. Clicking a definition row only selects it and shows its card. Drafts are resolved first (Cancel stays). Entering never moves the camera, plays or evaluates paths (only the Auto range is measured, in the background); the opened binding becomes the scenario's primary start (`AnimationScenario.WithPrimary`: another definition keeps the previous primary as an ordinary start; another binding of the primary's own definition, the binding picker, replaces it at its time). Opening another definition in the mode keeps the scenario and pushes the previous one to Back. Back/Forward take their entry off the history before the open awaits and ignore key repeat.
- Exit: the command bar's scope slot becomes **Exit animation** (Back glyph; "Exit" below 1,450 DIP) with the title block (definition picker; caption "Definition · file · root #entry"; binding picker when the definition has several) and Back/Forward; Shift+Esc; Animation → Exit animation mode; MCP `animation_mode exit`. Plain Esc never exits. Exit commits the Scenario tab's typed fields first, ends Pick in view, stops the run (as Stop), keeps the scenario and leaves the definition selected with its card. The kept item follows a reload of the same map (re-resolved on its new document, on the scenario's remapped primary) and is forgotten with another map, a closed map or the source chrome. Another map, closing the map or leaving the source chrome ends the mode; a rebuild of the same map (an edit, undo, redo, difficulty, LOD) keeps it on the scenario's remapped primary and ends the run, so the playhead returns to 0 s (the range's Auto or Custom choice stays; Auto is measured again with the next preparation); a save keeps everything (the run, the playhead, the range, the selection, Timing, the paths and the drop windows).
- Layout: the 3D view on top; the animation panel below (transport 40, view bar 34, the views), its height 52 % of the column by default (56 % narrow), at least 240 with the view keeping 160, remembered per project (`.zstudio/settings.json` `animationPanelHeight`); the right pane (340 DIP, 300 below 1,300, never below 280) shows the selection's header (34 DIP tile, name 15 SemiBold, kind 12 secondary, Frame and Close; the card's own title row hides, the object card's too; "Scenario · Kept for m4 · changes re-evaluate to the playhead" with the Scenario tab) above the Inspector | Scenario tabs and their content; the World tree is hidden until shown in the mode (remembered in the profile settings `AnimationModeWorldTree`); Diagnostics is a strip under the panel with its own splitter (default 140, minimum 96, at most the room the panel leaves above the view's 160: the panel keeps its height and gives way only for those 96; state reports the height shown; its height is the session's: `animation_mode layout diagnosticsHeight`, and `workspace_view toolsHeight` in the mode, never the map layout's height), hidden by default and remembered per project (`animationDiagnostics`); it never replaces the panel, and a reported failure never opens it. The status bar's selection names the Inspector's (`AnimationInspection.StatusLabel`: "flare_sequence › Player within 64? · condition"; the opened definition with nothing selected; the object card's selection). Overlay and Zones hide; below 1,450 DIP Camera and Display move to ⋯ and the scenario chip shortens to "Scenario · n". Hide UI and fullscreen keep their rules.
- Panel views: Structure | Timing | Split (Ctrl+1/2/3; Split needs 1,300 DIP of panel width). Structure is the default; Split at 2,200 DIP windows (Structure 58 %). Timing is described below; each shown view's tools sit in the view bar (both in Split); those that do not fit between the view switch and the notices chip move, in order, to **⋯** ("More view tools") beside the chip, never clipped (compiled previews too). Each ⋯ flyout (this one and the transport's) works from the keyboard: opening it focuses its first control, Tab cycles inside it, Esc closes it and returns the focus to ⋯ (a list open inside it closes first).
- Structure (`AnimationGraphView`, design §8): draws `AnimationGraphLayout` (Core; positions, bands and routes are the model's, so MCP reports the same geometry) on a canvas under one transform: frames, then one edge drawing, then nodes. Zoom 25–200 % (Ctrl+wheel at the pointer, Ctrl+=/−, the zoom menu), wheel/Shift+wheel scroll, middle-drag, a drag on empty space or Space+drag (anywhere, never selecting; Space alone plays on its release) pans, Fit (Ctrl+0), a minimap (180×110, bottom right, only when the graph is larger than the panel and the panel is at least 900 wide). A new binding opens at Fit when that keeps 75 %, else 100 % at the top left, at every panel width (design §8; a narrow panel no longer fits below 75 %); the same graph keeps its zoom and scroll through expansion, collapse and run updates. Semantic zoom changes what nodes draw, never where they are: ≥ 75 % full rows, 50–75 % rows without threshold badges, 30–50 % headers and faint row bars (switches and buttons hide; a reference node's run line becomes a mark in its header), < 30 % names with a large run mark; edges, ports and the run state stay at every level (design §8). Nodes are realised inside the viewport plus one screen and let go beyond two; a node holding keyboard focus stays. Each node draws itself (chrome, bands, boxes, the run overlay) and holds a thin focusable band per header, row, question, branch label, closing line, Show all and outcome line (pointer, tooltip, UI Automation name and help text naming its relations), plus real controls: the chevron, a grouped row's member chevron, Expand/Open on reference nodes, the Game | True | False radio group (`GraphSwitchSegment`; UI Automation: a Group named "Player within 64 of rlbridge, preview: Game") on every IF/ELSEIF outcome line (pips: at most 3 there; a question in a loop, or one that showed more passes, has a full-width pass strip under it with the latest 40 and "+n", each pip's tooltip "Pass 3 · 24.317 s · false (game)", a click seeks), a blocked sequence's link (Blocked ›: selects the waiting call row and focuses its port), an expanded group's member switcher in its frame header (one frame per group; the overlay is the shown member's, a line sums up every member's state), and a call port (`AnimationGraphPort`, a three-state toggle: all, none or some of the edge's call paths) on every shown call row. Notices (design §15): a node with notices draws a ⚠ n pill on its top edge (`AnimationGraphView.SetNotices`). UI Automation: the view is a Tree; frames (tree items) hold an expanded group's member switcher and their realised nodes; nodes are tree items holding their bands and controls (switch segments, ports, buttons); an element without a peer of its own (a panel, the run tag) is descended into, so everything below the frame headers is reachable. A relayout (expand, collapse) returns keyboard focus to the selection's band; a refused switch shows the scenario's choice again.
- Structure operations (GUI and MCP `animation_graph` alike, `MainWindow.AnimationGraph`): select loads the selection's definition into the card (`WorldAnimationSelectSourceAsync` with the frame's call path; a reference node's first binding's definition) and the Inspector shows its card (below); the view outlines the nodes the selection names (`AnimationPhrases.NodeNames`, found under the binding's root; the definition's roots for frames) instead of the definition's roots, and Timing selects the sequence's lane (opening its closed groups) with the event's marks outlined. A 3D object selection marks the rows naming it (bindings whose root holds it) with an amber bar. A switch is `ScenarioCondition` with the frame's path (refused for a frame reached only by name); a port is `ScenarioInclude` with the edge's paths; Include ▾ is `ScenarioIncludeAll` (All calls), `ScenarioIncludeAll(opened: true)` (This animation only: the paths below the opened binding's start, the other starts' calls excluded; MCP `includeAll` scope `opened`) or Exclude all; Expand is `AnimationGraph.WithExpanded` (64 groups, one frame each; the refusal says "Collapse another called animation first") and the member switcher `WithMember`, both remembered per definition for the session; collapse, open, Show all and member lists are presentation remembered per definition for the session (sequence identities change with a recompile). The run overlay is `AnimationRunOverlay` over the session's current frame (its last frame after a Stop, a source draft or a scenario change on a stopped run: drawn at 50 % with Re-run to here and "Stale · from the last run" or "from before your edit"; a source edit rebuilds the map, which ends the run, so no overlay shows then), recomputed at most ten times a second while playing. A Timing selection selects the same row (none when the graph does not show it) and outlines what it names; a selection a rebuild drops takes its outline with it. Keys in the graph: ↑/↓ through bands in column order, →/← follow an edge or expand/collapse a header, Enter expands (reference node) or toggles (sequence), Ctrl+Enter opens, G/T/F switch a selected question, F2 focuses the Inspector's threshold, Esc clears the selection.
- Timing (`AnimationTimingView`, design §9): draws `AnimationTiming` (Core; the GUI and MCP `animation_timing` read the same projection) in seconds. A label column (220 DIP, grip 160–420) and a 32 DIP ruler (ticks at 1, 0.5 or 0.1 s by zoom, labels at least 90 DIP apart, the playback range's outside shaded, a "+5 s" pill at the range's end (Extend +5 s; never over the playhead's time tag: at rest it moves beside the tag, after it when there is room, else before it, and while playing it hides as the tag passes; none while Auto measures), the playhead a 1.5 DIP accent line with its time; click or drag seeks, at most every 60 ms while dragging); rows are the Starts lane (28), instance groups (28; top-level open, called ones closed, toggles kept for the session) and sequence lanes (24). The run's refreshes (playback, seeks, scenario changes) build the projection on the thread pool, cancel one a newer frame supersedes and show it only while its frame, scenario and toggles are still the shown ones; selections, toggles and MCP build it at once. Only the rows in view are drawn and hit-tested (one element draws them; nothing is created per row or mark). Bands: waiting for release (hatched, labelled with its releaser or "no releaser left", shortened to its first clause where the full label does not fit), waiting for threshold (dots, "anim ≥ 23 s → 43.000 s"), paused (stripes), blocked (rose hatching), ✓ at completion; a group row's band is its binding state. Marks: shape is the kind, colour the graph palette's family; marks within 4 DIP of the previous form one cluster (its lead by priority, a count badge, hover lists 20 and "and n more"); a run wider than 6 DIP is a rail with its count; a closed group row shows its lanes' marks. Thresholds (off by default) draw brackets from observed anchors; the selected event's bracket end is a 10 DIP handle (a 3 DIP dead zone as a start drag has; 0.025 s grid, Shift 0.1 s, Ctrl free, never below 0) when `CanEditThreshold` allows (a provenance START_TIME field, no open draft). An analyzed VTOL flight of the opened definition adds a Drop windows lane (24) under its flight (motion) sequence lane (`AnimationTimingDrops`, from the analysis and the drop schedule's first-event marks as cycle starts): each window of every reached cycle as a numbered cyan bar at its authored start and duration on the flight sequence's clock (the Inspector's window list shows the same starts; a dispatch tick is never a drag's origin), the selected one outlined, muted with a dashed edge and a "Stale" pill while the analysis is stale; a click selects the window, a drag past 3 DIP moves its start only (0.025 s, Shift 0.1 s, Ctrl free, within the window's bounds; a ghost shows the proposal) through the drop-window draft; it is never a lane selection. The Starts lane drags (same snaps), right-click Remove start and Show in Scenario; a click opens the Scenario tab. Starts within 4 DIP are one cluster: one marker with "+n" after its top start's label (the start its click list chose, else the primary, else the last), every start in its tooltip; a drag moves the top start, a click without a drag opens the list (choosing one makes it the top start), the right-click menu removes any of them, and hit tests take the topmost; each start keeps its own UI Automation slider. Stale evidence draws at 50 % and the header says "Stale · from before your edit" or "from before Stop"; without evidence the empty-state message shows over the lanes. Log: a virtualised `ListView` (Time · Instance · Sequence · Event · Result), Copy (Ctrl+C), Follow latest, "n rows · n retained · n discarded". ## Source animation links, editing and paths

- Animation mode keeps the map's world viewport, toolbar, LOD and Difficulty controls. Selecting a definition in the map layout shows its card in the docked Properties pane; it prepares no player, evaluates no paths, measures no duration, decodes no audio and never moves the camera. Object cards (the player tank's too) end with Animations affecting this object (literal names, the reason, Open; a row selects the definition): the first 8, then "Show n more", which lists the rest in place; a row's animated mark opens a scrolling flyout of every one ("and n more" only for uses that are no definition of the map or beyond the 256 an object keeps, never silently capped). Links use exact definitions/bindings, never names as identities.
- Stop detaches to the initialized static map at time zero; source edits detach before creating the shared draft and leave previous evidence stale. Apply/Revert never revives a run.
- Editing scope (one Apply/Revert transaction, in Animation mode's Inspector above): existing event operands, waits for release, activation, prerequisites and start thresholds (seconds only; Timing's threshold handle writes the same draft, its marks never drag). Whole-sequence START_TIME is labelled ignored. Keyframes, synthetic/protected records and event insertion, deletion and reordering stay read only.
- Paths chip (`MainWindow.AnimationPaths`, design §14; Animation mode only): a `ViewportChip` after Perspective ("Paths ▾ · not evaluated / evaluating / shown / hidden / out of date / partial", a ring while evaluating). Its flyout: Evaluate paths (accent; `AnalyzeSourceAnimationAsync` for the opened binding with the scenario and its included paths, silent: never moves the playhead, camera or panel; progress and failures go to the chip and the transport status line, never to Diagnostics opening), Show guides (only with a matching cached result: same built map, binding and scenario), Contacts and impacts, Show range tests, Frame paths, Clear cached paths, the legend and the status line. Guides carry time (`AnimationViewOverlay`, a hit-test-free layer over the view projected through `SceneViewport.ProjectToView` and redrawn on `ViewChanged`): a dot per guide at the playhead (interpolated, its rest pose after its last sample), faint 3D ticks every second, and a selected event row emphasises the guides of the nodes it names (alpha only). Contacts (⊥) and impact sounds (◎) come from `AnimationPaths.Markers`. Range tests: a selected or hovered PLAYER_RANGE question or range-gated activation (`RangeOf`; the attach node from the run's `AnimationFrame.Attaches`, the callback node of every range-tested instance even without a model, else the latest pass's `AnimationConditionResult.Center`, else the map's) draws a 72-segment ring of its radius in the horizontal plane (1.5 DIP release green at 70 %, a disc at 8 %, its radius labelled), the player pin and a dashed line labelled "2,010 · outside 64 → false" ("→ runs/paused" for a gate); an off-screen or behind-the-eye player is an edge arrow with "Player · 2,010"; Show range tests draws every range test of the shown graph (the opened binding and its expanded calls). The player is `AnimationFrame.PlayerReference` at the playhead, else the scenario's setting (custom, none, the mission start). Exit and opening another definition hide the guides (their cache stays; when the cache is full, paths evaluated for an earlier scenario, which can no longer be shown, make room first). Drop windows are Animation mode's: Exit, opening another definition and another map close the analysis, while selecting another definition's items (a called animation's node, rows or Timing lanes) shows their card and keeps it; Move along path shows a banner ("Moving drop window 2 · click a point on the flight path · right-click or Esc cancels", the Pick in view style) that a click (placing the start; the draft stays for Apply), right-click, Esc, Cancel, Exit, map end or rebase ends; their markers: starts cyan, releases orange, the selected window white. ## Viewport toolbars
