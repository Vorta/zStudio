# Source projects

Agent reference for source projects: format, reconstruction, builds, edits and their limits. User guides: [source projects](../source-project.md), [map editor](../map-editor.md). Engine facts these rules rest on: [engine evidence](engine-evidence.md). The original tree: [recoil-original-worktree](recoil-original-worktree.md).

- A project is a folder with `data/` and `gamegen/` (the original tree, reconstructed) plus one hidden `.zstudio/` folder: `settings.json` (last view: Diagnostics shown and height, mission difficulty, texture dithering), `export/` (Blender graph checkouts, completed generations, sealed updates), `recovery/` (save journals), `staging/` (files being saved). Builds never read `.zstudio/`; nothing else of zStudio's lives in a project (owner decision). A missing `settings.json` means defaults. A malformed, oversized or non-object file is tolerated when the view is read (the view is not remembered) but refused by exports, checks, `source_status` and the `source_dithering` read until a dithering choice replaces it (`replaceDamaged`); a dithering value is never guessed. A linked `.zstudio` folder or settings file is refused (`IOException`) by Core; the GUI then does not restore the view and reports a failed view write in Problems.
- Sources are authoritative; game files change only on explicit export. Exports must work in the game; they are verified by meaning (members, compiled values, tokens, formats), not by matching shipped bytes.
- All model, buffer and texture inputs stay under `data/` or `gamegen/`; script search folders outside them are ignored; references into `.zstudio/` or other non-source folders are refused.

## Source format

Models are glTF 2.0 with external PNG textures; engine attributes live in `extras.recoil`. Reconstructed sources mark the scene `extras.recoil.sourceFormat: 4`. All readers, writers, edits and comparisons use the shared `WorldGltf` codec.

| Node property | Value | Engine flag |
| --- | --- | --- |
| `altitudeSurface` | Boolean | 0x08 |
| `intersectSurface` | Boolean | 0x10 |
| `intersectBounds` | Boolean | 0x20 |
| `proximity` | Boolean | 0x40 |
| `landmark` | Boolean | 0x80 |
| `declient` | `"canModify"`, `"clipTo"` or `null` | 0x10000 or 0x20000 |
| `overwrite` | Boolean | 0x800000 |
| `altitudeZoneCheck` | Boolean | 0x01000000 (the gate) |

- Omitted Booleans mean `false`; readers accept explicit `false`, writers emit only `true`; Booleans reject `null`. Missing/null `declient` means neither crater mode and is omitted on output; `"none"` and `"both"` are invalid (owner decision: CanModify/ClipTo are exclusive; their edits are atomic across GUI and MCP and keep script provenance). Defaults do not inherit engine constructor defaults: reconstruction writes every enabled flag. Example: `{"altitudeSurface":true,"intersectSurface":true,"declient":"canModify"}`.
- Load roots keep their named flags and `zone` together in scene `extras.recoil.loadRoot` (a numeric ID or `"any"`; cannot inherit).
- Zones: node `zone` is 0–254, `"any"` or `"inherit"` (absent also inherits). Material `zones` and primitive `polygonZones` (one array per polygon, `[[3], [3, 7], []]`) are ordered numeric IDs; `[]` (no IDs) differs from `[255]` (any). Nonzero object padding → `zonePadding` (three bytes); noncanonical inactive polygon slots → material `zonePadding` or sparse `polygonZonePadding`; malformed compiled counts → opaque `zoneRaw`/`polygonZoneRaw`. Ordinary assignments need none of these.
- Placement overrides: a reference node may carry `zoneOverrides` with a structural `fingerprint`, ordered node assignments (`zone`, `altitudeZoneCheck`, true-only) and mesh `polygonZones`; its `references` object holds deeper overrides keyed by the referenced file's node indices. The owning source path and the chain of reference occurrences select a placement (never a display name); outer assignments win over referenced-file defaults; stale assignments are refused before a build or edit attaches them.
- Other node fields: LOD ranges (a LOD node stores no local transform; a nonidentity one is refused); `name` when it repeats or looks like a Blender copy (`.001` is otherwise stripped); `ref` (an OpenFlight external reference: another glTF loaded under the node, relative path); `instance` ([Shared nodes](#shared-nodes)); `model` for a model without polygons (lens-flare points); Object3D `appearance` (`flags` for non-transform class bits, `alphaScale`, `color`, `colorAlpha`; transform bookkeeping bits 0x39 stay derived). Meshes: display mode and flags, texture scrolling, morph factor, point entries. Materials: polygon priority, back faces, `zones`, colour, soil, engine material flags, texture by name (an image's file name, else `texture`), `normals` when its polygons store normals. Primitives: `polygons` (fan counts or corner lists) where joining triangles would not restore the stored polygons. The mission master holds `zoneLabels`.
- Effective engine node names fit 35 Latin-1 characters without NUL; a recorded engine name wins over the display name. Material, mesh and Object3D `appearance.flags` stay separate attributes.
- Bits 28–30 (0x70000000) have no source property; source builds write them zero (owner decision; not a recovered meaning).
- **Refused, never migrated** ("reconstruct the project from the original ZBD files"): marked source formats other than 4; packed node `flags` and scene `rootFlags` (even null); numeric object `zone: 255`; `zoneInherited`, `inherit`, `zoneFromLoad`; packed `zoneWord`, material `zone`, packed polygon assignments; point-only records as empty meshes (use node `extras.recoil.model`); projects with the external `meta/zones.json` sidecar format; databases with external reference bindings outside glTF.
- Mirroring transforms (negative determinant along the node path) turn a mesh's polygons over on import, keeping each first corner; export turns them back. A mesh used with both handednesses becomes two models; a node shared by parents of both handednesses is refused.
- Two viewer-only conveniences, read by no build: a material whose PNG has alpha is marked `BLEND` (`MASK` at 0.5 when alpha is only 0/255); a pickup's `bvol` (the one `FindSubNodeByName` finds from the pickup, in a model a build loads under `pu000`–`pu039` or a placed `puNNNNN`) gets a transparent material `~hidden` (Alpha Clip, base alpha 0) recording the engine colour and `opacity`.

### Shared nodes

- `extras.recoil.instance` marks a node several parents share (an OpenFlight instance definition): each glTF copy carries the same number and import joins them; the first definition is used and later records join it (they may inherit other parent zones or omit its children). Copies that disagree are refused.
- Edits to an instance change every copy (transform, flags, copies, deletion), refused when an editor made the copies differ. An instance node does not move out, and nothing moves in. An instance without its own zone takes the zone of the copy the build reads first; an edit that makes the build read another copy writes that zone onto every copy (refused when it came from references in different zones).

## Reconstruction

- **Input:** RECOIL data with RECOIL evidence (prepared scripts, a version-15 world or a version-28 animation program); only files in the chosen folder and its mission folders `mN` are read. MechWarrior 3 and the version-13 1998 demos are refused. Only original archives qualify: the `zrdr.zbd` of each `anim.zbd`'s folder must hold exactly one `anim.zrd` member that decodes with top-level animation definitions; otherwise "zStudio can unpack only the original ZBD files." A project is reconstructed once, then only exported.
- **Safety:** creates every file as new and never replaces one; cancellation or failure removes only what it wrote (files with other content stay, named). Every probed input's size, time and content digest are captured first and verified on each later read (one read-only handle). A project folder may not be or lie inside the protected corpora (`zbd_1998`/`zbd_1999`), and may not be, contain or lie inside its input folder (`SourceProject.ValidateSeparate`, compared also through short names, SUBST drives and links); no folder on its path may be a link (`SourceProject.RejectLinks`). Destination parents are rechecked before writes.
- **Worlds:** each mission's scripts are replayed against its shipped world and their edits (attach, rename, rearrange) undone in reverse, so each load's root holds exactly its file's scene. Polygons keep authored corners and UVs (repeated corners, non-planar polygons, UVs; only the tile shift and 1/256 quantization apply). Scripts name files as written (`LoadGameGen` and `dbName` name `.gltf`; texture commands name `.png`); node names keep their spelling, also `.flt` endings.
- **File identity:** each evidenced original FLT boundary becomes one physical glTF file, keeping the original master names (`m1.gltf`) and nested relative `extras.recoil.ref` links; objects authored within a file stay within it; matching geometry never merges distinct original files.
- **File placement** (evidence only, never names alone; see [owner decisions](#owner-decisions)): a file whose script chose its folder (`SetModelDirectory`: `bftN.gw`, `bftmulti.gw`, `weapons.gw`) goes there; a file every mission's scripts load identically (the `pickup.gw` pickups) goes to `data/common/models`; a database and a mission's own loads go to that mission's `models` (one copy per mission); a load finding an identical file in an earlier-searched folder uses it; external references are written beside every referencing file (two missions keep a copy each). A copy never takes the name its load finds its own file by in an earlier folder (`name_2.gltf`). Only folders that hold files are created.
- **Mission databases and parts** ([build-tool loader](engine-evidence.md#build-tool-loader)): records in file order; groups the build deleted are placeholders (a part reference is `groupN`; another group takes the name a freed slot still holds — its own, or in an exact reading its node's slot in the part's cache — else `groupN`; no slot names a group unless the database's deletion directly follows its load, no other `DeleteTree`/`FreeNode` follows and no sourced script is missing); a group's last objects after it where its cache shows the group closed early; nodes in creation order. Inferred loader sections with unrecoverable names stay embedded in their owner: `extras.recoil.inlineSource` holds an opaque cache `id` and a `count` (the first `count` children are the section, the rest the reference's own records), nested as needed; no invented `mN_NN.gltf`. A file named by several paths is written `./name.gltf`, `././name.gltf` … (counted per physical file; caches key on the reference as written, ignoring case), also inside models where the slots show it (`comanche.gltf` names `./hturret.gltf`). Instance definitions stay one node with instance marks, made before the file's root.
- **Freed-slot names:** an exact parts reading replays the database's load once more, noting which record each cache node copies and which node was freed last at each slot; a slot the load left free and no later node took holds that node's name, used only when every such slot of an object holds its object's name (the replay counts only against the build's per-load limit). Gate: the database's `DeleteTree` directly follows its load, no other `DeleteTree`/`FreeNode` follows, and every sourced script exists (anything between could rename nodes the deletion frees). Only m6 kept freed slots: both releases name five city-part groups `street`, `ramps`, `bwall`, `phones`, `hydrants`; its other 75 deleted groups are `group1`–`group75`. Exports keep m6's freed slots in shipped order with shipped names, except the end node `db`, left unnamed.
- **Readings:** the slots cannot distinguish two loads of one file under one name nor which reference took a second path, so reconstruction tries each reading, builds each database as the build will and keeps the one where every node takes its shipped slot (else the closest, noted). The reference whose copy has its own models is the second-path one; later copies sharing those models name that path too. Records starting on several caches' leftovers (m2): search for the boundary whose simulated caches end there and give back their high-water mark. Records starting inside the first cache's copy (m6): read that cache whole from the bottom of the free list and simulate from it. No fit: objects in shipped slot order with a group at every freed slot, noted. Models are made as the original loader made them (once per cache, each object its own, in read order).
- **Textures:** each becomes one PNG in the folder pack record order places it (`data/common/effects/textures`, `data/common/textures`, the mission's `textures` and `textures/bft`, or `data/common/multi_bft/textures`). Differing duplicates inside one mission pack are refused before ranking (including external palettes); interface records in different recorded folders stay distinct files (same-folder differing copies refused). The copy kept (`SourceExtractor.BestTextureVariant`): the shape held by the pack with the most room (larger budget, `texturemax` none; at equal budgets the software pack, whose paletted texels take half the space; shipped rank `texture8`, `texture6`, `texture4`, `rtexture4`, `texture2`, `rtexture2`); between shapes whose best packs have equal room, the larger; then direct colour over a palette. Shape before size: m5 `swall3` is 128 × 128 in `rtexture2`/`texture2` and 256 × 64 in `rtexture4`/`texture4`/`texture6`; the 1999 strips (8:1, `heldoor6` 16:1) are stored as squares of half the long side (twice the texels, the strip stretched) in the smaller packs (`sonic06` 128 × 16 in `texture4`/`texture6`/`texture8`, 64 × 64 in `rtexture2`/`texture2`). A cycled material whose own texture no pack holds (1999 m9 `surf` samples `surf00`) gets its frames' shipped edge mode.
- **Sounds:** each source is its best-quality version across the three banks; repeated names within a bank must be byte-identical.
- **Layout provenance:** ZAR members record their compiler's temporary file in the source folder, so each resource returns to its folder; WAVs go to `data/common/sounds` (`SOUND_PATH`); the prepared-script index names each script and its modification time, which the file keeps.
- **Animations:** definitions are `.zad` files: each mission's `data/mN/zrdr/anim.zad` and the files it names (renamed, and the names in the lists with them); `pickup.zrd` keeps `PICKUP_DATA` and its animation becomes `pickup.zad`. A definition is replaced by one decompiled from `anim.zbd` only when the shipped text does not compile to the shipped entries and the replacement does exactly. Its note says it was rebuilt from `anim.zbd`, which the game uses and which was compiled from a newer version (recorded dates show the archived text is older), gives the save date `anim.zbd` records and what the newer version changes (both decompiled, so only compiled differences are listed; e.g. `gen_vtol.zad: vtol_destruction* … (saved 4 Nov 1998) … RESET_TIME ( 0.5 ) → ( 0 ); RESET_STATE › OBJECT_ACTIVE_STATE healthy › STATE ( ACTIVE ) → ( INACTIVE )`); never that the archived text was edited later (owner decision). The five affected definitions: [original worktree](recoil-original-worktree.md#how-the-shipped-files-were-built).
- Shipped files whose family is not reconstructed are listed and not copied. zReader files the game never requests ([resource archives](engine-evidence.md#resource-archives)) stay in projects and archives: they carry genuine data.

## Owner decisions

- No migration of old projects or settings; old formats are refused with "reconstruct" guidance.
- A vehicle that several missions' `bft1.gw`–`bft6.gw` load identically is one file in `data/common/models` (which those loads search); a differing version stays in its mission's `models/bft`.
- The turrets (`pturret`, `nturret`, `samsite1`, `fturret`, `lturret`, `arcturt`, `sonictur`) are one file in `data/common/models` that every reference names (`../../common/models/pturret.gltf`, keeping a second path's `./` spelling) when all copies are the same apart from zones, reference no other file and find the same textures; placements whose zones differ keep them as zone overrides. A turret whose copies differ otherwise stays beside each referencing file, noted.
- Effect models (`weapons.gw`) are kept with their textures in `data/common/effects/models`.
- New reconstructions put m6 `lasdesig` (loaded by `support/bft6.gw`) in `data/common/models`, and m4 `train`, `rcar1`, `trnsplsh` (`support/bft4.gw`) with the `tturret` they reference in `data/m4/models`, only when mission, script and model-folder provenance agree; buffers stay beside models, texture locations unchanged; existing projects are not migrated.
- No empty folders, even ones the scripts search (`data/effects`, multiplayer `models/bft`, `textures/bft`).
- Rebuilt definitions' notes follow the [reconstruction](#reconstruction) wording rule.
- One `SourceWorkspace` and one project-wide undo history per source project; Save writes every accepted source change and names the files.
- Text `.zrd`, `.zad`, `.gs`, `.gw` and `.zan` edits preserve untouched bytes, comments, order, scalar kinds and spelling; reformatting is never implicit.
- Source saves are recoverable, not simultaneously visible: a file name may briefly be absent, publication never replaces an unexpected file, and an incomplete rollback blocks writes until resolved. Unfinished recovery data or Blender work is never deleted silently.
- Blender changes enter only through Update from Blender export (sealed generations, the shared plan/apply path); the extension never writes project or game files.
- Evidence names the operation it establishes: runtime routines do not define the lost build tool's behaviour; animation-binding reports keep logical targets and resolution order, not names or slots, as identity.
- Terrain is authored as unsplit surfaces; splitting and zoning happen in zStudio; paint lives in a versioned terrain recipe with no editor state; reconstruction yields pieces, not recipes.
- "No clip" means ClipTo (no craters), as the original developers used the term; collision and standing are separate flags.
- Multiplayer crater compatibility with shipped worlds is not needed.
- The player start is read only where the mission's opening holds it (2026-10-23: the opening decides where the player actually starts and when the controls are released): the local player's placement is locked when its startup chain (the `NEW_GAME_START` entries and the entries they call) takes the controls (async callback 14) and, in the sequence that gives them back (15), takes the player's pose from the tank's node (10) ([engine evidence](engine-evidence.md#objectiveszrd-and-startanimszrd)). Where the chain also moves or turns the tank (m2–m6) the opening sets the start; otherwise (m1) it releases the controls from the placed pose. m7–m13 have no opening, so their start moves.

## Builds and export

| Game file | Sources | Build |
| --- | --- | --- |
| `zrdr.zbd` | `.zrd` in every `zrdr` folder under `data/common` | compiled, ordered by source path |
| `mN/zrdr.zbd` | `.zrd` under `data/mN/zrdr` | compiled, ordered by source path |
| `interp.zbd` | `gamegen/*.gs`, `gamegen/support/*.gw` | tokenized; each records its file time |
| `soundsh/m/l.zbd` | `data/common/sounds/*.wav` | converted to the bank formats of `sounds.zrd` |
| `image.zbd` | `data/common/{fonts,images}`, `data/mN/images` | authored size, direct colour, not dithered |
| `mN/rtexture*.zbd`, `mN/texture*.zbd` | the mission's texture folders and every texture its world uses | scaled to the pack's budget and colour mode |
| `mN/gamez.zbd` | `gamegen/mN.gs` and what it sources, glTF models | the build script with the engine's interpreter rules |
| `mN/anim.zbd` | `data/mN/zrdr/anim.zad`, the `.zad` files it lists, their `.zan` | compiled against the world this export builds |

- **Export destination:** may not be or lie inside the protected corpora, may not be, contain or lie inside the project (`ValidateSeparate`), and no folder on its path may be a link (`RejectLinks`).
- **Exports** stage and re-parse every output through the shared readers; if any fails nothing is written. Existing game files are replaced only with consent (GUI names them; MCP needs `overwrite`); other destination files stay. Staged files are checked against the built bytes and held until in place; replaced files move to a `.zstudio-backup-…` folder and are restored on failure (undo removes an output only while it still has the installed content and the backup holds the original). The export replans before writing and fails when outputs, inputs or packs changed; an edit during the export fails it. Unsaved project edits must be saved or discarded first (exports read disk). Exports never overwrite sources or escape the destination.
- **Archives:** members found by name, so two sources with one file name in an archive are refused. A mission resource named like a common one is never read by the game: its archive builds with a warning naming both. A `.zrd` source may be text or compiled data. Only `.zrd` resources are packed; a `.zrd` holding `ANIMATION_DEFINITIONS` fails the export. A member records its project path (63 Latin-1 characters; longer fails the archive; shipped paths ≤ 55; sound banks leave it out) and the fixed time 1 January 1980 00:00 UTC, so builds are deterministic.
- **Sounds:** declared formats are ceilings, never raised: each of rate, sample size and channels is the lower of source and declaration. Conversion mixes channels, reduces sample size, resamples with a windowed-sinc low-pass filter and moves cue markers; 8/16-bit PCM only; undeclared WAVs go into every bank unchanged, with a warning.
- **Worlds:** `gamegen/mN.gs` runs with `source`, macros and `ifdef`/`ifndef` (a condition holds when its macro is exactly `TRUE`; `||`, `&&`; while skipping, the first `endif` ends the block, as retail) and the retail command semantics ([script interpreter](engine-evidence.md#script-interpreter-commands)). `LoadGameGen name.flt node` loads `name.gltf`/`.glb` from the first `SetModelDirectory` folder holding it ([search-path rule](engine-evidence.md#common-rules)); the file after `GameGenSetWorld` is the mission database. At `GameZWriteZBDFile` the engine update runs (matrices, bounds, grid partition, single-parent flags) and version-15 GameZ is written. Texture-effect script textures must be named without a folder and in at most 19 characters. `CameraTranslate`, `CameraRotate`, `CameraSetActive`, `CameraSetNearClip`, `CameraSetFarClip` and other recognized world commands without saved-world support are reported, not executed; a small set of diagnostic/runtime-global commands is ignored.
- **Models:** at most 921 vertices; corners within 0.001 merge (as `AddOrMergeVertex` 0x482720); a mesh still over is refused naming node, mesh and counts. Normals merge within 0.0001 into at most 921; polygons past that are stored without normals, with a warning. One morph target per model, position deltas only. Textured materials need any RGB tint baked into the PNG; MASK on textured materials only at 0.5 (keyed textures, hidden `bvol`); untextured MASK becomes fully transparent or opaque by `alphaCutoff`. metallicFactor must be explicitly 0, roughness 1, emissive 0; normal/occlusion/emissive/metallic-roughness textures are refused. Vertex colours, skinning and animation channels are refused (bake them).
- **glTF reader:** canonical `asset.version` "2.0"; GLB exact length, one JSON chunk then at most one BIN chunk; JSON ≤ 32 MiB, 4M tokens, depth 64; numeric spellings ≤ 4,096 bytes, exact integers where required (`3.0`, `3e0` accepted, fractions never rounded); buffers 512 MiB together, ≤ 4,096, positive `byteLength`; transforms as a `matrix` (homogeneous row [0,0,0,1]) or `translation`/`rotation`/`scale`, unit quaternions; every reference must exist; accessor types as glTF requires (positions/normals/morph floats; UVs float or normalized unsigned 8/16-bit; `KHR_mesh_quantization` integer forms); indices unsigned, not normalized; strides multiples of 4 from 4 to 252 on vertex attributes only; views within their buffer; triangles, strips or fans with POSITION (points/lines refused); finite components; samplers `REPEAT` or `CLAMP_TO_EDGE` (mirrored refused; filters dropped); `texCoord` and `KHR_texture_transform` (scale, CCW rotation, offset) honoured; other required extensions refused; trees only (one parent per node, each root once); several scenes need the top-level `scene`; embedded images refused (external PNGs; PNG chunk order and `tRNS` lengths validated, end chunk empty and last).
- **Animations:** `anim.zbd` compiles from `anim.zad` (paths relative to the gamegen folder, or bare names beside the list or in `ANIMATION_PATH`; a missing file warns), its definitions and the `OBJECT_MOTION_SI_SCRIPT` keyframe scripts. A `NAME` listing several roots binds to the first the world has; `*` matches one digit, expanding in name order; a definition whose root the world lacks is omitted. A sequence named more than once takes its last `NAME`; inside an event the first of a repeated attribute counts; a `START_TIME` given to a whole sequence is ignored. An unresolvable node name or an effect missing from the `effects.zrd` the game reads (the common one when present) is an error, as are values that do not fit their field (`EXECUTION_PRIORITY` > 255, `LOOP_COUNT` > 65535), more than 32,767 entries, and nonfinite or overflowing operands. No source stamps are written. Keep every shipped entry recompiling to the same fields (`SourceProjectCorpusTests`).
- **Texture packs:** hardware packs (`rtexture`) RGB565 with an alpha plane, aspect ≤ 8:1, largest side 256 (`rtexture2`/`4`), 1024 (other built-ins), up to 4096 (profile packs); software packs (`texture`) shared palettes (≤ 255 colours a page, near-black opaque entry kept apart from the zero key), largest side 1024, wide/tall images kept. Damage masks the mission's scripts register (final expanded `WriteTextureSetMap` operand) and the horizon's textures stay direct colour in software packs. Colour-keyed textures store opaque texels with five-bit green (low bit clear) and black as 0x0001 (`TexturePackBuilder.KeyedTexel`); paletted pages keep 0x0020 for black. Numbered mipmap names (`_1` ending a name with an existing `_2`) are refused in 3D packs and world texture directories (`TexturePackBuilder.NumberedMip`). A texture's edge mode comes from its glTF samplers; an unsampled cycle frame takes the mode of the material its cycle shows on (tex_fx: first material of the node `FindNode`/`FindSubNode` selects; `effects.zrd` `MAPS`: first material of the first model at or below the effect's node); conflicting modes fail the build. At most 4,096 textures and 512 MiB per pack; textures up to 4096 × 4096.
- **Build profiles:** `original` (the shipped packs: `rtexture2`, `rtexture4`, `texture2`, `texture4` in every mission, `texture6` in m1–m6 and m13, `texture8` in m6) and `modern` (default; adds `rtexture8`/`rtexture16`, `texture8`, `texturemax`, and the automatic `rtexture<N>`). Profiles in `gamegen/build-profiles/*.json` (`format` `recoil-build-profile`, `version` 1, `texturePacks` with `file`, `budgetMiB` (null = full size), `maximumDimension` (power of two 8–4096, ≤ 1024 for software packs), `missions`); each profile needs at least one `rtexture` pack without a `missions` list (Direct3D reads only `rtexture` packs). The automatic pack: when full-size textures need more than the largest fixed `rtexture` pack, `rtexture<N>`, N the need in MB rounded up to a power of two, capped by its budget (256 MB in `modern`; textures then reduced); counted at two bytes a texel (one paletted) plus a byte for alpha planes. Full exports size it from decoded PNGs (alpha, cross-mission textures); listings and partial exports from PNG headers alone. Destination `rtexture` packs the profile does not build are warned about. An unusable profile file is listed as invalid and blocks only itself; one that may be the default (not valid JSON, or claiming `"default"`) can stop every export and check (a profile chosen by name reads only its own file), naming the file.
- **Dithering** (none, ordered 4×4, Floyd–Steinberg; the project's choice in `.zstudio/settings.json`, passed explicitly to exports and checks, owner decision): a colour the pack stores exactly is kept unless diffused error reaches it, so RGB565 packs built from reconstructed (565-expanded) PNGs are identical for every choice; paletted pages store only their palette, so reconstructed textures there can change. Keyed-out and transparent texels are not dithered, the key colour is never produced, alpha planes keep 8 bits. Paletted ordered strength follows the page's colour spacing; paletted diffusion carries at most 32 per channel and keeps the exact entry when error would move a texel more than 48 from its colour. Deterministic.
- **Lookups:** check and export report whole-world name lookups the game makes at load (texture-effect `FindNode`, animation roots, attach nodes, unresolved inner names, first prerequisite nodes) with the node found (highest slot); an export replacing a mission's files warns about every lookup that now finds another node; source edits that change one are reported until saved or undone (`lookupChangeCount`). Runtime macro operands are not expanded; reordered duplicate-name subtrees are not proven unchanged.
- **Input stability:** build snapshots include files searched for but absent and search folders named but missing; their appearance before publication refuses the export. Read files are rehashed before publication.

## Keyframe scripts

- `.zan` files are Softimage "SI Animation Script" exports; the SI compiler (`src/zStudio.Core/Animation/Si*.cs`) reproduces every shipped keyframe of both releases bit for bit (pad floats aside). Change its arithmetic only with new reference vectors.
- Format: header (`SI Animation Script`, `FRAMES:`, `OBJECTS:`), then frame blocks: `Frame: n` (frame n − 1 at the definition's `SCRIPT_FRAME_RATE`; may go back), per object `Object:`, `Scaling:`, `Rotation:` (radians about X, Y, Z, applied Z, Y, X; beyond ±π allowed), `Translation:`. Header, blank lines, `#` comments and DKit messages are not keys; a frame repeated immediately adds nothing; a definition's `NAME` picks the object.
- Compiler: consecutive frames become segments; a channel is kept when it changes (position/scale component > 0.00001; rotation half-angle > 0.00001 rad); first and last segments keep every channel; segments without change are dropped. Times are frame × float(1/rate); rotations through the engine's matrix/Euler/quaternion routines in single precision; rates are change over the segment, spin from the engine's quaternion log and fast square root.
- Writer guarantee: a script is written only when it compiles back exactly; otherwise zStudio's keyframe format with a note (two poses at one frame, a first segment not moving every channel, a value no six-decimal number reads back as, an angle search too long, an oversize script, a negative-zero rotation angle). A track off its rate's frame grid is not reconstructed (noted). Written values are the six-decimal values the stored floats came from; held frames take the next key's value; negative-zero translations/scalings are written `-0.000000`.
- DKit messages and Softimage versions are historical and written only for stamped retail files: before every frame (after every frame in the `m5doexit.zan` of 20 May 1998), version by stamp date (3.5001 before July 1997, 3.7 until 4 May 1998, then 3.71); the exit scripts list `vtol1`, `lengine`, `rengine`, `cargodoor`.
- zStudio's keyframe format: `OBJECT name` then `FRAME f` lines with `POSITION`/`SCALE` XYZ, `ROTATION` W X Y Z (nonzero), optional rates `VELOCITY`, `GROWTH` (per second), `SPIN` (half-angle rotation vector per second). A key's channels start a segment to the next key; the last key's frame ends the track. Without a rate a channel moves steadily to its next listed value; with a rate it moves until the next key, then holds unless listed. Two keys at one frame are a cut. A file without `OBJECT` lines is one track any node may use.
- Text resources (`.zrd`/`.zad`) use zStudio's lossless syntax: a file lists its root array's children; `( … )` arrays (`KEY ( value )` on one line); decimal 32-bit integers; floats always with `.` or exponent (`2.0`, `1E-45`), raw bits `f32:7FC00001` for NaN/infinities, bit-exact (`-0.0`, subnormals); bare strings start with a letter or `_` and hold letters, digits, `_`, `.`, `-`, else quoted with `\"`, `\\`, `\xNN`; ASCII written, Latin-1 read; `#` comments. Edits keep comments, spacing and untouched value spellings; new records use the canonical layout.
- Gamegen scripts use the engine tokenizer; empty tokens are written with commas (`a,,b`, trailing `a,,`).

## Workspace, save and recovery

- One workspace per project: one history (an edit may change several files; missions share files), one Save of every changed file (`zstudio_source_changes` lists them with history and line diffs), one map open at a time.
- **Apply/Undo/Redo** prepare a candidate source scene in memory on a worker against an isolated workspace before accepting the transaction; acceptance rechecks workspace revision, read-file stamps and other editors on the UI thread. Invalid changes or cancellation leave content and history unchanged; a failed publication check takes the transaction back and keeps the pending input. After acceptance a preview failure is reported, not retracted.
- **View updates:** unambiguous glTF Position/Rotation/Scale edits and placement transforms update the accepted snapshot and viewport instances, bounds and picking in place (keeping document, camera, geometry, textures, initialized child poses); reuse is refused when movement would change initialization bindings or placement decisions. Structural changes, ambiguous repeated occurrences and changes while VTOL analysis is open evaluate a replacement scene with the camera kept. No archives are created.
- **Ownership:** while a source operation prepares or publishes, other edits, saves and reloads are disabled or `busy` (shared with conversion planning); while a map opens, saves and interrupted-save decisions report it.
- **Edit admission:** retained file buffers (originals, pending content, undo/redo, rollback) share 1 GiB. Every written path passes the save's rules at edit time: no Windows device names (CON, PRN, AUX, NUL, COM/LPT + digit, any extension), forbidden characters, trailing dot/space, names > 255, paths > 1,024 folders or beyond what Windows can create (32,762 characters with a drive), files used as folders or vice versa, short 8.3 spellings of existing names, files inside files the edits write.
- **Save:** each file staged and verified in `.zstudio/staging`; a journal in `.zstudio/recovery` records what is replaced; each original moved aside and its replacement put in place unless changed or created meanwhile (staged content checked against the journal and held until in place); journal removed. Failure restores replaced files. A file changed externally since the workspace read it is never overwritten. Saved files are read back; one replaced meanwhile is reported changed and its new content shown. Save also checks that changed map-zone profiles still describe their geometry and that geometry changed through map-aware editors still matches every map assigning its zones (pending edits plus current disk).
- **Recovery:** an interrupted save is reported on opening: Roll back, Complete, Keep files (journal to `.zstudio/recovery/abandoned`), Later (saving asks again). Originals are verified by content before restoring; a missing or damaged one leaves the installed file and reports a conflict; links in staging/recovery are refused. Until decided, the project cannot be saved; the opening check holds the save lock. A save that finished but left its journal is a warning, removed by the next save. MCP `zstudio_source_recovery`, `zstudio_source_recovery_resolve`.
- **Reload** evaluates current dependencies into a fresh document; it refuses files with both external changes and unsaved edits (GUI asks to save or discard). Out-of-date maps (a dependency changed after building, including through undo) refuse edits until reloaded. A folder created externally where an unsaved new file would go counts as an external change.
- A project that is a link or lies below one is never edited or saved. Windows saves and exports hold directory identities through creation, verification, publication and cleanup; an empty staged file turned into a link between its last check and the rename remains an unresolved race.

## Edit semantics

- **Provenance:** every built object knows its source: a node of the mission master (`data/mN/models/mN.gltf`, with embedded sections), a node of a model file, or the script instruction that loaded or created it, with the instruction that last set each property.
- **Transforms and flags:** rotation is degrees about Y, then X, then Z (at ±90° pitch yaw is shown 0). Only object and LOD nodes have editable flags; a no-op flag edit changes nothing. CanModify/ClipTo exclusive (enabling one clears the other); an edit the script commands cannot express in its scope is refused (no script command sets ClipTo); a build refuses both bits.
- **Objects:** a database node edits its glTF node in the database or the part holding it (a part edit applies to each copy; `origin.part`); a model file's node changes every load of the file. A script `Object3DRotate`/`Object3DScale` replaces a node's own transform, so copies a script rotates or scales keep the script's values (noted, followed per mission by name). Script-placed objects edit the instruction that set the value (`Object3DTranslate 110.0 5.0 -50.0`), or add one after the creating instruction. A value set by a script other missions also run is set before this mission's world is written instead, after a `FindNode` of the object (whose name must be unique). Refused: instructions run more than once per build, values from macros (edit those in the script).
- **Copy/delete/parent** (`zstudio_source_world_object_edit` `duplicate`, `delete`, `parent`; parent is MCP only): database or part node — glTF copy beside it sharing meshes / node and descendants removed / moved within its file keeping place and zone; script-loaded object — the load repeated before the world is written (`SetModelDirectory`, `LoadGameGen`, flags, transform, `FindNode`, `AddChild`) / every instruction that loaded, changed or attached it commented out (`# LoadGameGen …`) / its `AddChild` commented and a new one added, transform compensated (its scripts must then run only in this mission). Copies need a name no node has; parents found by name must be unique. A copy or move is taken back when the rebuild makes any script instruction act on another node or none. Refused: deleting an object a script other missions also run creates (no exact deletion for one mission); a script-object move under a turned non-uniformly scaled parent; scale 0 (< 0.00001); a result beyond ±1,000,000 of the new parent; deleting objects other instructions use (a camera's horizon, a world's light); copying or moving templates (loaded models no node holds); moves that would change which `NodeSetLighting` reaches the object; database groups moved where the build deletes them while they have geometry or a transform; a LOD node moved under a parent not standing where its parent does. Moves write the zone a node had when the move would change it; a model-file node moved in maps that bind it states its zone per map and is refused when its loads gave different zones.
- **Rename/model** (database objects): `rename` changes the glTF node name in every copy; refused while a script finds the object by its old name, while a listed animation binds to that name (until the new name is added to its `NAME` list; the shipped `destroy_turret` lists `tur_101`), or while the mission's animations compiled with the new name would be rejected. `model` changes the object's (or its one referencing child's) external reference, keeping name, place, flags and zone; refused while a script acts on a part of the previous model; the previous model's zone overrides are removed. Groups the build removes (m1 `group1`) can be renamed in their sources only (MCP `rename` with `sourceFile`, `gltfNode`). Both rebuild as one undoable change.
- **Where edits land:**

  | Edit | Source |
  | --- | --- |
  | Transform or flags of an object in `mN.gltf` or its parts | that glTF node (every copy of a part) |
  | A placement wrapper with `ref` | the wrapper node; geometry belongs to the referenced file |
  | An object created or changed by a script | the responsible instruction, once its exact execution occurrence is established |
  | Shared model geometry, LODs, engine attributes | the owning glTF (Blender update), after showing every affected load and mission |
  | AI vehicle placement | its ordered record in the selected `aiv*.zrd` |
  | Pickup placement and creation | its ordered record in `puppies*.zrd`, linked difficulty variants kept, fallback resources deduplicated |
  | AI network header or node position | the network's `net_NN.zrd` (node moves and link changes are separate operations) |
  | Lights, fog, cameras | their effective script commands |
  | Object and polygon zones | the node, its placement override or the load root; polygon zones in the owning glTF |
  | Terrain attributes | the terrain recipe |

- Renaming a build-removed group writes only its glTF name; in worlds that are not dense (m6) the freed node slot keeps the new name as inert bytes.
- **World commands:** fog, lights and cameras are script commands; editing one edits its instruction; an unset command fitting the node is added after its creating instruction (`zstudio_source_world_command`).
- **Placements:** pickups, AIV vehicles and AI network nodes edit their owning resource tokens in memory (tanks the selected AIV resource; pickups `puppies*.zrd` with unambiguous difficulty counterparts matched by type, position and rotation); nothing else in those files changes. An edit stores the values it changes with the shipped precision (`PlacementPrecision`): positions and AIV headings (degrees) one decimal, pickup rotations (radians) four; always float tokens (`12.0`; an edited integer coordinate becomes a float); unchanged components keep their text (m6 `18.25`); drags snap so previews equal saved values. A tank record moves the node the game places for it: a world node of its own name, which is its own template identity (the player tank: every `bftN.gw` and `bftmulti.gw` loads it as `bft_00`), else the template its name derives ([`aiv.zrd`](engine-evidence.md#aivzrd)); either must be the only node of that name, or the record is read only. A node that several records of the shown difficulty place (retail m2 `aiv_easy.zrd` lists `bft_00` twice) belongs to the first of them and is read only; the map still shows. The player start is read only when the mission's opening holds it (see [owner decisions](#owner-decisions); m1–m6), so it moves in m7–m13; any other unit hidden at the mission's start, or a player tank hidden there without an opening holding the controls, is read only too. Startup-animation positions are not movable. AI path transforms are MCP only (`zstudio_ai_path`). Pickup creation (`zstudio_source_pickup_add`) appends records without changing existing ones and verifies the template spawns (bvol copy) before acceptance.
- **Zones:** an object's zone and altitude gate are written where that occurrence keeps its zone: the node, the reference placement's override, or the load root; a shared zone asks before changing all (`sharedScope`). The polygon zone tool paints map-owned models (`data/mN/models`) only: paint adds a zone after a polygon's others (a polygon with three is left), Any replaces all, a number replaces Any; erasing the last leaves none (≠ Any). A placement takes painted zones as its override; a file's own geometry changes wherever it loads. Strokes take at most 4,096 polygons across 1,024 placements. Labels live in the master's `zoneLabels`. Terrain painting and the zone tool are mutually exclusive.
- **Add model** (`zstudio_source_world_add_model`, MCP only) adds the shipped load lines before the world write (`SetModelDirectory ..\data\common\models`, `LoadGameGen ltank.flt ltank`; placed: `Object3DTranslate`, `Object3DRotate`, `FindNode %worldName%`, `AddChild`), optionally listing other missions' definition files in `anim.zad`; refused when an earlier-searched folder holds another file of the name or the name is one of the model's own nodes.
- **Section cards:** AI network headers edit `net_NN.zrd` values in place (Buddies Attack also stores Buddies Activate).
- **VTOL drop windows:** analysis runs on a frozen, independent copy of the animation runtime: it never moves the visible player, plays audio or changes sources. A move changes only the call's `START_TIME` scalar in the owning `.zad`, verified by a complete before/after compilation; refused when it changes another window's releases or when a shared definition would alter other entries. Camera changes are blocked during a pointer move; a failed rebuild rolls back and keeps a still-wanted draft. Compiled worlds: analysis only (windows cannot be selected).

## Terrain

- Terrain is unsplit glTF surfaces in a file of their own plus a recipe `name.terrain.json`; a marker node in the database's roots (`extras.recoil.terrain`, named `name_terrain` or `terrain`, ≤ 35 Latin-1) takes the pieces' place in root order.
- **Splitter:** cuts surfaces exactly at the cell lines (`WorldOrigin`, `WorldExtents`, `WorldPartition` must precede the database load); cuts along painted region outlines (only where an outline edge runs through a part) and gives each part the attributes of recipe defaults, surface defaults, then regions in order; groups parts into pieces by surface, cell and node attributes (named from the recipe's first twelve name characters, surface and cell); divides pieces past 921 vertices or normals (incoming polygon order kept). Crater-capable pieces (CanModify without ClipTo) keep at most 450 vertices/normals and polygons of at most 30 corners. Cut points enter every polygon sharing the edge (no cracks or T-junctions); every polygon starts on a well-shaped triangle (plane through the first three corners within 0.005 of every corner; twice its area ≥ 0.001 × longest edge²; smallest height ≥ 0.01); untouched authored polygons and normals are kept; deterministic.
- **Attributes:** `zones` (1–3 numbers or `any`), `nodeZone` (number, `any`, `auto`: the shared zone else `any` with the gate on), `nodeGate`, `collision`, `standable`, `craters` (`allowed`, `blocked`, `ignored`), `soil` (default, water, seafloor, quicksand, lava, fire, 6–99), `priority`, exact `flags`. Regions: name, surfaces (all when none), shape (polygons with holes in x, z, optional height range); a region without a shape covers its surfaces. Stacked sheets must be separate surfaces. Unknown recipe keys are kept as given.
- More than 16,000 painted polygons warn; a world past 262,144 polygons is refused.
- **Convert to editable terrain:** the database's untransformed mesh objects (roots and those in transparent groups) become surfaces in `mN_terrain.gltf`, one recipe per uninterrupted run of siblings (each marker in place, preserving encounter order); adjacent pieces with the same flags, zone, appearance and model values share a surface unless they overlap in plan. Kept as objects: horizon and landmarks, transformed nodes and nodes with children, references and parts, shared nodes, bounding-box collision or proximity pieces, facades, lens-flare pieces, and anything a script, resource or animation names or matches. A surface below an appearance-bearing ancestor is refused. Acceptance compares the altitude probe before and after (heights, zones, soils, flags; encounter order kept at equal heights); a sampled comparison, not gameplay equivalence. Loses the original piece layout and names.

## Blender extension

- The bundled **zStudio RECOIL** extension (Blender 5.2 LTS, Windows x64) runs a windowless format helper (no MCP). **Tools → Edit in Blender…** checks out a model or master map's complete reference graph from the current workspace into `.zstudio/export`; **Export RECOIL glTF** writes a completed generation into the outbox; **Tools → Update from Blender export…** (`zstudio_source_blender_update`) validates the generation and hashes, remaps placement profiles and applies one undoable transaction. Physical file identities, relative references, flags, zones, face assignments, load-root values and engine properties stay embedded in glTF.
- Consent is required for source edits since checkout and shared texture conflicts; it cannot force invalid metadata. An update may replace earlier updates' results only when its export descends from them (same import, the same `.blend`'s recorded generations); otherwise it is a conflict or refused. Ordinary Blender glTF exports and flattened checkouts are not accepted. Edited polygons keep boundaries only where surface, normals, UVs, morphs and placement zones survive; a split face takes the nearest assigned face's placement zones. Do not promise ordinary Blender import/export preserves the hierarchy.

## Compare worlds

**Tools → Compare worlds…** (`zstudio_world_compare`, `zstudio_world_compare_tree`) merges two `gamez.zbd` (version 15 or 13) by parent-child structure: children pair by name, repeated names by whole contents, then structure, children's names and nearest position, independent of slots; child, cell and overflow lists compare in encounter order. Rows: `·` same, `≠` changed (class, flags, zone, cell, transform, class data without pointers/slots/counters, model values and polygons, child count, order), `−`/`+` one side only (≤ 64 differences listed per row). `⚑` marks a shared-name node a whole-world lookup finds in one world but not the other (indistinguishable copies count as the same). Texture-directory multiplicity, load states and next-variant links are compared. Caps: 500,000 rows, 256 levels, 2,097,152 candidate pairs per name, 16,777,216 pair checks, 1,048,576 copy checks (summaries say when reached).

## Known differences

Exported files differ from the shipped ones where the original choices are not recorded:

- Name fields keep different residue after the terminator.
- `m9/gamez.zbd` names `surf00`, which no shipped pack holds; the game shows its default texture for it in shipped and exported worlds.
- Software packs choose direct colour by rule (damage masks, horizon), so the hand-chosen direct textures (`tanktop`, `tankback`; m1 `tanktop`, `tankgn01`, `tankgn02`; 1999 m10/m11 `arcgun01`, `beamred`, `beamyelo`, `erfpgscl`) are paletted, shaded and unstamped in software, and m2 `sky2lite`, 1999 m11 `m11sky`, m13 `skym6` are direct.
- Rebuilt worlds order used materials differently and omit unused colour materials (not crater-compatible in multiplayer with shipped worlds).
- Five archived animation definitions are rebuilt from `anim.zbd` (see [reconstruction](#reconstruction)); their archive members differ from shipped ones.
