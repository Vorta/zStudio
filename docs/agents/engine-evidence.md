# Engine evidence

What the retail RECOIL engine does that source projects, builds and previews rely on (how to use it: [AGENTS.md](../../AGENTS.md#engineering-invariants)). Facts only the running game can settle: [in-game acceptance](testing.md#in-game-acceptance) (T1–T20).

Labels: **[B]** byte-matched in the reconstruction; **[BN]** confirmed in the executable; **[D]** measured on the shipped 1998/1999 data; **[U]** reconstruction only or inference. Addresses are 1999 retail unless noted. The private references (retail database, reconstruction) are described in [architecture](architecture.md#formats-and-evidence); they are not build dependencies.

## Common rules

- **Errors are silent.** `zError::ReportOld` (0x404e80) is a single `ret` [BN]. "GameZ node buffer is full", "Database intersections array is full" and the like never appear; a failure shows only as its effect (a default texture, a missing object, a crash).
- **Resource keys.** `zRdrGetNode` / `zRdrFindNode` (0x48cf70, 0x48cec0) [B] search depth-first through nested arrays and return the item after the first string equal to the key anywhere, including strings inside values. Of duplicate keys the first wins; a string value can shadow a key read later; a key that ends its array makes the reader read past it.
- **Script commands match by case-sensitive prefix** (`strncmp` over the command's length): built-ins (`CZInterp::HandleBuiltinCommand` 0x4c1c50 [B]) and engine commands (`DispatchCoreCommand` 0x4c20a0 [B]). `FindNodes` runs `FindNode`; `findnode` runs nothing; `Quit` must match exactly, ends its own script, and the sourcing script goes on.
- **Search paths keep their first order.** `zRdrAddSearchPaths` (0x4a5ce0 [B]) splits its operand at `;` (`strtok`) and adds each folder at the head of the list only when it exists (`zReaderFileExistsWrapper` 0x4a5c40, `_access` [B]) and no entry has exactly the same text (`zRdrStrCmpPredicate` 0x4a5da0, `strcmp` [B]); it never moves an entry. `SetTextureDirectory` reaches it through `zImageInitMissionResources` (0x46ebd0 [B]), `RdrAddPath` through `zRdrAddPath` (0x48cce0 [B]); `RdrSetPath` (`zRdrSetPath` 0x48cca0 [B]) empties the zReader list first. The gamegen tool's `SetModelDirectory` is lost; it is taken to use the same routine [U].
  - A script naming a listed folder again leaves the order: `weapons.gw` and `bftN.gw` stay behind `common.gw`'s `data\common\effects\models` and `data\common\effects\textures` [D: the damage masks `weapons.gw` names after setting `..\data\effects\textures` came from `data\common\effects\textures`].
  - A missing folder is not listed and is tested again when named again. Another spelling (case, separators) is a new entry at the head; Windows finds the folder under any spelling.
  - zStudio: builds list a folder only when the project has it (on disk or holding a pending file) and its text is new, and search each folder once from its first place. Traces outside a build (reconstruction, checkouts, object edits) take every named folder as present, which finds the same files.
- **No type checks.** Gameplay loaders read the raw value union and never call checked accessors: an integer where a float belongs reads as a denormal (`10` → about 1.4e−45), a float where an integer belongs as a huge integer (`8.0` → 1090519040); a missing item or wrong shape dereferences garbage. zStudio treats each as an error.
- **Loose files.** Scripts not in `interp.zbd` are read loose from the game folder (`RunScriptFile` 0x4c1500 [B]); a loose `support\*.gw`/`*.gs` newer than its `interp.zbd` entry overrides it (loose-file timestamp precedence 0x4C5740 [U]). Loose difficulty variants: [Resource archives](#resource-archives).

## Node attributes and flags

- **Object zone:** one unsigned byte at node +0x30 (getter 0x448180, setter 0x448330); 0xFF is any. The next three bytes have no identified runtime meaning (padding).
- **Polygon zones:** four bytes, a count then up to three IDs; 255 is any (0x476370, 0x476400). A polygon with count 0 differs from one assigned 255.
- **Altitude gate:** node flag 0x01000000, independent of the zone.
- **Flags:** altitude surface 0x08, intersection surface 0x10, intersection bounds 0x20, proximity 0x40, landmark 0x80, CanModify 0x10000, ClipTo 0x20000, overwrite 0x800000, gate 0x01000000. Setters `NodeSetCanModify` 0x447D20 and ClipTo 0x447D70 change single bits. The retail crater path gives ClipTo precedence when both are set ([Craters and quicksand](#craters-and-quicksand)).
- **Bits 28–30 (0x70000000):** clear on all 54,017 live nodes of the 19 retail worlds and 25,885 live nodes of nine demo worlds [D]. Bit 28 is set on 134 of 282 (1998) and 136 of 287 (1999) retained free m6 slots, each with one live counterpart of the same name, bounds and zone word, a direct world child with bit 28 clear [D]: a build-time membership/promotion marker, name and lifecycle unknown [U]. `CopyNodeBaseData` (0x451BD0, mask at 0x451E54) copies the group [BN]; no runtime setter or test was found. All 325 overflow entries (including 235 landmarks) have the bits clear [D].
- **Soil:** material byte 32 (reset 0x480C40 zeroes it); names 0–5 from the table at 0x4E0FD0 (`default`, water, seafloor, quicksand, lava, fire); `LoadSoils` adds 6–99 (0x481460). Polygons of one model can have different soils through different materials; the probe returns the hit polygon's own material. `CompareForReuse` (0x480d20) merges runtime material clones that differ only in soil when one is 0.
- **Visibility and transforms:** a node is active by base flag 0x04; Object3D data flag 0x08 bypasses its local transform. Matrices store three basis vectors then translation (row-vector convention; local before parent).

## Map grid and zones

- **Grid:** every mission is 256 × 256-unit cells (M1 16 × 17). A top-level node joins the cell holding its plan-view centre if it overhangs that cell by at most 3 units; otherwise it goes to the world's always-considered overflow list. Cells own terrain/static roots besides world children; a root listed in several cells is one root (duplicate cell-root references collapse; child instancing stays). The horizon is a landmark: never in a cell, never distance-clipped.
- **Pieces:** shipped terrain and static geometry are pieces with world-space vertices and identity transforms (M1: 337 pieces, 146 placed groups, the horizon, 4,482 triangles; M6 14,148). M1's ocean is 93 two-triangle quads, one per cell.
- **Cells:** queries search only the cell(s) they touch plus the overflow list (0x443d20), so geometry overhanging into a neighbouring cell is invisible to probes there: cut terrain exactly at cell lines. A cell holds at most 32,767 nodes.
- **Current zones:** every frame the zones of the polygon below the camera become current; each player also has zones for collision and line of sight. Nodes and polygons outside the current zones are not drawn, collided with or targeted and run no animation callbacks. Transition polygons carry two or three zones (M1 uses 0–4, 9, 14 underwater, 32 outer cliffs/sand; M6 about 20).

### Zone gate and filters

- The node zone byte is compared by `VariantTag::CurrentAllowsId` (0x476400) against the current set (count, three IDs): it passes when its zone is 0xFF, the set is empty, or the set holds 0xFF or its zone.
- The gate (0x01000000) affects only the altitude probes (0x443d20, 0x443f80, 0x4444b0, 0x444890). Rendering (0x44c0e0), segment queries for collision, line of sight and camera obstruction (0x4455f0 and others), proximity queries and turrets test the zone whatever the gate says.
- Every visited node is tested on its own zone and flags at every level; a rejected parent prunes its subtree. Actors take their zones from the top-level node they stand on, so a top-level piece with zone 0xFF passes every zone test.
- No script command sets the gate; it is a serialized flag.

### Zone probes

Modelled by `ZoneProbe` in Core; its tests check each rule.

- **Line:** every gameplay probe is a vertical line at a point's x, z from y = 500 down without limit (0x443d20, 0x4444b0); a surface above 500 is never found. It searches the point's cell, then the overflow list.
- **Outside the grid:** world flag +0x50 clamps queries to the edge cell; it is 0 in every shipped world, so outside the grid the point probe searches only the overflow list and a vehicle's probe nothing. The cell is `(int)floor()`; a coordinate beyond 32-bit range or NaN is outside (−2³¹).
- **Nodes:** a node takes part when active (0x04) and an altitude surface (0x08) and, with its gate, when the current zones allow its zone. A LOD group takes part only when its band starts at the viewer (near range² ≤ 5). A node with siblings takes part only when its cached box (flag 0x100) holds the point in plan; one without a cached box is skipped. A camera (no box test) and a light pass the probe to their children under their own translation and angles (camera +0x20; light orientation +0x08, not the world angles at +0x20; 0x4441c1, 0x4443e0, 0x444a52, 0x444d10); sound and other classes end it. The player's own vehicle is excluded.
- **Polygons:** a polygon holds the point when every edge keeps it on the inner side of an upward winding within 0.0001 (0x4856d0); the height comes from the first three corners' plane. Morphing models are probed at their current morph factor.
- **Two kinds:** the point probe (camera, spawning, renderer) takes per node only the first polygon in stored order that holds the point at or below the top (0x484960). A vehicle's probe (0x4444b0) takes every polygon of the node that holds it and faces up (normal y > 0). Each keeps at most 32 hits; the point probe then reports "Database intersections array is full", the vehicle's drops further surfaces at or below the top (0x484b70).
- **Equal heights:** `Player::SelectProbeSampleHeightFromCandidates` (0x4290F0, byte-matched `Battlesport/player_move.cpp`) replaces its candidate only when the new height is strictly greater and within the rise window, so coincident candidates keep encounter precedence [B]. The point probe visits the cell's area entries before the world's overflow children in stored list and subtree order (0x443D20/0x443F80); slot order is not encounter order.
- **Choosing a hit** (0x4290f0): the highest hit no more than a window above the reference height, skipping water (soil 1) where asked; with none, hit 0 and the nearest height. Hits at or below y = −250 are never chosen. Windows: camera 0.001, a moving vehicle min(1 − vertical speed × tick, 4), spawning 4.
- **Camera** (0x406470 at the end of the tick, or 0x406110 in third-person views, which skips water in the submarine; then 0x406510): a point probe at the eye whose gate tests the previous camera zones. The hit's zones, with the player's own added while there is room for three, become current. A hit without zones (count 0), a result naming 0xFF, or no hit keeps the previous zones; count 0 means no information.
- **Vehicles**, AI included (0x428d60, 0x42cf90): every tick a probe at the mode's sample points, gated by the vehicle's previous zones. Sample 0's hit sets the zones even when it has none (count 0 then passes every test). The root takes the zone of the top-level node it stands on; without a hit the zones stay and the root zone becomes 0xFF. Collision, AI line of sight and pickups use these zones. AI vehicles are simulated only while their zones overlap the camera's (0x476370) and they are near or were just hit.
- **Start and teleport:** spawning (0x421830) clears the zones, then probes the spawn point with window 4, skipping water until the amphibious mode is unlocked; without ground the zones stay cleared and the root zone is 0xFF. Mission start gives the camera the local player's zones; a teleport (0x42be00) gives the player the camera's.
- **Other cameras:** a camera without the game's override (only the main camera has it) probes from its eye in the renderer (0x44d600 via 0x443c70) with no gate: the highest hit, at equal height one with zones; a hit without zones keeps the previous ones, no hit clears them (every zone drawn).
- **Shipped data** (both releases, samples every 8 units) [D]: no altitude surface lies above 500 and no probe fills 32 hits (at most 10). Surfaces stacked in one node occur (up to 738 samples in M6); camera and vehicle disagree at only two points without effect (M2 `facrds` same set reordered, M7 `o973` superset). Up to 226 samples per mission are ground whose zones include 0xFF.
- **New maps:** keep walkable surfaces at or below 500; give stacked floors separate nodes or store the camera's polygon first; keep each point under 32 surfaces; give ground polygons zones.

## Name lookups and node slot order

- **The node list runs highest slot first.** Loading a world inserts every live node at the head of the Object3D list in ascending slot order (`ReadNodeTable` 0x455350 [B], `ReadSingleNodeClassData` 0x454c60 [BN], `CZTypeList::Insert` 0x44ed90 [B, BN; 1998 0x447c70 BN]), so every lookup by name (`FindByTypeAndName` 0x44ecf0) finds the **highest slot** first. Later nodes go to the head too: `LoadZbd`'s light and sound nodes precede the world's. No node is created between the world load and animation binding (`InitMissionGameplaySystems` 0x417a00 [BN]).
- **Animation roots** (`zEffect_Anim::LoadZbd` 0x45efb0, binding loop 0x45f5bf–0x45f689 [BN]): consecutive entries with the same root name take the following same-named nodes in list order; a new name or running out of matches restarts at the head. Entry 0 and entries in state 5 are skipped without breaking the chain.
- **Names inside an animation** (`ResolveNodeByName` 0x45e5c0 [B]), in order: the callback node's subtree (preorder, children first to last); the bound root's subtree; the entry's own light and sound nodes; the whole world, highest slot first. Names compare exactly (`strcmp`); there is no shortcut for the root's name.
  - The callback node is the entry's attach node, looked up the same way at load (root subtree, then the whole world); a failure fails the whole `anim.zbd` (`LoadZbd` 0x45f6d3–0x45f6e5 [BN]). 1999 m4, m6, m12, m13 (1998 m4, m6) attach hit entries outside their root (`hit_wall_102`, root `dwall02`, attaches to one of 66 `wall1`).
  - A runtime copy (`CloneEntryForNode` 0x45e730 [U]) or rebinding (`RebindEntryToNode` 0x45ed80 [BN]) takes the new node as callback when the loaded callback was the bound root, otherwise looks the attach node up only inside the new node; without it the entry is disabled (state 5). Rebinding takes the new node's name as root name and looks every tracked node and reference up again; names stay, so a reference by the old root's name finds the new node only when it has that name (m5 `under_water_exp`, root `watexp.flt`, started at pipes' `destroyed`, finds the world's `watexp.flt` [D]).
  - The game rebinds for: a child animation started at a node (`ActivateRuntime` 0x45d930 [B]), even its bound node; a stop at another node (`StopAndCleanup` 0x45d570 [B], used by turrets and vehicles through `NodeActionCallback` 0x45d6b0 [B]); an entry flagged 0x8000 (entry flags +0x94), whose root `LoadAndInstantiate` 0x45fb30 copies and binds to the copy (`EnsureCopiedRootTree` 0x45e6d0 [B]); no shipped entry has the flag [D].
  - What the whole world holds depends on timing: at mission load the world file's nodes and the animations' own light, sound and copied nodes; AI vehicles and pickups are placed afterwards (animations, turrets, `Player::InitMissionRuntimeFromWorldAndCamera`, then pickups), so only lookups made while the mission runs find their copies.
  - Vehicle code looks parts up differently ([Vehicles](#vehicles)).
- **Allocator** (`gwNodeNew` 0x4478c0 [BN], `FreeNodeToFreeList` 0x447a70 [B], `DestroyNodeRecursive` 0x451a60 [B]): one free list for every class, last in first out; a freed slot keeps its old name. `DeleteTree` frees post-order. Models (0x482080, 0x4820f0) and materials (0x480dc0) are also LIFO; no lookup by name depends on model or material slots.
  - `DestroyNodeRecursive` returns while the node still has a parent (+0x54); otherwise it removes `children[0]` until none is left, destroying each child left without a parent, then frees the node. A node under two parents is freed with the last; world objects survive `DeleteTree %dbName%` because the world is their second parent.
  - `AddChildGeneric` 0x4484d0 appends to child and parent lists; `RemoveChildGeneric` 0x448660 keeps order.
  - `TryFreeNode` 0x447b60 queues a free (`CZNodeList::Insert` 0x44ed60, at the head) while `g_CZClass_DeferredProcessingEnabled` (0x4dded8) is 0 during runtime update passes (0x44eaa0, 0x44ebe0, 0x44ec30 [U]); a queued node's type-list link is only marked (`MarkPendingRemoval` 0x44eed0) and `FindByTypeAndName` does not skip it. `ProcessPendingFrees` 0x44eea0 frees from the head. A build frees at once.
- **Shipped data is inconsistent:** which `smoke1` binds differs between missions; several cross-links come from wildcard definitions applied to roots lacking the named node.
- **zStudio:**
  - The preview takes the highest live slot (freed slots keep names but are not nodes): `AnimationPreviewContext.ResolveRoot` with the binding chain (`NameLookups.RootPositions`, entry state +0x98), its whole-world fallback, effect templates, the texture-cycle lookup in `Textures.cs` and the mission's AI vehicles. Load-time lookups see only the world file's nodes.
  - Check and export report ambiguous supported whole-world lookups (`WorldLookups`) and which bindings an export or edit changes: literal texture-script names, animation roots, fallback references and prerequisite roots. Runtime macro operands, successful subtree bindings and other resource categories are outside the report.
  - Exports must give every node its shipped slot, so every lookup the game makes by name finds the shipped node (animation roots and names, attach nodes, prerequisites, `tex_fx` `FindNode`, `effects.zrd` templates, `ai.zrd` targets and deactivations).
  - A refactor that changes a binding (renaming the m2 dish, one `smoke1`, restricting wildcards) changes shipped behaviour and must be stated.

### Build-tool loader

How the lost build tool's `LoadGameGen` loaded a file [D, from the shipped slots and free lists]:

1. Each file the records reference is loaded once into a cache in order of first reference (also among a reference's own records): loaded on its own (its caches, instance definitions, a root, its records), kept to the end. A file named by two paths is cached twice: in databases (1999 m8 `frntbrdg.flt`; m1 `veg1`, `veg2`, `gullfly`, `pier`) and inside models (`comanche.flt` names `hturret.flt` by two paths; 1999 m4 `chemplnt.flt` names `chempipl.flt` by two). A referenced file without nodes caches a root alone.
2. Instance definitions: a node reached along more than one edge (an unnamed OpenFlight instance definition) is made once with its subtree; instance references attach it without making nodes (1999 m9's unnamed node under `sgate1`…`sgate8`).
3. The load's root.
4. The records in order, a node then its children. A reference's content is copied from its cache after the next record's node is made; a reference with records of its own is copied at once, before them. When a reference is the file's last record, an end node is made for the copy and freed after it. A copy expands instances along every edge, so a cached file's identical unnamed subtrees are one definition again (1999 m1 `rktpad.flt` `r_blst1`…`6`, `smkring.flt` `s1`…`s8`).
5. A cached file's own caches are freed when its load ends; the outermost load's caches when it ends, in creation order, each as `DestroyNodeRecursive` frees it.

- Slot allocation is separate from member encounter order: flattening database groups keeps authored child order (a referenced part before the following record); 1999 m3 (`dish_1`, `dish_q4` before `fog_switch_03`) and m5 (the last part's objects before `g426`) show both orders [D]. Preserve both independently.
- The root and first records take the slots the caches' own loads freed and nothing took again, last freed first, before fresh slots (1999 m13 begins on `walldes1.flt`/`walldes2.flt`'s freed cache slots; m5 on its last caches' slots; m2 on slots several caches left).
- A copy shows a file's records but not always where its groups closed: a group's last objects may follow it; the cache frees them in its groups' order, which settles it (1999 m1, m4, m13).
- Two later loads of one file under one name cannot be told apart in the world; the database's caches decide (1999/1998 m1 `rfpg_mzl.flt`).
- **Models** are made when a file is read, by a cache's load or the file's own load; a copy uses its cache's models [D]; rebuilt worlds must share each model among exactly the shipped nodes. Copies of one cache share models, as do the game's AI clones of a template (sharing scroll, morph and texture-cycle state). Each cache has its own models, also for a file read again by another file's load (1999 m1 palms; m4/m12 warehouse pieces 28 times). Each object read has its own model, even with equal values (1999 `redsprks.flt`). A world stores models in creation order (caches before records); turret guns and some groups (2–28 nodes per mission) got theirs after their children's, and 1999 m3's `rfpg_mzl.flt` model precedes the database's records: not reproduced, affects nothing in game.
- Where the slots fit several references as the one that made a second cache, the models decide: 1999 m5 `btundr1.flt` copies under `tun_door_01`/`02` share models while `tun_door_03` has its own (zone 11 vs 6), so the third reference named the second path; m3 `lturret.flt`/`pturret.flt` likewise (both releases). 1999 m1 `fgull08`/`fgull09` copy the cache `fgull07` made; m4's `chemplnt.flt` names `chempipl.flt` by its second path four times.
- **Mission databases were several files** [D]: the database referenced files holding parts of the world (groups, objects, references, sometimes parts of their own; 1999 m5's first part holds a reference to a part of `comctr` and `tunl`, then the radio towers). The reference is a group the build deleted; its part is cached and copied like a model (1999 m1 `dock1`, `dock2`, `dock_house`; `g307`, `g306`; a 302-node part; m13's teleport and terrain parts).
- Deleted names are lost except where slots stayed free: every shipped world but m6 is dense. 1999 m6 keeps 287 freed slots (`g219`, `street`, `hole01`, `phone.flt`, `db` …); its first cache (city part) names five groups, `street`, `ramps`, `bwall`, `phones`, `hydrants`, each freed straight after its objects' slots; reconstruction names those groups so (both releases).
- **m2:** its records start on slots several caches left (553–573, 726–756, 914, below the caches' high-water mark 916): the boundary is where the caches' simulation ends and gives back its mark. Its factory part's last ten objects are the next group's records, with `nturret1.flt` named by a second path in the shorter part; its last record is a part reference whose copy, after the end node, holds `labradio` alone. The fitting free list is the one where `comanche.flt` names `hturret.flt` by a second path. `world1` lists `mcar_01` … `mcar_06` first.
- **m6:** the free list is the reading where `comanche.flt` names `hturret.flt` by a second path. Its database load made 20 caches, 11 parts (the aztec, beach and lava parts hold a part each); the city part names `phone.flt` once by a second path; the brain part names `braintur.flt` once by a second path and closes a group before its last objects, as does the lava part. Its records begin on the 126 slots the last part's load freed (inner part cache, `dr02.flt`'s cache, its end node): first `horizon` and children, then the city part's reference and the group after it, whose copy runs on into fresh slots (1804 in 1999, 1799 in 1998). The bottom of the free list holds the first cache whole (402 nodes from slot 46). `db` (4787 in 1999, 4777 in 1998), the first slot freed, is the end node of the last part reference.
- Rebuilt worlds must keep the shipped parent-child structure (check with Compare worlds: no node changed, missing or extra).

## Craters and quicksand

- **Pipeline** [B, BN]: a weapon's `CRATER (min max)` hits a node with CanModify (0x10000); radius uniform in [min, max] (`MAX_CRATER_RADIUS` never applied; shipped 10–39). `declient.zrd` `CRATER` gives `POINTS 6`, `DEPTH 1.7` in every mission. The centre moves so the circle lies at least 1 unit inside the impact cell (`InitFeatureFromEventTemplate` 0x456c80 [BN]); the outline is clipped into the touched surfaces (`ClipPatch` 0x46b1f0 [BN]); the bowl is `n` quads and `n` triangles, centre 2 × DEPTH below the impact (`CreateFeature` 0x457140 [BN]).
- **Grid limit:** the feature grid is the cell grid; each 64-byte area record counts craters at +0x39 (0 in every shipped cell). A cell refuses a crater once its count reaches world byte +0x4C [BN] (16 in every shipped world, at most 255, `WorldPartitionMaxDECFeatureCount`); craters and quicksand share it. Nothing is evicted; a refused crater plays the normal impact.
- **No stacking:** refused when its outline box with a 5-unit margin overlaps an existing feature in the cell [BN]. The bowl node is ClipTo (`gwNodeSetFlag17` 0x447d70 [B]).
- **ClipTo blocks craters:** before cutting, the whole patch is cancelled if any polygon of an active top-level ClipTo node with its own model, in the impact cell or the overflow list, overlaps the outline in plan view, tested in model space (0x46B1F0, 0x46B550, byte-matched 0x46BB90). CanModify means "craters can form here", ClipTo (the developers' "no clip") "no crater may overlap this"; neither affects collision. Splitting a ClipTo node does not change the result; splitting CanModify surfaces changes how many crater models a crater creates. In plan view a ClipTo surface above can cancel a crater on a floor below.
- **What the test sees** (`ProcessNodePolygonSetXY` 0x46b550 [BN], `ClipPatch`): only the impact cell's top-level list (clamped to the edge cell) and the overflow list, overflow first; only active (0x04) nodes with their own model, every ClipTo before any CanModify (a node with both counts as ClipTo); no zone, gate, height, LOD or child test; model vertices with **no transform**. So a transformed or nested CanModify node never craters as placed (M2 `g502`/`g503` [D]); a ClipTo group without its own model blocks nothing (30 M2 bunker groups [D]); every overlapping CanModify layer is cut at any height (M4 `g659`/`g660` over `g671`/`g672` [D]).
- **Each accepted crater creates** one bowl node (ClipTo, gated, zone of the first touched CanModify node whose zone is not 0xFF [BN 0x46af40], polygons with count 0), one bowl model, and one replacement model per touched node holding a full copy of its polygons (`ApplyNodeDiPairs` 0x46ae40 [B]). Quicksand creates 2 nodes and 2 models. At radius 25, 88–100% of craters touch one node; at most 3 in M2, 4 in M4 [D].
- **Model limits while clipping:** replacement models are rebuilt polygon by polygon (`AddPolygonEx` 0x483650 [BN]); the polygon needing vertex 923 and all after it are dropped while the crater succeeds. Shipped growth is 6.5–11 vertices per crater per node (at most 26), so 16 craters reach 291 at worst [D]. Crater models carry no normals; clipped pieces get UVs from a flat projection of their first three corners, rounded to 1/256. A crater inside one polygon goes through `TriangulatePolygonWithHole` 0x46c070 [BN] (32-entry edge stack, no bounds check).
- **Saved games:** saving writes each crater's template (`WriteFeatureSectionsToZAR` 0x457b40 [B]); loading reloads modified nodes' models from `gamez.zbd` by slot, deletes bowls, resets counts and replays (0x457c10, 0x457750 [B]). [U] a road crater may return with the default crater material (matched by address). Animation states save with node slots (`NodePtrToValidatedIndex` [U]), so retail saves keep working with exports that keep shipped slots.
- **Multiplayer** [U]: a crater event names its material by index into the world's material table (`craterTypeId`, `IndexFromPtrOrMinus1`), unchecked on the receiver. Rebuilt worlds order materials differently and omit unused colour materials, so they are not crater-compatible with shipped files (owner decision: not needed).
- **Retail bugs** [BN]: a clip failing partway leaks built models; `ClipPatch` sizes its result by the cell's node count but also clips overflow-list CanModify nodes (none shipped [D]).
- **Crater-capable terrain:** top-level nodes with their own model and identity transform, in a cell (never overflow); at most about 450 vertices per node (16 craters within the 922 budget); convex, upward, UV-mapped polygons of at most about 30 corners; cells at least 2·Rmax + 2 wide (80 for shipped weapons); overhang under 1 unit; one CanModify layer at any point.

## Runtime capacity

- **Pools** are fixed arrays with free lists; nothing grows during play. `initmN.gw` sizes only the first allocation (16000/6000/5000 in every shipped script; defaults 8250/1750/2500: 0x451900, 0x475e70, 0x480ae0 [B]); the world file's pool headers and free chains then replace them (0x455350, 0x481fa0, 0x4808c0 [B]). Usable capacity is the exported file's free chain; every shipped world stores 16000 nodes, 6000 models, 5000 materials [D]. No engine maximum except 32767 materials; zStudio's 65,536-node clamp is its own.
- **Copy cost** (`CopyNodeDispatch` 0x452400, `CopyNodeDisplayInstance` 0x451b20 [B]): single-player vehicle clones nodes only (sharing the model); pickups nodes plus a model per node that has one; effect instances and network vehicles nodes, models and materials. Light, sound, animate, sequence, switch and world nodes are never copied: `CopyObject3DNode` (0x452100 [B]) skips a child yielding no copy; camera and LOD copying return null on a null child (their parent skips them; made nodes leak). A node flagged 0x04000000 is returned itself, uncopied.
- **Load consumers:** vehicle clones (25–35 nodes each; m6's 143 use 4,342 [D]); pickups; one runtime node per animation entry plus light/sound nodes; the projectile pool Σ(trunc(range × rate / speed) + 1) + 9 = 455 nodes in every mission [D] (0x4b1190 [BN]); effects. **Play consumers** (kept until unload): effect instances at peak concurrency, extra concurrent animation instances (never freed), pickups dropped by killed vehicles, craters, material clones (never freed, `zDi::FreeContents` 0x482160 [B]).
- **Running out is silent** [BN]: `gwNodeNew` returns 0 (objects, effects, animation instances skipped); a model shortage leaks the copy's node; materials fall back to default white.
- **Fixed tables:** texture directory 4,096 entries, runtime appends unchecked (0x46d810 [B]); model vertices: `AddOrMergeVertex` (0x482720 [B]) merges within epsilon and refuses a new vertex past 0.9 × 1,024 (no shipped model passes 921 [D]); 64 active lights per frame (0x487a30 [BN]); 254 light and 254 sound references per animation entry; 32,767 nodes per cell; 16 craters per cell; 256 transparent polygons per frame (overflow dropped).
- **Shipped headroom after load** [D]: nodes tightest m6 5,091 free (32%; m1 7,595, m8 14,342); models ≥ 3,970; materials ≥ 4,327; texture directory ≥ 3,283.
- **Budget:** node capacity ≥ stored live nodes + animation entries' nodes + projectile pool + about 6 fixed + AI clones and pickup placements (minus turret helpers freed at load) + a reserve for effects, concurrent animations, drops and craters (cells × min(16, expected)); models and materials alike. zStudio does not validate these budgets yet ([roadmap](roadmap.md#open-gaps)).

## Vehicles

- **Lookups:** vehicle code uses `FindSubNodeByName` (0x452770 [B, BN]), a depth-first search of one subtree: the node, then its children last to first, each before its own children; animations (`ResolveNodeByName`) first to last, then the whole world. A repeated role name can resolve differently for each; no shipped vehicle repeats one [D].
- **Roles:** `rtracks` and `ltracks` must be separate textured models; each scrolls its model along **V** at 1.72 × the side speed (forward speed ± yaw × 2.25) [BN 0x42704e] (the reconstruction's U is wrong); `rtracks`' first material switches its cycle frame by `track_switch` thresholds; an `rtracks` without a model crashes. `chassis` rotation is overwritten every tick with pitch and roll in track mode [BN]. `turret` (yaw) and `gun` (pitch) have their whole rotation overwritten every tick (`UpdateGunAndTurretAimNodes` 0x43a4f0 [BN]); pivots are their origins.
- **Fire points:** `fpnt_c`, `fpnt_l`, `fpnt_r` under `gun`, offsets in the aim basis (any model on them is detached); without `gun` or `turret`, shots leave from the root plus (0,1,0). `firepoint` does not exist in the executable; only turrets name fire points, through `ai.zrd`.
- **Helpers:** `collide00`–`collide11` and `support00`–`support03` give only their local position, then are deactivated (0x421ed0, 0x4220f0). Collide points are read only when `vehicle.zrd` has no `collision` list, and only from the first clone; supports are read for every clone and override a `platform` list. Shipped numbering: collide 00–02 front, 03–05 right, 06–08 rear, 09–11 left; supports front-left, front-right, back-right, back-left; every shipped helper is an untransformed direct child of `healthy` [D]. `target` adds its local position without the vehicle's rotation.
- **Mode parts:** track `chassis`, tracks, `dust_l`/`dust_r`; amphibious `wake`, `splash_l`/`splash_r` [U]; submarine `props` cycle speed and `caustic1` cycle; hover `shadow` only. Morphs are driven by mode-change animations.
- **Clones:** the template is the AI vehicle name up to its first `_` followed by a digit (0x423150 [BN]): `ltank_2_05` spawns `ltank`, the `*_2` templates are never used. Single-player clones share the template's model (track scroll, morph and texture-cycle state); only transforms and active flags are per copy.
- **Animation lifecycle:** `start_anims` runs once per created vehicle as its own instance on that clone (0x420d10 [BN], `ActivateRuntime` 0x45d930 [B]); mode changes never touch it; death never stops it (death sequences hide `healthy`, so a loop under it runs invisibly); `STOP_ANIMATION` by name stops only the base entry, the first-spawned copy's instance (`zEffectAnim::Stop` 0x45c040 [BN]); respawn never re-runs `start_anims`; saves restore sibling instances onto the base entry (0x461040 [U]).
- **Weapons on the gun** (the player tank; preview: [player tank](preview.md#player-tank)): the template's `common_mode` `weapons` list (`LoadMasterCommonDataFromNode` 0x422170 [B]) holds key, mission threshold, dual mount, start ammo, repeat delay, AI ranges, recoil flag and hardpoint state; the key's characters 4 and 6 are bank and side (`wep_2.0` bank 2, side 0; 0x438ba0 [B]). `gun` is found with `FindSubNodeByName` (`CacheGunHardpointsAndDetachDisplays` 0x4390d0 [B]); a weapon's model is the node named by its `weapons.zrd` BALLISTICS `NAME`, else its key (zwep_init.c 582–587 [B]), with `_L` and `_R` for a dual mount, found under `gun` by `FindNodeRecursiveByName` (0x447bc0 [B]: the node, then its children first to last, depth first). `LoadWeaponBanksAndSelectDefaults` (0x438ba0 [B]) switches off every listed weapon's model, makes the first listed weapon the mission allows the secondary and the second the primary (single player; `CheckMissionWeaponAvailability` 0x43ca90 [B, BN]: threshold ≠ 0 and ≤ mission), and switches the secondary on; `ApplyPrimaryWeaponSwitch` (0x439600 [B]) switches the primary pair. Bank 1 holds the primaries (RFPG 1.0, ERFPG 1.1), banks 2–9 the secondaries; `Pickup::ApplyEffect` (0x41d220 [B]) grants the pickup catalog's weapon types 0x11–0x21 to 1.1, 2.0, 2.1 … 9.1 in order. Shipped [D]: the BFT list is the same in `vehicle`, `vehicle_easy` and `vehicle_hard`, 1998 and 1999, and starts with `wep_2.0` (HEM, threshold 1) then `wep_1.0`, so every fresh mission starts with HE Mortar and RFPG; every shipped BFT gun holds all 13 models (RFPG and ERFPG pairs, HEM, MDM, P-HEM, P-MDM, NAPALM, FREON, LASER, LASERD, ARC, `sonic`, LO-EM); the remote mines reuse P-HEM and P-MDM, the four missiles and nukes LO-EM; `wep_9.2` (LO-SM) is not in the BFT list and no gun has its model.
- **Weapon pop-up** (`TickAltGunRuntimeState` 0x439ba0 [B]): a selected single-mount secondary is shown 0.4 lower at scale (1, 0.6, 0.6), the turret doors (`doorleft`, `doorright`, `FindSubNodeByName` in 0x420d10 [B]) scale X down to 0.001 over 0.25 s, then the weapon rises to its stored position at scale 1; settled, the doors stay collapsed. A dual-mount secondary, or one without a node, leaves the doors closed. A RELOAD weapon with ammo also hangs its FLYOUT `MODEL` template on the weapon node (`AllocOrReuseAttachNodeClone` 0x4ae530 [B]).
- **Sub-mode weapons:** `IsAltWeaponAllowedInCurrentMasterMode` (0x43c630 [B]) forbids in sub a secondary with `BEAM` (present: flag 0x02) or `CATCHES_FIRE` (bit 0 of its value: 0x1000) (zwep_init.c 614–626 [B]): LASERD, LASER, ARC and NAPALM. Entering sub switches away from one (`TransitionToMasterTypeSub` 0x42b2a0 calls `AutoSwitchToNextUsableAltWeapon` 0x43c660 [U]): the bank's other side when owned, allowed and loaded, else the nearest lower bank down to 2, else the nearest higher, with a usable weapon; another bank is selected on its remembered side (`HandleAltWeaponBankSelectInput` 0x439260 [B], which only refuses CATCHES_FIRE in sub); the load sets every remembered side to 0. With every weapon owned and loaded [D]: Napalm → Freon, Laser Designator and Laser Sabre → Remote Mine, Arc Sabre → Sonic Burst.
- **Master type:** a mode block's `mode` is matched on its first two characters (`LoadMasterModalDataFromNode` 0x4226d0 [B]: sub 2, track 3, hover 4, amphib 5); the first block is the starting mode (0x4384e0 [B]), track for the BFT [D]. `ApplyMasterTypeTransition` (0x42b520 [B]) takes the change's list from the current mode's block (`t2a_anims`, `t2h_anims`, `a2s_anims` …; every BFT block lists the same eight [D]): at most two names (`PlayerLoadModalFxList`), found by name when the animations load (0x45ff10; a missing name starts nothing), started in one frame on the vehicle root, entry 0 then entry 1, through `ActivateRuntime` (0x45d930 [B]: rebound at the root, prerequisites checked; a flag-0x20 entry's cleanup runs first only when the entry is not already stopped, and the load stopped every one, so the first change runs none), only when the change plays its effects (flags 0; a carried save uses 1 and skips them). With flags 0 sub is reached only from amphibious, so track → sub is `t2a_anims` then amphibious's `a2s_anims`. Code, not the entries, sets height (sub dives 4.1, hover and amphibious float), trails and the props' speed. Shipped [D]: m1's animations have no mode entries; m2 has the tracks and amphibious ones; m3 and m4 add hover; m5, m6 and m7–m13 all eight (1998 and 1999). Each `X_to_none` morphs its parts to 1 and switches them off, each `none_to_X` switches its parts on and morphs them back to 0, except that m2's `wings_in` and m3's and m4's `wings_track` stay shown folded (morph 1) after `tracks_to_none`.
- **Vehicle authoring requirements** (for the planned upgrade workflow, [roadmap](roadmap.md#upgrade-vehicle)): unique role names in the subtree; textured `rtracks`/`ltracks` with the tread along V; identity rotation and origin pivots for `turret`, `gun`, `chassis`; geometry-free, unrotated helpers directly under `healthy`, numbered as shipped; `fpnt_*` under `gun`; spinning parts under `healthy` with constant-rate loops, never stopped by name on clones; `props` an empty pivot or its cycled model. Upgrading `ltank` changes every `ltank_*` placement.

## Animation runtime

- **Activation prerequisites** (`CheckActivationPrereqs` 0x45db20 [B, BN]; path binding in `LoadZbd`): each 48-byte record has an optional-group flag at +0 (0 required, 1 option) and mode at +4. Mode 1 stores an animation name at +8, satisfied when that entry's activation state is not 1. Modes 3/2 store node names at +12; 3 continues a node path, 2 terminates it and resets the lookup root. Only mode 2 uses the Int32 at +8, an expected active bit compared with `(node.flags >> 2) & 1`: `OBJECT_ACTIVE_LIST` must write 1 there (0 reverses the condition). Required mismatches refuse activation; optional matches count toward the minimum at +268. A mode-1 name no entry has refuses activation; a mode-2 node the load could not bind is skipped. `ActivateRuntime` checks them on every start (calls, hits, startup) except the `NEW_GAME_START` list, which clears them permanently (0x45d7a0 [B]). Original 1999 archives: 27 terminal checks in m6 (three warm thresholds of 1, three hot of 2, three required destruction groups), three in m1 (`one_rocket`, `two_rocket`, `warning_sound`), all expecting 1; `destroy_a1boss` has three required mode-1 prerequisites [D].
- **Events** (`RunSequenceEvents` 0x45CC00): start mode 1 uses entry elapsed time, 2 sequence elapsed time, 3 time since the preceding event; timed handlers pass their unused frame slice on. The primary sequence is used by cleanup/stop callbacks and does not run alongside runtime sequences; state 3 waits for release and resets to waiting on completion. Event 0x16 releases a waiting sequence, 0x17 stops one (historical handler names reversed); in a cleanup both resolve against the runtime sequences, which do not run then, so they have no effect (shipped: `m1_start_animation`'s cleanup stops `start_the_semi`) [B, D]. 0x19 stops, 0x1A resets, 0x1B invalidates an animation by name (below).
- **Entry states** (`activationState` [B, BN]): 0 never run, 1 stopped, 2 running, 3 finished with its final pose kept, 4 invalidated, 5 unavailable (corrupt), 6 running and invalidated. Every shipped entry stores 0, and the load stops every flag-0x20 entry, leaving 13–30 per mission in state 0 [D].
- **By name** (0x19 `HandleNamedAnimStopEvent` 0x45c100, 0x1A 0x45c1a0, 0x1B 0x45c240 [B, BN]): each acts on one entry, the first in entry order with that exact name (its index cached in the event; a match at index 0 is never acted on), on its base record only, never runtime clones or other entries of that name. Shipped missions hold 5–12 repeated names each (`spark_blue.flt` ×3, m3 `belev_rsnd` ×2, m10 `fire_always` ×5) [D].
  - **Stop** (`Stop` 0x45c040 [B]) acts only in states 2 and 6: a `RESET_TIME` ≥ 0 replaces the entry's frame callback (its sequences freeze at once) and resets it after that time (0 at once, in the same event); a negative one finalizes it at once without cleanup or restore: state 3, or 4 from 6. Natural completion calls the entry's callback with 0, then `Stop`.
  - **Reset** (`zEffAnimReset` 0x45d6b0 → `StopAndCleanup` 0x45d570 with immediate cleanup [B, BN]) in any state except 1 and 5, never-run, finished and invalidated entries included (m6/m13 `reset_the_transporters` resets finished `bft_to_*` [D]): restores the rest pose, runs the cleanup's zero-time events at once and its timed ones per frame, then `FinalizeStop`.
  - **Invalidate**: state 2 becomes 6 (it keeps running, its loops continue, a `WAIT_FOR_COMPLETION` caller keeps waiting, a stop still works), any other state except 5 becomes 4. `ActivateRuntime` refuses states 4–6, so the entry never starts again in that mission (calls, hits, startup); a reset still runs its cleanup. 1,123 shipped destructions invalidate themselves (one-shot destructions); 45 invalidated entries loop for the rest of the mission (m1 `hologuide` invalidates `nbfrc_field`) [D].
- **`FinalizeStop`** (0x45d3d0 [B]): frees the entry's lights and sounds; stops each child cached by a `LOCAL_NAME` launch (call record +64 = 1; each launch clears the slot, then caches the child it started: `CALL_ANIMATION` 0x45bc60, `CALL_OBJECT_CONNECTOR` 0x45b8b0), each by its own `RESET_TIME`, whether the launcher completed, finished a delayed cleanup or stopped with a negative `RESET_TIME`; re-arms the hit countdown to `HEALTH`; state 1 (6 becomes 4). Waited-only children are not cached. Shipped `LOCAL_NAME` uses (15): enemies' `fire_40` `hulkfire` (also waited), m1 `call_rocket1N` → `countdown_from_9`, m2 `powvoice` countdown, boat wake connectors [D].
- **One-shot:** `RESET_TIME -99` is refused while running or finished (state 2 or 3; `ActivateRuntime` 0x45d930 tests |value + 99| < 0.1 [B]). Shipped: m1 `one_rocket`, `two_rocket`, `three_rocket` [D].
- **Keyframe segment** (event 0x0C: `AdvanceKeyframe` 0x45b120, `AnimateKeyframeSample` 0x45ae90 [B]): a 12-byte interval header and 28 bytes per enabled channel; each frame evaluated from its own base with τ = min(elapsed, t1) − entry: position P0 + V·τ, scale S0 + G·τ (no clamp; event 0x0B clamps scale at 0.001), rotation exp(Ω·τ) ⊗ q0 (`zMathQuatFromRotationVector` 0x475b80 [BN]: true square root, sin/cos of |Ω·τ|, so Ω is a half-angle rate); then quaternion → matrix → Euler (0x475a80, 0x474e10 [BN]) and the local matrix is rebuilt from TRS. Nothing is normalised; the node keeps no winding. A segment's sample cursor advances from the event start (0x45B120/0x45AE90), so a reversed span (end before entry) finishes as soon as it starts and is skipped when a same-channel successor has begun; otherwise it samples its negative end-minus-entry local time (shipped RECOIL `m3pickup` streams have such spans).

### Between segments

- The runtime reads only the next segment's channel flags, never its values: a channel the next segment does not key holds the current end value. Continuity is the compiler's job.
- Shipped [D]: 176 events, 14,747 segments (largest event 520); shortest segment 0.04 s; largest rotation in one segment 159°; jumps of up to 1.8° between segments come from the original compiler's approximate spin, which the SI compiler reproduces.

- **Time:** the frame step comes from `GetTickCount`, capped at 0.125 s (`Time::Tick` 0x4a56d0 [BN]). An event starts with the frame's remaining time, so its τ = 0 pose is never shown (0x45cc00 [BN]); a loop drops up to one frame per iteration; range/zone-paused animations do not catch up; `SCRIPT_FRAME_RATE` matters only to the compiler.
- **Morph** only by event 0x0B (`AnimateNodeOverTime` 0x45a9d0 [BN]): the factor advances at its rate and snaps to the end; above 1 clamped to 1; below 1e−5 the morph is switched off but the value kept (can go negative). A LOD with a range fade overwrites its descendants' factor every frame (0x44b8c0 [BN]); no shipped morph sits under one [D]. Geometry is base vertex plus morph delta × blend scale.
- **Opacity:** events 0x0D/0x0E control opacity and its override state. `gwObject3DSetLitFlag` toggles bit 2, which `RenderTraverse` 0x44B300 uses to push an alpha override for the subtree; stored opacity without that flag is ignored; the nearest active ancestor override is inherited.
- **Texture frame:** event 0x11 calls `SetCurrentVariant` 0x4842B0, selecting a texture-cycle frame.
- **Reset:** the rest pose is captured at load and at every activation (`CaptureNodeStates` 0x45d240 [B]) and restored on every `zEffAnimReset` path: a stop or completion with `RESET_TIME` ≥ 0, `RESET_ANIMATION`, and the callback-20 key skip (`StopAndCleanup` restores when flag 0x40 is set, which `zEffAnimReset` sets at run time; no shipped entry stores it) [BN 0x45d6b0, D]. Load and activation cleanups run without the restore. A negative `RESET_TIME` keeps the final pose. Restored: the tracked nodes' active flag and transform, morph off; opacity, texture variant, parenting and camera values are not restored.
- **Starting a running animation:** `ActivateRuntime` 0x45d930 [B] does not start an entry already running (state 2) without a target node unless its copied root is attached to the world (runtime flag 0x100, which starts a clone); with a target node where it already runs it is refused, elsewhere an idle sibling or new clone is bound there. `ON_STARTUP`, the `NEW_GAME_START` list and child launches (event 0x18, `HandleSurfaceRefEvent` 0x45bc60 [B]) all start through it.
- **Mission load:** `LoadAndInstantiate` 0x45fb30 [B] stops each entry with a single `RESET_TIME` (flag 0x20), running its cleanup at once (`StopAndCleanup` 0x45d570), and only marks each `ON_STARTUP` entry running; vehicles, turrets and pickups load next; `RunStartAnimsFromZrd` 0x4192d0 [B] clears each `NEW_GAME_START` entry's prerequisites and marks it running. No event runs before the first frame (`RunSequence` 0x45d010 [B]), so every load cleanup precedes every started entry's events. In the first frame callbacks run by priority (`UpdateAllBuckets` 0x44ea70 [B]): m2–m6 start animations (priority 1) before `ON_STARTUP` entries (4). m6/m13 transporters (`bft_to_*`) and `reset_the_transporters` start each other at zero time; each starts once [D].
- **Cleanup on activation:** `ActivateRuntime` runs `StopAndCleanup` on a flag-0x20 entry before starting it; nothing for an entry already stopped (state 1, `FinalizeStop` 0x45d3d0). In practice that is state 3, a finished entry with a single negative `RESET_TIME` (682 shipped `RESET_TIME ( -1 )`): its cleanup runs without the restore (except for a fresh clone of a running world-attached entry), then the rest pose is captured (`ResetForNode` 0x45d6c0 [B]); m1 `call_rocket1N`'s cleanup resets `rbody00`'s active flag, rotation, translation and opacity before each relaunch from `loop_rocket1` [D]. A cleanup still timed at the start is abandoned. No shipped cleanup outlasts zero time [D]. A clone's state is copied from the running entry (`CloneEntryForNode` 0x45e730 [U]).
- **`EXECUTION_BY_RANGE`** (flag 0x02): `RunSequence` runs a started entry's events only while the reference position is set and in range: squared 3D distance from it to the callback node's world position (`GetConditionalRefPosDistanceSq` 0x45c640 [B]) at least the minimum at +0x9C and below the squared range at +0xA0. The reference is the local player's position: `InitMissionRuntimeFromWorldAndCamera` 0x41fe90 [U] makes the first created vehicle (first AIV record whose template the vehicle resource defines) the local player and stores its spawn with `SetConditionalRefPos` 0x458af0 [B]; m1–m13: `bft_00`, same place in every difficulty [D]. Every shipped entry stores minimum 0 and 2 at +0x9B, a frame delay gated entries count down first [D/U], so the first test is in the third frame. The player starts outside the range of all 90 range-gated entries [D] (closest m2 `m2_exit_trigger` 162 units/range 5.5, m5 `active_helipad` 235/120). Only `RunSequence` is gated: a stop delay and a cleanup run anywhere, a paused entry's clocks freeze, and retests are staggered 1 to priority × 10 / 4 frames apart [B].
- **`EXECUTION_BY_ZONE`** (flag 0x08): `RunSequence` runs the entry only while the camera's last complete zone set (at least one zone, none 0xFF: `UpdateCameraVariantFromCameraPos` 0x406470 → 0x458b20 [B]) allows the callback node's zone byte (0xFF always passes); before the first complete set the entry never runs; retests are staggered 1–10 frames apart [B].
- **Player reference over time** [B]: `SetConditionalRefPos` (0x458af0, from `InitMissionRuntimeFromWorldAndCamera`, player.cpp:6897) sets it to the local player's position, the exact XYZ of the first spawning `aiv.zrd` record (the spawn probe 0x421830 leaves it); `TickMasterTypeAndForceFeedback` 0x4266b0 then updates it every vehicle tick while the control type is not inactive or suspended. In the m2–m6 openings callback 11 suspends the vehicle, so the reference stays at the AIV start while the hidden tank moves; callback 10 (`SyncLocalPoseFromRootNode` 0x42b810) copies the tank root's pose and restores player control, so that frame's vehicle tick makes the reference the drop-off pose; callback 17 likewise from the tank root (elevators, m13 transporters). m1's opening never moves `bft_00`. `m2_do_exit_trigger` (`PLAYER_RANGE 27` around `vtol1`, polled every frame) keeps the VTOL waiting while the player stands at the drop-off [D].
- **Conditions** (`HandleConditionalChainEvent` 0x45c3c0 [B, BN]), operand bits tested in the order 0x01, 0x02, 0x08, 0x10, 0x04:
  - `RANDOM_WEIGHT` (0x01): one draw from the global 200-entry table at 0x575a80 (index 0x53a244, advancing mod 200), true when the draw ≤ the weight. The table is refilled from `srand(time(0))` at every `zEffInit` (each mission load) and its index never resets, so in the game the outcome is random (p ≈ weight) and not reproducible; procedural launches share it (four draws per `OBJECT_MOTION` flag 8, 0x459e70). An IF and its ELSEIF both draw.
  - `PLAYER_RANGE` (0x02, r² stored): needs the reference enabled; squared 3D distance from it to the world position of the entry's callback node (attach node: `ANIMATION_ROOT_NAME`, else the root) ≤ r² (0x45c640); an unreadable position reads as distance 0, true. 31 shipped definitions attach elsewhere than their root (enemies' `healthy`, m3/m6 elevator `btrig*`, m4 `kill_bft`, m1 silo, m2 `bramp`, m6 `my_butt`) [D].
  - `NODE_UNDERCOVER` (0x10, node, d): `TraceUpwardHitFromNodeOrPos` 0x45c530 traces a segment from the node's world origin straight up by d (the stored value; 50 only without one) with `RaycastFindClosest` 0x444e90: nodes active (0x04) and intersection surfaces (0x10) at every level, in the current zones, skipping any node flagged 0x40000; the first candidate ends the search. The tested node's 0x10 is cleared during the test (its subtree is skipped) and set afterwards unconditionally. A polygon is hit when the segment crosses it from its front, or from either side when it shows its back face (`BuildPickCandidateForSegmentVsPolygon` 0x4857f0). An ELSEIF `NODE_UNDERCOVER` tests the node of its chain's IF (the handler keeps that event's node index).
  - Bit 0x08: the same upward test from the reference position (needs it enabled); no compiler keyword, no "UNDERCOVER" string [BN].
  - `ANIMATION_LOD` (0x04): the effects level ≥ the value (HIGH 2, MEDIUM 1, LOW 0); `SetEffectsLevelForCurrentHwMode` 0x407f30 maps the Effects detail option High 2, Medium 1, Low 0; Direct3D defaults to High, the software renderer forces High to Medium (RecoilApp.cpp:960).
  - Branching: a false test scans forward, depth-unaware, to the first ELSE (0x20), ELSEIF (0x21) or ENDIF (0x22) or the end; an ELSEIF found by the scan is evaluated at once (its START_TIME ignored); a taken body reaching ELSE or ELSEIF waits for that marker's threshold, then skips to ENDIF. No nesting is shipped. Each `LOOP` pass resets the cursor to event 0 (IFs are evaluated again) and ends the sequence's work for that frame, so a polling loop tests at most once a frame; an `ON_CALL` sequence evaluates again on each release.
- **`CALLBACK` values** (`Player::AsyncCommandCallback` 0x42bb30, player_state.cpp:1076 [B]; attached at mission start to every entry with a CALLBACK, flag 0x10, `FindNextAsyncEntry` 0x45ffa0): 0 sent when the animation finishes (clears the skippable mark); 1 rebinds the game camera to the player and re-aims the chase camera (12 shipped uses); 2 releases the camera from the player (single player), HUD, reticle, top and chat lines off (11); 10 takes the player's position and heading from the tank root, normal control, top and chat lines on (12); 11 suspends the player vehicle (single player): no driving or physics, position frozen, engine loop sound off (10); 14 takes the controls away (single player): HUD, reticle, mission timer off, all turrets paused in every mode (12); 15 gives them back: HUD per options, reticle centred, the selected weapon's name for 5 s, mission timer runs, the m1 first-objective power-up sound, turrets resume (12); 16 stops the player vehicle, velocities and inputs zeroed (0); 17 moves the player's restart point and pose to the tank root (teleports, elevators, m13 transporters) (16); 20 makes the animation skippable: any key resets it (restore and cleanup; ends an opening) (6, each `mN_start_animation`); 25 empties the nanite reserve, then destroys the player (2); 26 destroys the player, damage = health + 1 (1); 27 deals 10 damage to the player (5); 99 mission complete: saves state, queues the next mission's film (after the last: credits, quit) (6 exit animations); 911 VTOL airdrop: drops the next VTOL pickup at the airdrop point if 20 units are clear (9); 912, 913, 914 spawn pickup types 32 (Lock On Nuke Launcher) at `vwbus`, 36 (Nano-Canister) at `crbox`, 30 (Lock On Missile Launcher) at `drop`, one each (2, 2, 1; names follow zStudio's catalog order [U]; `SpawnAtCarrierNodeByName` 0x41ea30: whole-world lookup, newest node first, node rotation); any other value does nothing (use counts [D]). Entries other systems start (pickup collection, airdrop chute, turret `FIRE_ANIM`, player death and respawn, weapon flyouts) get those systems' handlers, which receive every value including 0 and (those checked) ignore it [B].
- **Hit activation:** `WEAPON_HIT`, `COLLIDE_HIT`, `WEAPON_OR_COLLIDE_HIT` entries count down +0xB0 through their attach node's callbacks and start at 0 with no target node (`TickResetDelayOnHit` 0x458bb0, `TickResetDelayOnTimer` 0x458b50 [B]). `WEAPON_HIT` installs a damage handler on the attach node and every descendant without one (the first installer keeps a node; animations install before turrets and vehicles); each hit subtracts its damage. `COLLIDE_HIT`: each vehicle contact tick deals 5 · |v|² / maxSpeed² (`ProcessTransferContactQueue` 0x424d00); while the countdown is above 0 it is a normal collision, at 0 or below the vehicle passes through [B]. The loader keeps the stored countdown [U]; only a stop copies `HEALTH` (+0xAC) into it (`FinalizeStop` 0x45d3d0 [B]). Shipped entries store `HEALTH` in both [D]; with 0 stored, an entry without load cleanup starts on its first hit (1999 `destroy_vtol1`, `vtol2` m1–m5, m6 `vtol1`: 15 damage).
- **Game-driven nodes:** callbacks run by priority 0–5, last writer in a frame wins: vehicles tick at 2 (0x420057 [BN]); animations default to 4 (the 34 shipped definitions at 1 are overwritten); turrets aim at 1. Rotating or scaling a node with an authored matrix discards the matrix.
- **Procedural launch and gravity** (`zEffect::HandleNodeAnimEvent` 0x459E70, read directly in retail; the reconstruction's temporaries are swapped and its initial gravity branch wrong): random ranges at bytes 32/40/48/56 are yaw, pitch, speed and radial acceleration, in that draw order; 0x474580 rotates the **−Z** forward direction. Motion flag 1 adds the signed gravity at byte 24; flag 0x2000 applies the transposed world basis.
- **Ground contact** (0x45A4DB–0x45A6C0): contact gates both waiting-sequence release (flag 0x800, name/index at bytes 208/240) and impact audio (flag 0x1000, positive sample index at byte 242). Velocity is damped by `0.199999988f` unless its squared magnitude is below squared acceleration, which completes the motion. Gain uses post-damping speed and the threshold at byte 244, falling back to gravity (byte 24) × 10 for a negative threshold. The reconstruction wrongly leaves the sound branch outside the contact gate.
- **Procedural surface query:** `HandleNodeAnimEvent` (0x459E70, collision branch 0x45A401) clears cell-pickable bit 0x08 on the bound assembly during `FindNearestPickCandidateBelowPoint` (0x45A920), then restores it. The query uses the moving node's world origin, not mesh vertices or its footprint. `BuildPickCandidateListBelowPoint` (0x443D20) updates queued display trees before querying current eligible geometry. Only negative Y displacement can clamp: crossing the candidate height replaces Y displacement with surface minus origin, plus half the absolute original Y displacement when either horizontal velocity component is at least 0.100000001. Missing candidates accumulate descending time for untimed motion; over 15 seconds completes/clamps it through the same release/impact branch. There is no permanent mesh-support latch preventing later authored sinking [B/U].
- **Cameras:** `CZNode::gwNodeBuildNodeToAncestorMatrix` (0x449480, camera branch 0x4496AE) uses +0x20 as Euler angles and +0x14 as translation; flag 2 uses the cached matrix. `CZCamera::BuildWorldTransform` (0x44ABF0) takes the eye from the composed world translation and forward from negative Z. The historically named `gwCameraSetPosition` (0x449EA0) and `gwCameraSetTarget` (0x44A0F0) set rotation and translation respectively; keyframes (0x45AE90) write position and quaternion-derived rotation through them. Stored/event horizontal FOV is radians.
- **Effect templates** (name, model, `MAPS`, `SPEED`, `LOOPING`) come from `effects.zrd`. **Audio:** `sounds.zrd` maps sample names to WAVs; `LOOPED` controls looping. The engine's random table uses the MSVC linear-congruential sequence, seeded from the clock at each mission load (conditions, above).
- **Wildcards:** a `*` in an animation `NAME` pattern matches one decimal digit (m4 `stgwin*` produced `stgwin1`, `stgwin2`, not `stgwing`/`stgwinb`; same for m5 `tower**`, m1 `pu***`, m10 `barrel**`) [D].
- **Blender action import requirements** (not implemented; [roadmap](roadmap.md#phases)): sample evaluated local transforms; only linear position/scale and constant-rate fixed-axis rotation are representable; compute exact rates (V = ΔP/Δt, G = ΔS/Δt, Ω = log(q1·q0⁻¹)/Δt) on a continuous hemisphere, never the original spin for new content; SPIN for turns ≥ π; unit quaternions; contiguous segments keying every moving channel; never key `INPUT_NODE`; one shape key per model as 0x0B events in [0, 1], never under a range-fade LOD; loops start and end on one pose; do not key game-driven nodes; avoid pitch ±90° with |roll| > 90°.

## Missions and slots

- **No mission table:** per-mission inputs are formatted from the number without a range check: `support\initm%d.gw`, `m%d_zbd.gs`, sound set `M%d` (`LoadMissionCoreResources` 0x417810 [BN]), `zbd\m%d\zrdr.zbd` with its search path (0x42ecb0 [BN]). `maps\m%d.zmap`, `briefing.zrd` `CAMPAIGN%d` and `Weather.zrd` `MISSION%d` are optional. Everything else is named by the mission's scripts. Saves store the number as a plain integer, unchecked on load (0x4174f0 [BN]).
- **Choosing a mission:** New Game always starts mission 1 (0x41c525 [BN]); completion queues the next number unless `objectives.zrd` sets `FINAL_MISSION` (`inc edx` at 0x418fdf [BN]; only m6). Multiplayer worlds come from `dialog.zrd` `MP_NEW_GAME/WORLD/CYCLE` (up to 20 entries; entry *i* is mission *i* + 7, 0x41a5b0 [BN]).
- **Per-number rules:** network weapons from a 13-row table (`CheckMissionWeaponAvailability` 0x43ca90 [B, BN]; mission 14 reads past it and allows every weapon, 15+ read stack garbage); amphibious online only in 9, 11, 12, 13 (0x423380 [B, BN]); single player amphibious from 3, hover from 4, submarine in 6 only, carried by saves; mission films `'M'` + `'0' + number` (0x42edb0 [BN]), so 10+ never match.
- **Consequences:** any existing slot is replaceable as data; a multiplayer arena m14 is pure data (files, scripts, a `dialog.zrd` entry), 15+ need a patch; a new single-player mission is reached only by clearing m6's `FINAL_MISSION` (m7, also arena 7) or patches (0x41c526, 0x418fdf).
- **Difficulty files:** `zVehicle::SelectZrdByDifficulty` (0x41FE50) selects `vehicle_easy`/`vehicle_hard` and falls back to `vehicle.zrd`; `Player::GetAivZrdPath` (0x41FE40) returns `aiv.zrd`; pickup difficulty selection 0x41DDF0; spawn transforms 0x41DA20. Selecting the shipped alternate AIV layouts is a preview capability, not engine parity.

## Resource archives

- **A resource comes from the first mounted archive holding its name.** `zReader::Load` (0x48cdc0 [B]) reduces the path to file name and extension and opens it with `zRdrOpenFile` (0x48d1c0 [B]), asking each mounted archive in list order (`zIndexArchive::OpenFileByName` 0x4a6630, `FindRecordByNameCI` 0x4a65d0 [B], case-insensitive). Loose `.zrd` files and zReader search paths are not consulted: `.zrd` is read only as compiled archive members, by fixed names (plus `net_01`–`net_99.zrd` and the difficulty variants), never as text.
- **The common archive is searched first.** `zArchive::Mount` (0x48d210 [B]) appends. With archives in use (`HudSensorTracker::missionFlags` nonzero), `zbd\zrdr.zbd` is mounted at startup as the current archive (`RecoilApp::LoadZbdAndStartEngine` 0x42e490 [B]); at mission end (`CRecoilAppPlayState::OnDeactivate` 0x42f8e0) or loading another mission's save (0x4174f0), `zRdrUnmount(0)` (0x48d2c0 [B]) leaves only the current one; `zUtil::SetMissionZrdrPathsAndMountZbd` (0x42ecb0 [B]) appends `zbd\m%d\zrdr.zbd`. A common member hides a mission member of the same name.
- **Effects:** `zEffect::InitFromPath` (0x460070 [B]) reads `effects.zrd` this way as each mission loads (freed by `zEffect::Reset` 0x460330); `zEffect_Anim::LoadZbd` rejects the whole `anim.zbd` when an effect template it names is missing (0x45f899 [BN]). A mission `effects.zrd` counts only when the common archive has none.
- **Animations:** animation definitions are never read at run time; `anim.zbd` alone carries animations, binds entries to world nodes by stored names and is called by name from other resources. The loader rejects an `anim.zbd` when a source it stamps exists with another date (and is still passed `anim.zrd`, the remains of a development path).
- **Variants:** `vehicle_*`/`puppies_*` variants are chosen only when a loose file of that name exists; their data still comes from the archive. `aiv.zrd` is fixed.
- **Shipped data** [D]: the only name in both the common and a mission archive is `anim.zrd`. The common archive holds `effects.zrd`, `sounds.zrd`, `pickup.zrd`, `vehicle*.zrd`; missions hold `ai.zrd`, `aiv*.zrd`, `puppies*.zrd`, `startanims.zrd` and `net_NN.zrd`. The game never requests `location.zrd`, `aiv_easy.zrd`/`aiv_hard.zrd`, `cockpit.zrd`, `fonts.zrd`, `rcochet1.zrd`.

## Resource schemas

The keys the game reads; anything else is ignored. Types are exact ([Common rules](#common-rules)).

### `net_NN.zrd`

`AINet::LoadFromZrd` (0x403040 [B, BN]), NN 01–99, single player only.

- **Identity:** the network ID is the file number. **`version`:** integer 105 or absent, otherwise the network is dropped silently. **`name`:** copied unchecked into 20 bytes. **`type`:** first two letters ST/HI/FI/DE, else standard.
- **Floats:** `path_width` (default 10), `activate_rad`, `attack_rad` (0 → about 38.7), `attack_dwell` (0 → 10 s), `not_pursuit_dwell`, `return_range`, taken when a vehicle starts (`Player::InitStateFromNameAndMasterCommonData` 0x420d10 [BN]); a zero `activate_rad`, `not_pursuit_dwell` or `return_range` stays 0. The `vehicle.zrd` `common_mode` `not_pursuit_dwell`/`return_range` these "override" are loaded but never applied [BN].
- **Effects** [BN, static]: `activate_rad` — a vehicle acts only while the player is within this horizontal distance or it is alerted (`PlayerMgr::TickAllPlayers` 0x426625; 0 wakes it only when alerted). `attack_rad` — an attack starts when the player is within it (3D, between target points) in line of sight (0x401b20); none in a vehicle's first 10 s (0x4210d9). `attack_dwell` — burst length; `not_pursuit_dwell` — pause between bursts and cooldown after a chase (`AiEnterPursuit` 0x401c60, 0x402250, 0x401b3e); neither ends a chase. `return_range` — a chase ends when the vehicle is farther than this from the route node it was heading to when the attack began, or the player dies (0x401913); 0 ends every chase at once (inferred). `path_width` feeds per-link probe data nothing reads (0x403550, 0x403620); `hide_times` (8 and 4 when absent) are copied (0x420fe3) and never read; defilade uses fixed 4 s and 14 s waits (0x402c85, 0x402e05).
- **`type`** (`TickAiTopLevel` 0x401060 [BN]): standard drives its route and returns after an attack; hide (0x402090) and fixed (0x402170) stay and turn to face the player; defilade (0x402b70) drives from its home node (nearest to where placed) to its first link, waits 4 s, backs home, waits 14 s, repeats, staying awake.
- **`pursuit_params`** (or `pursuit_range`): two floats for the strategy (`TickAiPursuit` 0x401710, jump table 0x401948 [BN]): head-on backs off nearer than the first and closes in farther than the second (0x401970); circle orbits at the first (0x4026d0); back-and-forth charges to the first, backs to twice it and swings sideways by the second (0x4028c0); others use neither.
- **`attack_strategy`:** first three letters FOL/CIR/HEA/BAC/ZIG/SIT, uppercase comparisons (0x403367–0x40342E; literals 0x4DA0F8–0x4DA10C, key 0x4DA110). **Missing or unrecognised means head-on (HEA).** Follow-net keeps driving and shoots; sit stops and faces the player (a vehicle hitting obstacles more than six times switches to sit); **zigzag has no steering** (keeps its last controls) [BN].
- **`attack_buddy`:** integer flag: nonzero, a vehicle that starts pursuing (`AiTryEnterPursuitIfLineOfSight` 0x401b20) or is hit (0x43bb3e) alerts its ring (`AiAlertAttackBuddies` 0x401c00): every active vehicle of the network (`BuildAiPeerRingsByAiNetId` 0x403750), each joining and staying awake 10 s. A hit vehicle joins and stays awake 5 s regardless. **A missing `activate_buddy` zeroes it** (0x403329 [BN]); `activate_buddy` itself is read into an unused field. Every shipped `attack_buddy` is 0 [D].
- **Net Edit dialog** (executable resources [BN]): Net Name, Net Type, Path Width, Activation Radius, Attack Radius, Return Radius\*, Attack Dwell, Post Attack Dwell\* (`not_pursuit_dwell`), Pursuit Rad Min, Pursuit Rad Max, AttackStrategy, Buddies Activate, Buddies Attack ("\* These parameters override vehicle.zrd defaults"); pursuit labels follow the strategy (`AiPropertyDlg::UpdatePropertyLabels` 0x41c170): Min/Max Pursuit Rng for head-on, Attack Range/Unused for circle, Attack Range/Movement for back-and-forth, Unused otherwise. The network card uses these names.
- **`node_00`–`node_98`** in index order: an integer (never read), float XYZ, three integer links. 0x403550 resolves nonnegative indices within the network; negative means absent; **a link to a missing node crashes at mission load** [B]. Shipped: 470 networks, no dangling link or self-link [D].

### `aiv.zrd`

0x41fe90 [BN]; only `aiv.zrd`. A list of name/record pairs: `name ( netId:int ( x y z :float ) yawDegrees:float )`.

- Names at most 27 characters; template derived as in [Vehicles](#vehicles). `CreateFromNamesAtPose` 0x421ab0 [B] finds the name, else copies the template, with `FindByTypeAndName` among all live nodes (most recent first) and uses what it finds as the vehicle whatever its class (no shipped collision [D]). It applies rotation `(0, heading × π/180, 0)`: pitch and roll are not authorable.
- **Copying** (`CopyNodeDispatch` 0x452400 [B, BN]; pickups copy alike, `CreateObjectInstance` 0x41dab0 [B]): a node flagged 0x04000000 is returned uncopied and becomes a child of the copy too; otherwise only Object3D, LOD and camera nodes are copied. An Object3D skips a child yielding no copy (0x452100); a LOD or camera yields none when one of its children yields none (0x452250, 0x451f70). The copy is renamed (`CloneType6NodeFromTemplateAndRename` 0x421a40 [B]); an uncopied template is itself renamed and placed, so a later record of it finds none. No shipped node has the flag [D].
- An entry spawns only when its template occurs in the selected `vehicle*.zrd`. The local player is the first entry that spawns (`bft_00` in every shipped file); every shipped world holds a `bft_00` node, which is placed itself (every `bftN.gw` and `bftmulti.gw` loads the tank as `%playerName%`; `bft1.gw` loads it a second time as `bft`, which no retail record copies) [D]. Network ID 0 means no AI; an unknown network leaves the vehicle inert. Shipped: 1,838 entries, all well typed; one duplicate, `bft_00` in m2 `aiv_easy.zrd` [D].

### Pickups

- The engine's 40-type catalog is at 0x4DB6E8; templates are `pu000`–`pu039` (`puNNN`), placed copies `puNNNNN` named from the type's `nameSuffixMax`.
- `puppies.zrd` (and `puppies_easy`/`puppies_hard` when loose files exist) are ordered placement lists, not key/value pairs: type name, amount (0 = the type's default), XYZ, Euler XYZ radians, respawn delay. Template scale applies.
- **A copy without a `bvol` is destroyed:** `CreateObjectInstance` frees it (`DestroyNodeRecursive`) when `Pickup::AssignBvolGroupAndId` (0x41DB60 [B]) finds no `bvol` in it with `FindSubNodeByName` (order in [Vehicles](#vehicles)); only a found `bvol` advances `nameSuffixMax`. The found `bvol` is switched off at once, so it is never drawn. A `bvol` that is a light, or a LOD holding one, yields no copy.

### `ai.zrd`

Turrets (0x437ac0 [BN], 0x4367a0 [B], callbacks 0x45D6B0): root keys `DESTROY_ANIM` and `TURRET` (pattern and definition pairs; each `*` in a pattern is one decimal digit).

- `PARTS`: 2–4 names, bound only under a `healthy` node. Behaviour: `DEACTIVATE`, `EFFECT`, `ACTIVATE_ON_HIT`, `ALWAYS_LOOK_AT`, `DAMAGE_PART`, `DESTROY_ANIM`, `FIRE_ANIM`. Defaults: `HEALTH` 100, `INTERSECT_BVOL` 1, `LOS` 0.
- Destruction animation precedence: the definition's explicit `DESTROY_ANIM`, then an animation named for the turret, then the global default; an absent name never resolves the reserved empty entry.
- `TARGETS`: at most 8, each the highest slot of its exact name in the whole world, aimed at through its local matrix while active (`InitFromReaderNode` 0x4367a0 [B], `Tick` 0x436e40 [U]); shipped `TARGETS vtol` finds a `vtol` child at its parent's origin (the SAM sites aim at a fixed point); `hel_*1` and `braintur_*` find nothing.
- `DEACTIVATE` finds its first name in the whole world, further names in that node's subtree; `PARTS`, `EFFECT`, `DAMAGE_PART` search the turret's subtree, preorder. `MSL_LOCK`: presence only. `WEAPON`: `NAME` required (missing or unknown crashes), `AMMO` 50, `BASE_MOVES`, `DAMAGE_MODIFIER` 1, `DETECTION_RANGE` 200, `FIRE_DWELL`, `FIRE_RATE` 1, `FIRE_LIMITS`. Shipped: 130 definitions [D].

## Script interpreter commands

- **Tokenizer** (`CZInterp::TokenizeLine` 0x4C13C0): `#` ends a line; tokens separated by comma, space, tab or newline; ASCII whitespace after a separator is skipped; only a separator directly after another produces an empty token. Prepared instruction blocks and terminators: 0x4C1160 (16-pointer token list).
- **Horizons and camera worlds** (`DispatchCoreCommand` 0x4c20a0 [B, BN]): `CameraSetHorizon` and `CameraSetHorizonXZ` resolve with `FindByTypeAndName(6, name)` (0x4c2494 [BN]); bucket 6 is the list `gwNodeNew` adds every node to, newest first, so a horizon can be any class. Camera setters 0x44A910 and 0x44A980 assign separate `horizonNode` and `horizonXZNode` references (also null); the XZ one follows camera X/Z. `CameraSetWorld` looks in the worlds' list (bucket 13); `gwCameraSetWorld` (0x449dd0 [B]) returns 5 without a world, keeping the camera's world.
- **Object transforms:** `gwObject3DSetRotation` (0x44e030 [B]) and `gwObject3DSetScale` (0x44df00 [B, BN]) clear the authored-matrix flag 0x10, so `gwNodeUpdate` (0x448cc0 [B]) rebuilds the matrix from stored rotation, scale and the matrix's translation; `gwObject3DSetPosition` (0x44e300 [B, BN]) writes the translation and keeps the flag. Each clears identity flag 0x08 only when a value differs from identity and sets TRS dirty 0x01. Degrees convert with the double 0.01745329251994, which differs from float π/180 in the last bit for about one angle in eleven (none shipped).
- **Lights:** `gwLightNew` (0x452fd0 [B, BN]) makes a white point source (+0xC0) at full intensity (+0xA8), enabled, dirty, facing +Y, ranges 32 and 64 (cached 4096, 1/32). `LightSetDirectional` (0x4532a0 [B]) sets only its flag (+0xB8); `LightSetDirectedSource`/`LightSetPointSource` set theirs and clear the other's. `LightSetActive` is `gwNodeSetActive` (0x447c60 [B]), flag 0x04 for cameras, worlds, objects, LODs and lights. `gwLightSetRange` (0x453400) makes equal ranges 10 apart; `gwLightSetSpecularColor` (0x453aa0) clamps each channel to 0–1 (0x49b5a0).
- **Texture names:** `TexDirFindOrAppendByPath` (0x46d810 [B, BN]) names an entry with `TexDirSetBaseNameFromPath` (0x46e380): from the last backslash or slash (separator included); `SetPathExtension` (0x46e2c0 [BN]) ends it at the first dot. The copy is unbounded into a 20-byte name whose load state (+0x1C) overwrites bytes 21–24, so a name with a folder or over 19 characters is never found in the packs.
- **Other commands:** `CameraRotate`/`CameraTranslate` dispatch to Euler and position setters; `CameraSetActive` changes activation; `CameraSetNearClip`/`CameraSetFarClip` keep the other plane. `Object3DSetActive`, `Object3DSetPriority`, `NewLOD` and the Matl/Model/SEQ and window-clear-polygon commands create or alter saved structures. `CameraSetDynamicLOD` and `CameraSetObjectHSETest` change global settings, not saved records.

## Textures and the rendering target

- **Choosing the pack** (`zVidTexturePackEnsureBuiltinTexturePacksLoaded` 0x46df50 [B, BN]): Direct3D: N = total texture memory in MiB (`GetAvailableVidMem` with DDSCAPS_TEXTURE, 0x4a9a30 [BN]); tries `rtexture<N>.zbd` down to 1, then `texturemax.zbd`, `texture.zbd`. Software: `TextureMemory` 1–4 chooses `texture8/6/4/2`, anything else `texturemax`; a missing pack falls back from `texture<size>` (8 for `texturemax`) to `texture1`, then `texturemax`, `texture.zbd`. The option does nothing under Direct3D; the choice is made per mission. So `texture8`/`texturemax` serve only the software renderer; Direct3D reaches `texturemax` only without any `rtexture` pack, then refuses its paletted textures.
- **Runtime texture cycles** are created from saved materials, then the mission's `tex_fx` interpreter setup, then `effects.zrd` setup, in that order; effect setup changes shared material bindings (`fire_bft` uses the `fire1` material).
- **Software texture size:** spans are drawn for textures 8–1024 wide; the span routines switch on 20 − log2(width) with cases 10–17 and skip anything else (0x49bbf0 and siblings [BN]; `CalcPow2ScratchFields` 0x4902b0 [B]). The loader stores 16-bit sizes and allocates by pixel count (`zVid_Image::ReadHeader` 0x46ED70). No shipped pack holds a texture above 256 [D].
- **Software colour modes:** paletted textures draw through the shade path (`SpanShade16FromPal8` with the fog recipe's palette); direct-colour textures are copied unshaded (`zRndrDrawTexturedQueued` 0x495850 [U]). A damage stamp applies only when both mask and hit texture are direct (`ApplyDamageMaskStampOnHit` 0x479660 returns when either palette word at +0x0E is set [U]); when masks are on and not networked, the player's spawn marks every textured material of `bft_00`'s subtree stampable (`SetMaterialFlagBit9ForFlagBit0EntriesRecursive` 0x452860 [B]); a hit on any (unless a cycle runs on it, material flag 0x400) takes the mask, and a repair reloads all (0x480f80 via 0x4528a0). `WriteTextureSetType`/`WriteTextureSetMap` choose only the masks; no data names stamp targets. The external palette flag is 0x10 at image +0x0E (0x46EE69; 0x80 is runtime ownership).
- **Horizon:** the node named `horizon` the game finds from the world node (`Player::InitMissionRuntimeFromWorldAndCamera` 0x41fe90 [U] via `FindSubNodeByName` 0x452770 [B, BN], starting at the world node, whose children are the landmarks and the nodes outside the grid) and the cameras' `CameraSetHorizon`/`CameraSetHorizonXZ` nodes; kept at the camera (`Player::UpdateThirdPersonCamera` 0x405650, `CZCamera::SyncViewContextPositions` 0x44d320 [B]).
- **Shipped software packs** [D]: in every software pack of both releases (one choice per mission), direct records are the damage masks `pock1`–`pock3`, every texture of models at or below the horizon except m2 `sky2lite` (the lightning sky an animation swaps in), 1999 m11 `m11sky` and m13 `skym6` (m6's is direct), and hand choices nothing records: `tanktop`/`tankback` (m2–m13; m1 `tanktop`, `tankgn01`, `tankgn02`) of the about 40 textures the player vehicle uses, and in 1999 m10/m11 `arcgun01`, `beamred`, `beamyelo`, `erfpgscl`. The stamp reach (about 40 textures, 42 in 1999 m2, 43 in m10) does not explain the choice; builds choose by rule ([known differences](sources.md#known-differences)).
- **Colour keys** [B, BN]: a transparent texture without an alpha plane (image flag 2) is drawn by masked spans skipping a direct texel of 0 and a paletted index 0 whatever its palette colour (`SpanMasked16FromTex16SwitchVShift` 0x49b7e0, `SpanMasked16FromPal8SwitchVShift` 0x49bbf0 [B]). On a 555 display every direct texel and palette entry is converted on read to `((s >> 1) & 0x7FE0) | (s & 0x1F)` (`zVid_Image::ReadData` 0x46eee4–0x46ef1f [BN], shared pages in 0x46dae0 [B]), so 0x0020 is the key there.
- **Texture name lookup:** `zVidTexturePackLoadImageByName` 0x46d940 and `zVidTexturePackLoadBuiltinImageByName` 0x46dd30 [BN] scan records in order and stop at the first case-insensitive match.
- **Numbered mipmaps** (`BuildMipChain` 0x46e3e0 [BN], called at 0x46deb5 by `TexDirLoadPendingEntries` 0x46de50 for every entry it loads, both renderers): it returns unless the first `_1` in the name (`strstr` 0x46e41b) ends it (0x46e42e); otherwise it increments the last character (`_2`, `_3` …, 0x46e43e) and takes a directory entry of exactly that name (`FindTexDirEntryByName` 0x46d4d0) or the image of that name in the mission pack then `image.zbd`, ignoring case (`TexDirFindOrCreateByPath` 0x46d900, `_stricmp` 0x46dd99), stopping at the first name found nowhere (0x46e466); each is appended (unchecked), marked loaded and linked as `nextVariant` with a width ratio scale (0x46e4b1). A pending `rock_2` is then never created under Direct3D (drawn untextured); an entry already loaded is linked through an uninitialized stack slot (0x46e439), a likely crash. The software renderer draws a chained texture on distant polygons (0x499130 [U]). Not chained: `rock_10`, `a_1b`, `y_1_1`, a lone `rock_1`, or `rock_1` beside `rock_3` without `rock_2`. No 3D texture of either release has `_1`; `image.zbd` holds `camp_1`/`camp_2`, loaded by name without the directory [D].
- **Creating Direct3D textures** (`CreateTextureRecord` 0x4aa0f0 [BN]): the default texture replaces one with a side above the device maximum (0 counts as 256), a non-power-of-two size where powers are required, aspect above 8, or a palette; no size limit of its own (original hardware generally stopped at 256; wrappers report far more). Formats: opaque as the display format (565), alpha planes ARGB4444, colour keys 1555. Colour-key conversion: `(s & bMask) | ((s >> 1) & ((rMask | gMask) >> 1)) | (s ? 0x8000 : 0)` with the primary surface's masks (`ConvertImagePixelsForTexture` 0x4aa70d–0x4aa762; masks at 0x632164/68/6c set by 0x4a8f80 [BN]); on 565 that moves green's low bit into blue's high bit, so shipped keyed hardware textures (`vcap04` m3, `cath18` m4, 1998 m6 `stub07`) gain about 132 blue on texels with odd green and blue < 128 [D]; on 555 red and green shift too. Alpha planes are right on both. Each texture is created with one level (no mipmaps) [U].
- **Edge modes:** each axis repeats or clamps. `ReadHeader` (0x46ed70 [B]) keeps the header word at +0x0E; `TexDirLoadPendingEntries` passes bits 0 and 1 to `CreateTextureRecord` as clamp U and V (D3DTADDRESS_CLAMP or WRAP) [U]. A texture cycle only changes which texture its material draws, so each frame is drawn with its own word [U]. Texture commands take their first operand (`LensFlareTexture` the one after its stage) through `TexDirFindOrAppendByPath`; `CycleTextureSetOn` without a current node (a failed `FindNode`) only reports it, so the previous display instance stays current and later `CycleTextureSetMap` frames join its first material's cycle while it has room (`AddCycleTexture` 0x481100 [B]). In both releases every frame has the word of the texture of the material its cycle shows on (tex_fx: first material of the node found; `effects.zrd` `MAPS`: first material of the first model at or below the effect's node), except 1999 m9 `surf`: its material samples `surf00`, which no pack holds, and `surf01`–`surf13` clamp V as m1's do [D]. Textures cannot mirror.
- **Filtering** is the same for every texture: `CreateDeviceState` (0x4a9c20) sets TEXTUREMAG/MIN linear once [U].
- **Memory:** each texture keeps a system-memory copy beside its video surface; all textures load with the mission (no streaming). No executable is large-address-aware: game, wrapper and driver share 2 GiB; expect 2–3 × the pack's size in the process [U].
- **UVs:** shipped models are drawn with their stored float UVs (`RenderNodeHardware` 0x477b30, `SubmitPolygon` 0x4abb20 [BN]). The 1/256 rounding of shipped models was the build tool's; geometry built during play (craters, quicksand, clipped CanModify pieces) is rounded to 1/256 by `AddPolygonEx` 0x483650 [BN], up to 2 texels on a 1024 texture. `AddPolygonEx` also removes colinear corners, fans non-planar polygons and extrapolates UVs; shipped models repeat corners, keep non-planar polygons and non-affine UVs, so the build tool did none of that.

### Frame time

Each opaque polygon is its own draw call; transform, lighting and clipping run on the CPU, so frame time follows polygon count rather than texture size [U]. The shipped 1999 worlds hold 4,243–15,119 polygons in all (m11–m6), at most 170 in one model [D]; the engine sets no polygon limit.

## Animation recipients and position references

Static association discovery follows bound recipients separately from load-time roots [B: reconstructed retail call sites in `Player::CreateFromNamesAtPose`/`StartDestroyedStateVehicleEffect`, pickup collection, turret callbacks, `OptCatalog::LoadFxSpecFromReaderNode`/flyout activation, `zEffect::HandleSurfaceRefEvent`]:

- Turret initialization/destruction and firing pass the turret root; destruction uses the resolved explicit override, the object-name entry, then the global default; burning destruction (`napalm_vehicle`) also binds the turret.
- Pickup collection binds the placed pickup and passes the player as a position reference.
- Vehicle startup, destruction and modal FX lists bind the actor root (transition lists keep at most two entries); shatter/napalm/submerged destruction and wake/exhaust/bubbles have explicit actor recipients; `regen_skin` and `shock_vehicle` start with a null bound node.
- Weapon flyout `MODEL_ANIMATION` binds the model copy (its template lookup precedes AIV/pickup placement); `ANIMATION` and `ANIMATION_ATTACHED` use a null bound node and positional references; `EFFECT` takes precedence over `MODEL` even when empty.
- `CALL_ANIMATION` binds `OPERAND_NODE` when its positive reference resolves; `AT_NODE`/`WITH_NODE` position rather than own. Runtime impact victims have no statically identified recipient.
- Discovery includes all sequence branches and cleanup without evaluating conditions or advancing time; it describes known assignments, not proof that a branch runs.

## GameZ world format

- RECOIL worlds are GameZ version 15 in both releases and the September 1998 demo; version 13 in the demos built 21 July–12 August 1998 (read-only, read into the same model). Version 13 differs in two ways, established from every node of the ten version-13 demo worlds: node slots are 268 bytes (after the sphere, the cached box as eight corners in the parent's space — bottom face then top, each from minimum X and maximum Z — then model and child boxes and the activation pointer; the reader rebuilds the cached box from the flagged model/child boxes, otherwise maps the corners back through the matrix); Object3D records are 156 bytes (a translation after the scale, matrix and rest 12 bytes later; the matrix already carries the translation, so the reader drops it and shows it as `translate`). Version-28 animations bind to version 15 or 13.
- **Node bounds:** +0x74 cached node box, +0x8C model box, +0xA4 child box, node-local; flags 0x100/0x200/0x400 mark them valid. `gwNodeRecalcBBox` (0x448E90) sets cached = model ∪ child and marks non-world parents dirty; `gwNodeComputeChildBBox` (0x4491B0) unions children's cached boxes through their local matrices; `CZZbd::ReadNodeTable` (0x455350) reads the table raw; render traversal (0x44B300) turns the cached box into the world sphere at +0x64/+0x70 and skips the subtree outside the frustum.
- **Models:** `zDi::RebuildBounds` (0x483AD0) sets the centre to min + half extent and the radius to `(bits(hx²+hy²+hz²) >> 1) + 0x1FC00000` (reproduces stored radii 1.41, m1 model 1206, and 2.045, facade 1207). Dynamic ranges and their absolute table offsets follow 0x4815C0. Material slot links: previous at +0x28, next at +0x2A (0x4812C0, 0x48130E/0x481316, 0x481353–0x481381); the allocator removes the free head and prepends it to the active list. Node class-none offset words are parent indices, never relocated.
- **LOD** uses squared near/far distances.
- **MechWarrior 3** (inspection only; deferred): worlds are GameZ version 27, animations version 39, motion members version 4. Every retail MW3 material carries bit 0x10 (the most common opaque textured material of every map has flags 0x11) and every retail polygon a nonzero `field24` word; their engine semantics are unverified. 456 shipped MW3 transform events contain reversed spans of unestablished meaning (the preview reports them). AI networks are version 106 with variable link counts and edge-constraint records without XYZ.
