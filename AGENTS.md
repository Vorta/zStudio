# zStudio

Every user-facing capability must have semantic MCP parity. MCP shares the visible GUI workspace, identities, revision checks, drafts, undo and verified saves. Use the existing command registry and shared editing/preview/export services; never implement a second parser or bypass source protections. Add/update typed schemas, `docs/mcp-capabilities.json`, MCP documentation and meaningful protocol tests with each feature. Regenerate the embedded discovery catalog from the shared command registry when commands change; full catalog parity is tested. MCP initialization/discovery must remain windowless; launch or attach the visible workspace only on a valid workspace request. The parity test rejects unmapped XAML action handlers and mappings to missing tools; reviewers must also check bindings, dynamically created controls and renderer interactions. Generated property fields/actions inherit MCP exposure. Keep local MCP opt-in, same-user named-pipe transport, stdout protocol-only, bounded requests/results, explicit unsaved/draft decisions and asynchronous operation handles. Agents must not enable their own access or capture the user's physical mouse. New functionality is incomplete until both GUI and MCP paths work.

Source projects reconstruct RECOIL's original build tree (`data/`, `gamegen/`) from shipped files; see `docs/source-project.md`. They are separate from direct ZBD editing: sources are authoritative, and game files change only on export. Keep no zStudio metadata in a project; derive outputs from its folders. Exported files must work in the game, not match shipped bytes: verify them by meaning (members, compiled values, tokens, formats). A project is reconstructed once, from the original game files, and then only exported; reconstruction refuses any folder whose archives do not carry the animation definitions (`anim.zrd`), such as an export, with "zStudio can unpack only the original ZBD files." Place sources only by recorded evidence (compile paths, script names, animation stamps), never by names alone. Worlds record no model paths: a vehicle several missions' `bft1.gw`–`bft6.gw` load identically is one file in `data/common/models`, which those loads also search (user decision); a differing version stays in its mission's `models/bft`. Effect models (`weapons.gw`) are kept with their textures in `data/common/effects/models`, which the same loads search, and reconstruction creates no empty folders, even ones the scripts search, such as `data/effects` and the multiplayer missions' `models/bft` (user decision). Mission databases are rebuilt as the original tool loaded them, from the order the shipped node slots and free lists record (no rank or order metadata): the parts a database referenced are separate glTF files (`mN_NN.gltf`, placeholder names) referenced by group nodes, deleted groups are placeholder groups, and later paths to one file are spelled `./name.gltf` so they are cached separately (user decision). The rules that explain the shipped slots (instance definitions, second paths also inside model files, groups closing before their last objects, records starting on the slots the caches left) are in docs/engine-evidence.md; emulate only mechanisms that reproduce them, never per-mission exceptions, and note the missions whose slots still differ. Keep the best-quality variant as the source and derive lower variants on export; declared sound formats are ceilings, never raised. Exports stage and re-parse every output, write nothing if any fails, replace existing game files only with explicit consent, and roll back on failure. Projects and export folders stay separate from their inputs, links and the protected corpora. Mission worlds shown for editing build only into the project's `zstudio/cache/worlds` (user decision): derived data no build reads, not listed in Files, removed with the world; game files are created only by export.

Keyframe scripts are Softimage "SI Animation Scripts" ([docs/source-project.md](docs/source-project.md#keyframe-scripts-zan)). The SI compiler (`src/zStudio.Core/Animation/Si*.cs`) reproduces every shipped keyframe bit for bit; change its arithmetic only with new reference vectors, and keep the writer's guarantee that a script is written only when it compiles back exactly (otherwise the keyframe format with a note). DKit messages and stamp-dated versions are historical and written only when reconstructing stamped retail files. Reconstruction replaces a definition with one decompiled from `anim.zbd` only when the shipped text does not compile to the shipped entries and the replacement does exactly; its note says the shipped text is not the compiled version (the recorded dates show the archived text is the older one), never that it was edited later. Original-compiler rules verified on the corpora: a sequence named more than once takes its last `NAME`; inside an event the first of a repeated attribute counts; a `START_TIME` given to a whole sequence is ignored.

Engine behaviour that world editing depends on (zone probes, node slot order and name lookups, the animation runtime, mission slots, resource schemas, textures) is recorded with its evidence in [docs/engine-evidence.md](docs/engine-evidence.md) and the plan's "How the engine sees a map"; check them before changing related code, and keep them current. Retail runtime facts that source and export decisions rely on (1999 executable and its reconstruction): the game reads `.zrd` only as compiled members of mounted archives, by fixed names (plus `net_01`–`net_99.zrd` and the difficulty variants), never as text, each from the first archive that holds the name (the common `zrdr.zbd` before the mission's). Animation definitions are never read at run time; `anim.zbd` alone carries animations, binds entries to world nodes by stored names and is called by name from other resources. The game rejects an `anim.zbd` when a source it stamps exists with another date, so exports write no stamps. `vehicle_*`/`puppies_*` variants are chosen only when a loose file of that name exists (their data still comes from the archive), and `aiv.zrd` is fixed. Animation definitions are therefore `.zad` files, never resources: reconstruction writes each mission's list (`anim.zad`) and the files it names as `.zad`, renaming the names in the lists, and splits `pickup.zrd` (its `PICKUP_DATA` stays, its animation goes to `pickup.zad`). Exports pack only `.zrd` resources into `zrdr.zbd` and fail on a `.zrd` that holds `ANIMATION_DEFINITIONS`. zReader files the game never requests (`location.zrd`, `aiv_easy.zrd`/`aiv_hard.zrd`, `cockpit.zrd`, `fonts.zrd`, `rcochet1.zrd`) stay in the projects and archives: they carry genuine, non-redundant data. How the developers built the shipped files is in [docs/recoil-original-worktree.md](docs/recoil-original-worktree.md#how-the-shipped-files-were-built).

Treat ZBD as five separate format families. Probe binary structure and version, not just filenames. Preserve record identities, ordering, unknown data, and source ranges. Names are not unique. Stored pointer values are metadata, never process pointers. Verify disputed semantics against available engine evidence and the private reconstruction/decompilation references described in `docs/architecture.md`; historical notes are provisional. These external references are not build dependencies and must not be committed.

Use nullable types, explicit little-endian bounded reads, cancellation, deterministic exports, and actionable diagnostics. Keep binary models independent of UI and rendering dependencies. Keep malformed-input and corpus coverage to the minimum necessary under the testing policy below. Do not claim engine compatibility from a successful parse alone.

Animation edits must preserve untouched bytes and record order, keep runtime simulation state separate from serialized data, and support undo and verified Save As to a new file outside the source dataset. The primary sequence is cleanup, not an extra runtime sequence. Retail event 0x16 releases a waiting sequence and 0x17 stops it. The historically named Object3D SetLitFlag controls the inherited alpha override; do not reintroduce unconditional stored-opacity rendering. Mark game-dependent preview approximations explicitly.

Procedural launch ranges at bytes 32/40/48/56 are yaw/pitch/speed/radial acceleration, verified directly in retail 0x459E70; the reconstruction's temporary names and initial gravity branch are inaccurate. Forward is -Z. Flag 1 enables signed gravity at byte 24; 0x2000 selects its transposed world basis. Keep active one-shot sounds in seek snapshots until their WAV duration ends so mute and pause/resume do not drop them. Animation audio defaults to unmuted.

Prepare animation audio from a frozen dependency snapshot, including child animations, branches and cleanup. Decode only reachable samples off-thread and reuse a single warm mixer/output. Sound cues, pause, mute and seek must not initialize or dispose native audio devices on the UI thread. Preserve independent voice cursors and generation checks across cancellation, seek and asynchronous shutdown.
