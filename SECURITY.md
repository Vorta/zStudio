# Security policy

The latest released version of zStudio receives fixes. Earlier 0.x versions may require updating rather than a backport. The application parses binary files; reproducible crashes caused by invalid data are useful reports even if exploitability is unknown.

## Reporting a vulnerability

During the initial private review, authorized collaborators can use a private repository issue and notify @Vorta. Keep reports within the repository's authorized audience.

After the owner makes the repository public, use [Report a vulnerability](https://github.com/Vorta/zStudio/security/advisories/new). The maintainer must enable private vulnerability reporting as part of the public-launch checklist before inviting public reports. Do not post exploit details in public issues. If the private reporting form is unavailable, open an issue requesting that it be enabled without including sensitive details.

Include the affected release, reproduction steps, expected impact, and a minimal synthetic input where possible. Do not attach proprietary game files, decompilation databases, personal information or credentials. No response-time guarantee is currently offered.
